# Home Media Platform 宪章 (Constitution)

## 核心原则 (Core Principles)

### 一、规格驱动与多层证据验收（不可妥协）
所有新功能、接口变更与领域模型调整，在编写实现代码之前，**必须**先编写并通过已接受的规格文档（`docs/specs/`）和架构决策记录（`docs/adr/`）。代码实现规格，自动化与手工测试证明规格。处于 `Proposed` 状态的未接受规格**严禁**作为实现承诺。所有验收标准必须具备客观可判定的二元结果，并且必须在明确的证据层级中提供证明：静态检查、单元/集成测试、运行时行为以及网络/后端契约。仅通过单元测试**绝不能**替代运行时或真实契约证据。任何涉及权限、状态变更或数据修改的规格，**必须**显式包含越权访问、非法入参与防篡改的负向验收条件。

### 二、三层身份与数据边界严格隔离（Household / Account / Profile）
所有业务逻辑、存储结构与 API 契约，**必须**严格遵循 `Household -> Account -> Profile` 三层层级结构：
1. **Household**（家庭）是顶层资源边界（`household_id`）。所有媒体源、媒体库、物理设备和家庭级策略均归属于 Household。
2. **Account**（账号）仅负责认证、凭据校验、设备会话及管理员权限。V1 阶段单个 Household 由一个主 Account 管理；Account 不得混淆为观看者个体。
3. **Profile**（档案/画像，`profile_id`）代表当前观看者。观看历史、播放进度、收藏夹、待播清单（Watchlist）及个性化偏好**必须**直接绑定至 `profile_id`。个人数据**绝不允许**与 `account_id` 耦合，更**严禁**跨 Profile 泄漏。

### 三、默认安全的服务端播放鉴权（Secure-by-Default Playback Authorization）
播放解析器（`Playback Resolver`）是直播频道（Live TV）、电影、电视剧集与 NAS 本地文件获取播放资源的唯一统一入口。客户端上报参数、本地存储标记（`localStorage`）及 URL 参数**绝不可**作为授权信任源。服务端**必须**基于经过验证的设备会话（`DeviceSession`）解析并校验绑定的 `activeProfileId`。内容访问授权**必须**通过内容策略（`ProfilePolicy`，包含内容分级、媒体黑白名单、未分级策略及频道白名单）进行动态计算，不得仅依赖前端展示性的档案模式（如 `adult/child`）。只有当设备会话有效、Profile 归属当前 Household、内容策略放行、家庭拥有该资源且设备能力匹配时，播放资源方可解析并下发。

### 四、自托管 NAS 与隐私优先架构（Self-Hosted & Privacy-First）
平台专为家庭及个人 NAS 运行环境设计，数据自主可控与本地化是核心基石。在 V1 阶段，单个部署实例严格对应单个 Household（遵循 ADR-0002）；但所有数据库表结构、缓存键与存储路径**必须**保留显式的 `household_id` 边界，确保未来演进时不发生结构性重构。用户个人观影记录与媒体元数据**必须**保存在本地私有基础设施中，核心流媒体与播放功能**严禁**引入任何强制性外部云端依赖或非授权遥测。

### 五、架构决策记录（ADR）与非破坏性演进
所有重大结构设计、业务边界调整及不可逆的技术选型，**必须**沉淀于受版本控制的架构决策记录（`docs/adr/`）。当技术或业务需求发生重大演变时，历史 ADR **严禁**被静默篡改或删除；旧决策必须通过新增 ADR 进行形式化废弃（标记为 `Superseded`），并附带清晰的迁移路径与背景分析。规格文档、ADR、代码实现和测试套件**必须**在同一次原子变更中保持完全同步。

## 技术约束与环境规范

1. **目标运行环境**：基于 Docker/Linux 容器化交付，适配主流家用 NAS 硬件平台，保持轻量高效的 CPU 与内存占用。
2. **媒体与流式处理**：支持 NAS 本地文件系统直接挂载与标准化流协议（如 Direct Stream、HLS/DASH）。转码能力与媒体解析需与核心业务事务有效解耦。
3. **幂等性与数据一致性**：播放进度上报、观看状态更新与收藏夹操作等状态变更接口**必须**具备幂等性保证。数据库迁移必须支持向前兼容，并包含经测试验证的回滚方案。
4. **领域核心解耦**：核心领域模型与业务规则**不得**反向依赖任何特定前端框架、UI 呈现方式或具体网络传输协议。

## 开发工作流与质量门禁

1. **工作流全生命周期**：遵循 `项目简报 (Project Brief) -> 领域模型 (Domain Model) -> 功能规格 (Feature Spec) -> 架构决策 (ADR, 必要时) -> 编码实现 -> 多层证据验收 -> 发布归档`。
2. **规格状态流转**：规格必须按序显式流转：`Proposed -> Accepted -> Implementing -> Verified`（或 `Superseded`）。
3. **合并前质量门禁**：
   - 静态类型检查与代码规范检查通过，无阻断警告或错误；
   - 单元测试与集成契约测试 100% 通过；
   - 包含越权、跨 Profile 篡改、未授权内容拦截等安全边界负向测试用例且通过；
   - 伴随代码的文档、规格状态与 ADR 更新必须在同一代码变更中提交。

## 治理与演进规则 (Governance)

1. **宪章最高效力**：本宪章是 Home Media Platform 的最高工程与架构治理准则，效力高于任何口头约定、未书面化的团队习惯或临时的代码审查让步。
2. **修订流程**：任何对核心原则的修改均需提出正式修订提案，详述修订原因、影响评估及迁移方案，并由核心维护者一致通过方可生效。
3. **合规审查**：所有 Pull Request、设计方案评审与新功能规格，**必须**对照本宪章各项原则进行合规核验。任何有意为之的设计妥协或技术债务必须有经接受的 ADR 记录说明。
4. **语义化版本定义**：
   - **MAJOR（主版本）**：对核心治理原则的向后不兼容变更、治理结构重大重组或核心边界定义废弃。
   - **MINOR（次版本）**：新增核心原则、追加独立约束章节或对现有规则进行重大实质性扩展。
   - **PATCH（补丁版本）**：非语义性文字润色、排版修正、术语说明补充及语言翻译对齐。
