# ADR-0020：EPG 节目单的呈现尺度与详情形态

- 状态：Accepted
- 日期：2026-11-12
- 适用版本：V1.0+
- 依据：项目宪章核心原则七（频道中心制）、技术约束 5/8（HeroUI v3 + 语义 token）
- 关联：[019-player-control-experience](../specs/019-player-control-experience/spec.md)（同为播放/观看面体验）

## Context

节目单（`/live/guide`）此前存在三个体验问题（产品评审）：

1. **时间轴过密**：`PX_PER_MINUTE = 2`，半小时节目块仅 60px，标题几乎必然截断成「新闻专…」，无法扫读；
2. **节目块像色条**：无圆角层次、块间无缝隙，密集排列时难以区分相邻节目；
3. **详情是居中弹窗**：节目详情用 `Modal` 居中弹出，遮住整个时间轴——而用户看详情时通常还想对照前后排期；
4. **布局宽度不一致**：只有节目单铺满、其他页 1120px 窄栏，观感割裂。

## Decision

1. **时间轴尺度 2px/min → 6px/min**（1 小时 360px、30 分钟 180px、全天 8640px），与参考站同档；横向由墙内滚动承担，DST 日按真实日长、比例不变。
2. **行高 56px → 72px**，为双行卡片留出呼吸感；多泳道重叠仍按 `MAX_LANES` 压缩。
3. **节目块卡片化**：`rounded-lg` + 边框 + `shadow-xs` + 块间留缝（left+1/width-2/top+4/height-8），hover 抬升；语义仍是 `<button>` + `aria-label`（HeroUI `Card` 不是可按压组件，直接套用会丢失键盘/读屏语义）。
4. **节目详情改右侧抽屉**：`Modal` → HeroUI `Drawer`（`placement="right"`，面板宽 420px / `max-w-92vw`），保留原有可访问名「节目详情:频道」与动作按钮；宽度加在 `Drawer.Dialog` 上而非 `Content`（加在 Content 会把定位容器压窄并贴左，已踩坑）。
5. **布局壳统一铺满**：`PublicLayout` 不再整体限宽，顶栏与内容区一律 100%；阅读型内容（首页等）在页面内自行 `max-w-6xl`。壳宽一致、内容易读，两者不互相牺牲。

## 追加决策（2026-11-12 第二轮产品评审）

6. **「回到现在」入口从工具栏迁到 NOW 浮标**：删除工具栏按钮与 ±2h 平移按钮；
   NOW 时间胶囊本身即按钮（可访问名「回到现在」），滚动/拖拽把 now 推出可视区时
   浮标**贴边固定**（左缘不越过频道列），始终可点。读屏的 `role=status`「当前时间」
   语义保留（sr-only 节点）。列表视图无 NOW 浮标，顶部保留一个「回到现在」按钮。
7. **频道列整格可点**：去掉每行的「直播」按钮，整格即「播放该频道当前直播」按钮；
   频道列背景与节目区区分（`surface-secondary` vs 卡面），右缘加渐变阴影提示可横向滚动。
8. **节目块统一用 HeroUI `Card` 承载**，内部仍为 `<button>`（Card 本身不可按压）：
   视觉走 Card，语义走 button，`data-programme-key`/aria-label/LIVE 角标/进度条不变。
9. **点击分流统一**：所有节目块（含正在直播）都打开详情抽屉；「正在直播」只是详情里
   多一个「播放当前频道」主操作，不再块内直接起播。

## 追加决策（2026-11-12 第三轮：铺满可视高度）

10. **节目单铺满一屏高度，墙内滚动**：`PublicLayout` 新增 `fill` 满屏变体（根 `h-dvh`
    + 内容区 `min-h-0 flex-1 overflow-hidden`），仅 `/live/guide` 使用；页面根 → 卡片 →
    墙体逐层 `flex-1 min-h-0`，`GuideScrollContainer` 以 `fillHeight` 把 `maxHeight`
    从 `min(70vh,640px)` 改为 `100%`。结果：页面不再出现整页纵向滚动，节目墙吃满
    剩余高度（975→807、900→732、720→552、600→432），横向/纵向滚动都发生在墙内。
    其他页面保持自然高度（整页滚动）。

## 追加决策（2026-11-12 第四轮：进度可见性与「回到现在」修复）

11. **恢复当前档进度且更明显**：节目块内加「已播比例」填充（`bg-accent/15`，自左铺到
    已播百分比）+ 底部 1px→1h 的 accent 进度条;列表视图当前行同样恢复底部进度条。
    （此前一轮按「不要进度条」删除，实测导致当前档辨识度不足，产品回退该决定。）
12. **修复「回到现在」无效**：根因是 `goNow` 触发 `navSeq` 焦点锚 `focus()` 未带
    `preventScroll`，浏览器把聚焦的窗口标题滚进视口 → 抵消刚做的居中滚动。
    修复：`focus({ preventScroll: true })`；同时把远近策略改为「距离超过一屏直接定位、
    否则平滑」，避免长距离平滑滚动要数秒、观感像没反应。
13. **浮标位置改为滚动时同步写样式**（不经 React 状态）：瞬时大跨度滚动时，
    状态更新有一帧滞后会让浮标先飞出视口再 snap；现在 80ms 内即正确定位。

## 追加决策（2026-11-12 第五轮：台标列与节目块辨识度）

14. **频道列只展示台标,名称走 Tooltip**：列内不再渲染频道名文本,只显示 logo 接口
    (`/api/media/logos/:posterRef`)台标;无 posterRef 回退首字。名称由 HeroUI `Tooltip`
    (Trigger 包裹整格)在悬浮/聚焦时给出;整格仍是「播放该频道当前直播」按钮,
    `aria-label` 保留完整频道名。**原 SC-006「时间轴零 img」守护就此废弃**(产品变更),
    测试改为「台标走 logo 接口 + 无频道名文本」。
15. **当前档不再显示进度条**:只保留背景色区分(`accent/20`),`liveProgressPercent`
    与进度条一并移除(第二次调整,产品最终口径)。
16. **节目块辨识度**:块间留 2px 横向、5px 纵向缝隙;边框 1px(普通档 `border-border/80`,
    当前档 `accent/60`);行加斑马底(`even:bg-background/25`)与更强的小时刻度线
    (`border-border/40`);Card 显式 `rounded-lg` 覆盖 Card 默认大圆角。

## 追加决策（2026-11-12 第六轮：渲染性能与切日连续性）

17. **频道行 memo + 分钟桶**:`GuideChannelRow` 以 `nowMinuteMs`(分钟桶)与预计算
    `programmeMeta` 为输入;`useServerNow` 每 15s tick 时同一分钟内行不重渲染
    (4 次 tick 只渲染 1 次)。
18. **时间格式预计算**:每块原本每次渲染都做 `Date.parse`×2 + `Intl.DateTimeFormat`×2,
    现按 `data` 一次性算好(435 块/次渲染省约 1700 次昂贵调用)。
19. **content-visibility: auto**:离屏频道行跳过布局与绘制(配 `contain-intrinsic-size`)。
20. **切日连续性**:切日保持视口中心的时间位置(记录偏移→新日居中),并预取相邻日期
    (昨天/明天)的分页窗口;配合 `keepPreviousData`,切日不跳回 00:00、不出现加载空白。
21. **测试并发上限**:`vitest maxWorkers = 4` —— 86 文件并行打满 CPU 会让时间敏感用例
    (server-clock / VOD 410 / live-watch) 偶发红;限并发换取确定性。

## 追加决策（2026-11-12 第七轮：跨日连续时间轴）

22. **次日尾巴段**:`GuideWall` 接受 `nextDay` 窗口,在当天时间轴右侧追加 `TAIL_MINUTES=360`
    的节目段(共用同一套频道路与节目块渲染);仅在视口距日界不足 0.75 屏时挂载,
    避免与当日同名节目在可访问名上重复,也省常态渲染。
23. **日界提交**:当「当天 24:00」的内容坐标拖到视口左缘(`scrollLeft ≥ 频道列 + 当天宽`)
    时,提交切到次日并令 `scrollLeft = 旧值 − 当天宽` —— 新旧两帧内容在同一时间点上
    完全对齐,达成连续拖拽(实测:旧 9216 → 新 576,左缘均为 01:07)。

## 追加决策（2026-11-12 第八轮：拖动流畅度）

24. **滚动帧内不做 setState**:原实现每个 scroll 事件都 `setViewport` 触发整面墙重渲染;
   现改为「同步写浮标样式 + 记录 ref」,只有**宽度变化**或**接近日界阈值翻转**才提交
    状态,且后者走 `startTransition`(可被手势打断)。
25. **横向窗口化**:按四屏窗口(左 2 屏余量)只渲染可视区节目块,滚动超过 1 屏才推进
    窗口(transition);首帧测量时同步建立窗口,避免首屏空白。切日渲染量从 435 块
    降到 ~230–320 块。
26. **Tooltip 按需**:标题长度 ≤10 的块不挂 Tooltip(仍有原生 title),实例数从 450
    降到 ~214。
27. **切日提交走 transition**:跨日切换不再阻塞拖动手势。

实测(1440×900,40 帧内拖过日界):长任务从 429ms 级降到 **0 条 >50ms**;
首屏可视区 81 块;往回拖同样 0 长任务。

## Consequences

**正**
- 节目名可显示 6–10 个汉字，扫读效率提升；6px/min 与 30 分钟 180px 与参考站一致。
- 卡片化后相邻节目边界清晰，当前/选中态层次更强。
- 抽屉不遮挡时间轴其余部分，符合「就地查看上下文」；作品页与节目单共享同一面板，形态统一。
- 壳宽一致，页面切换无「忽宽忽窄」。

**负 / 风险**
- 全天内容宽 8640px，横向滚动距离变长；依赖「回到现在」与 ±2h 平移，窄屏更需要横向滚动。
- 卡片留缝依赖 inline 计算的 ±px 偏移，泳道压缩（3 道）时块高可能不足 2 行，已由 `showTimeLine` 回落单行。
- 抽屉在窄屏（<420px）以 `92vw` 呈现，接近全屏，仍保持右侧滑入语义。
- 详情形态变更影响 `/live` 首页与节目单两处宿主；e2e 若按 `[data-slot="modal-dialog"]` 定位详情需改为 `role=dialog` + 可访问名（登录弹层不受影响）。

## Verification

- 单测：`test/guide-detail-panel-host.spec.tsx`、`test/epg/*`、`test/live-upcoming-ended-no-play.spec.tsx`、`test/epg-channel-watch.spec.tsx` 全绿（详情仍按可访问名与按钮断言）。
- 浏览器实测：30 分钟块 178–181px（6px/min）、块高 64px、圆角 8px；详情抽屉 `x=1276, w=420, right=1696, h=975`（右侧贴边满高）。
- 全量：85 文件 / 570 通过 / 1 跳过。
