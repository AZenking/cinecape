# ADR-0012：Profile 续播一致性与新数据代际交付

- 状态：Accepted（2026-10-26 维护者随规格005实施指令显式接受；替代关系自此生效，实施与证据见 specs/005 tasks.md/evidence.md）
- 依据：用户确认不兼容历史业务数据、同Profile跨设备续播；宪章原则二/三/四/五及一致性约束。
- 关联：[规格005](../specs/005-pc-browsing-flow/spec.md)、[研究R6/R7/R10](../specs/005-pc-browsing-flow/research.md)、[数据模型](../specs/005-pc-browsing-flow/data-model.md)、ADR-0004/0005/0009。

## Context

现有播放session与15秒heartbeat用于临时控制/审计，不是个人历史，临时保留清理不能带走续播。多设备、进度重试、seek后退、从头播放与换档会制造乱序。用户同时要求彻底调整，不兼容旧数据，不能因此推定允许自动删库或改写历史决策。

## Proposed Decision

1. 历史独立于临时session，以Household/Profile/Media唯一。服务端每点播resolve分配candidate epoch，不立即建立历史；实际playing有效started上报时才领取写入权，较新有效起播意图胜出，旧设备可继续播放但不能覆盖新owner位置。
2. 每session递增sampleSeq，匹配当前generation并验证有效身份/资源/位置。重复最新样本幂等、迟到旧样本不覆盖、同seq不同载荷冲突。不用客户端时间或max(position)，主动回退与从头播放允许降低位置。
3. resolve增加beginning/resume；服务器在准备ready前读取可信历史与时长。新内容revision不继承旧位置；失败准备不改历史。停止携finalProgress在同一事务内先保存后终态化，重复停止不重写。
4. 新增10秒progress协议，004原15秒heartbeat仍为存活控制、不直接持久化个人历史；004 resolve与stop请求新增字段，其余授权、票据、交付、转换、轨道与seek范围不扩大。
5. 交付采用新空业务库代际2，仅在空旧基线结构上应用0006。旧已初始化库明确拒绝，不提供兼容读取、旧路由别名或自动升级清库。用户免除旧数据迁移/保留要求，不免除新版本一致性、幂等与恢复验证。
6. 保留历史0001～0005迁移与原始媒体；维护者显式选择新DATA_DIR。新版本支持停服备份和匹配版本恢复，备份恢复后旧播放中断、设置授予撤销；不能把旧备份中的活动授权复活。

## Alternatives and consequences

不采用把设备记录直接当历史、解析就计观看、以最大进度合并、先stop再保存、自动删除旧库或永久兼容双流程。多设备同时观看同媒体时本期不合并位置，使用较新已起播session作为单写入者；这是续播显示取舍，不是媒体并发播放限制。

无需为“彻底重构”重写正确的导入/播放内核。无历史升级意味着上线需重新配置账号与来源；这是已授权兼容范围，不意味着可随意删除用户旧目录。原始媒体与独立备份必须保留。

## Migration and rollback

本轮旧业务数据兼容豁免由宪章1.2.0“特定交付例外（仅规格005、存储代际2）”直接授权，本ADR不得自行创建或扩大豁免；交付方案接受时仍须同步001 FR-005、ADR-0004/0005涉及本轮升级路径的适用范围；不静默改旧文件、不宣称旧版本兼容。新版本自身迁移仍验证up/down/up和备份恢复，down仅独立临时库。真实交付回退采用旧镜像+其旧数据目录，不能用新库配旧镜像。

## Acceptance and evidence

待接受。验证真实playing之前无历史、失败从头保留旧位置、两个Profile隔离、两设备新旧epoch和seq乱序、seek后退、跨generation拒绝、stop最终保存原子性、换档后迟到写拒绝、正常停止跨设备误差<=5秒、异常中断丢失<=15秒、新空库闭环及备份恢复。旧数据目录与媒体误删次数必须为0。
