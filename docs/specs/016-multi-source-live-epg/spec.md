## User Scenarios & Testing *(mandatory)*

### User Story 1 - 观影者实时查看当前频道节目与精准进度 (Priority: P1) 🎯 MVP

家庭成员（包括游客与已登录用户）在浏览直播首页（`/live`）或分类网格（`/live/channels`）时，每个频道卡片实时展示当前正在播出的节目名称、已播出进度的动态微条以及即将播出的下一档节目预告。无需全量下载笨重的 XMLTV 文件，当当前节目播出结束时，界面自动、无缝翻转至下一档节目，进度条归零重新计算。若频道没有匹配到节目单，卡片优雅降级显示“暂无节目单”，但频道依然可以直接起播。

**Why this priority**:
这是用户进入直播系统的第一感知界面与核心痛点（“页面如何匹配并展示具体的当前 EPG”），解决频道元数据与时间轴对齐问题，是所有直播体验（卡片播放、EPG 墙定位、换台信息条）的基础。

**Independent Test**:
打开 `/live` 或 `/live/channels` 页面，检查频道卡片能够立即渲染出当前节目标题与百分比进度条；调整测试时间跨越当前节目结束时刻，验证页面无须手动刷新即可自动切换至下一档节目。

**Acceptance Scenarios**:
1. **Given** 用户打开直播首页或分类网格，**When** 页面加载完成，**Then** 每个频道卡片显示规范化频道名、台标、当前正在播放节目标题、时间进度百分比及下一档节目预告。
2. **Given** 某频道当前节目排期到达结束时刻（`end_time`），**When** 系统到达该时刻，**Then** 前端组件通过事件定时器自动将下一档节目翻转为当前节目，重置进度条，无须整页重新拉取。
3. **Given** 某小众频道在所有已配置 EPG 源中均未命中排期，**When** 用户查看该频道，**Then** 界面显示“暂无节目单”，频道卡片保持正常布局，点击起播按钮依然能正常播放该频道。

### User Story 2 - 多 EPG 源自动级联匹配与手动锁定保护 (Priority: P2)

系统接入多个 EPG 来源（例如官方 XMLTV 源与第三方备用 EPG 源）。系统按照“**手动锁定 (ADR-0008) > 来源级 tvg-id 精确匹配 > 高优先级 EPG 源级联 > 频道别名归一化清洗匹配**”的确定性优先级链进行自动匹配。主 EPG 源中缺失节目单的频道，自动由次优先级 EPG 源补充；针对自动匹配失败或异常的特殊频道，管理员可在后台手动搜索并关联正确的 EPG 频道，保存后标记为“手动锁定”，后续后台定时刷新或全量同步时**绝不覆盖**管理员的手动绑定。

**Why this priority**:
单 EPG 源在实际 IPTV 场景中经常面临频道覆盖率低、tvg-id 缺失或命名不规范问题，多 EPG 级联与归一化匹配能显著提升自动化匹配率（由 ~60% 提升至 95%+），而手动锁定保障了异常情况下的最终人工裁决权。

**Independent Test**:
导入两个 EPG 源（源 1 缺失频道 A，源 2 包含频道 A）。验证频道 A 自动由源 2 补充排期；在后台对频道 B 执行手动绑定并锁定，触发全量 EPG 重新拉取，验证频道 B 的手动绑定状态未被重置或覆盖。

**Acceptance Scenarios**:
1. **Given** 系统启用 EPG 源 1 与 EPG 源 2（源 1 优先级高于源 2），**When** 导入频道列表且频道 A 在源 1 中无匹配，但在源 2 存在匹配，**Then** 系统自动采用源 2 的节目单作为频道 A 的排期数据。
2. **Given** 频道在 M3U 中命名包含清晰度或网络标识（如 `CCTV-1 综合 [4K] [IPv6]`），**When** 执行匹配，**Then** 系统自动清洗后缀归一化为 `cctv1`，命中 EPG 源中的对应节目单。
3. **Given** 管理员针对频道 C 手动指定并保存了 EPG 映射（触发 ADR-0008 manual 锁），**When** 后台执行定时或手动触发的 EPG 全量更新，**Then** 频道 C 的绑定关系与排期数据严格保持手动选择，不回退为自动匹配。

### User Story 3 - 多直播源（多线路）聚合与播放器自动容灾 (Priority: P3)

当导入多个包含重叠频道的 M3U 直播源时，系统自动将相同逻辑频道归并为一个实体（`media_item`），其下的各个物理播放地址挂载为“线路 1（默认/高清）”、“线路 2（备用）”等。在播放时，播放器默认选用最高优先级的线路起播；若当前线路遇到网络断开、404/500 或持续卡顿等致命错误，播放器在后台静默尝试切换到备用线路（Failover），并在界面给予轻量提示；同时播放控制栏（OSD）提供“线路”菜单，允许观众手动切换不同线路。

**Why this priority**:
直播源具有高度易变性与失效概率，多源线路聚合与客户端容灾换线彻底消除了传统播放列表中“一个台占多行、坏一个就黑屏”的混乱糟糕体验。

**Independent Test**:
为一个频道配置两条测试流（流 1 模拟返回 500 报错，流 2 正常流）。点击起播该频道，验证播放器在检测到流 1 失败后自动切换到流 2 成功起播，并弹出换线提示；验证在 OSD 菜单中手动点击“线路 1”可切换回流 1。

**Acceptance Scenarios**:
1. **Given** 导入包含同名频道的两个 M3U 列表，**When** 系统完成处理，**Then** 频道列表仅展示一个频道卡片，详情或播放器内挂载两条不同流源的线路。
2. **Given** 用户正在观看频道，**When** 当前播放线路发生致命错误（如连续连接超时或 4xx/5xx），**Then** 播放器自动切换至下一条可用线路重试，且界面呈现“已为您自动切换至备用线路”的提示。
3. **Given** 用户在播放页唤出控制栏（OSD），**When** 点击“线路”按钮，**Then** 弹出线路列表（包含线路名称与清晰度标签），点击任意一条线路立即生效切换。

### User Story 4 - 管理者多源权重与渠道管控 (Priority: P4)

主管理员（输入 PIN 验证身份通过）进入设置面板，可以配置各个 EPG 源的优先级权重、强制触发多源同步、隐藏或停用不需要的垃圾频道、调整频道排序和分组。受管频道遵循 Household 与 ProfilePolicy 边界，儿童档案仅能收看白名单内的频道，任何多源线路的扩展均不突破既有内容安全防线。

**Why this priority**:
确保家庭环境下的内容可控性与治理能力，符合 ADR-0017 与项目宪章的严格角色分工。

**Independent Test**:
以管理员身份将 EPG 源 2 的优先级调至高于源 1，触发刷新，验证匹配结果按新权重更新；将某测试频道设为“隐藏”，验证在普通前台页面该频道消失；以儿童档案登录，验证即便某频道有 3 条可用线路，只要不在儿童白名单中，依然被严格拦截。

**Acceptance Scenarios**:
1. **Given** 主管理员在来源管理中调整 EPG 来源优先级顺序并保存，**When** 重新执行匹配，**Then** 级联回退按新的优先级顺序生效。
2. **Given** 管理员在后台将某频道标记为“隐藏”，**When** 普通用户访问直播首页或 EPG 墙，**Then** 该频道在页面上完全不渲染。
3. **Given** 当前观影者为儿童 Profile，**When** 访问未在 `allowedChannelIds` 白名单中的频道，**Then** 无论该频道包含多少条备用线路，播放解析器均坚决拒绝播放并提示家长锁。

### Edge Cases

- **所有 EPG 源均缺失排期**：频道元数据降级显示“暂无节目单”，但保留该频道的正常起播入口与全部播放线路。
- **所有直播线路均失效**：播放器在轮询尝试完所有线路后停止重试，展示友好的“当前频道所有线路暂不可用，请稍后重试”的错误缺省页，不陷入无限死循环请求。
- **客户端本地时钟偏差**：客户端本地时间若与服务器存在显著偏差（如未开启网络校时），进度条以服务器返回的基准时间戳计算漂移差值，防止进度倒流或越界。
- **EPG 节目单存在时间重叠或间隙**：匹配引擎根据开始时间升序排列，重叠部分以最新节目覆盖，间隙时段安全返回占位标识。
- **手动绑定目标 EPG 频道被源删除**：若已手动锁定的 EPG 频道在后续源更新中消失，该频道节目单状态标记为 `unavailable`，系统保留管理员的配置记录，绝不静默、隐式回退到其他未经验证的源（严格遵守 ADR-0008）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持在同一个家庭（Household）下添加并启用多个 EPG 数据源。
- **FR-002**: 系统 MUST 允许主管理员为每个启用的 EPG 源配置全局优先级权重（数值越小优先级越高）。
- **FR-003**: 系统 MUST 建立多级级联 EPG 匹配链，匹配执行顺序必须严格遵循：
  1. 单频道手动锁定绑定（ADR-0008）；
  2. 直接关联源的 `tvg-id` 精确匹配；
  3. 按优先级升序遍历其他已启用 EPG 源的 `tvg-id` 级联匹配；
  4. 频道名称归一化别名库匹配（清除 `4K`、`1080P`、`HEVC`、`IPv6` 等噪音标签）；
  5. 匹配失败时安全降级为未匹配状态。
- **FR-004**: 针对手动绑定的频道，系统 MUST 保持手动锁定状态（`manual: true`），在全量 EPG 导入与刷新过程中禁止被自动算法覆盖。
- **FR-005**: 针对多 M3U 导入的同名频道，系统 MUST 支持按归一化频道标识聚合成单一逻辑频道，并挂载多条物理播放线路（Lines）。
- **FR-006**: 服务端 MUST 提供高效的批量当前节目投影查询，单次请求同时返回指定频道的 `current`（当前播出节目）、`next`（即将播出节目）以及时间戳。
- **FR-007**: 批量节目投影查询在服务端 MUST 保持固定次数查询预算（Anti-N+1），严禁在频道循环体内执行逐条 SQL 查询。
- **FR-008**: 前端频道卡片 MUST 实时呈现台标、频道名、当前节目标题、时间进度条与下一档预告。
- **FR-009**: 前端 MUST 采用基于当前节目结束时间（`end_time`）的事件定时器进行节目无感翻转，严禁采用高频整页轮询机制。
- **FR-010**: 当频道无 EPG 排期时，界面 MUST 统一显示“暂无节目单”，且 MUST 保留完整的直接起播能力。
- **FR-011**: 播放器内核 MUST 具备自动故障转移机制（Auto-Failover），在检测到主线路不可播时静默切换至下一顺位备用线路，并给出轻量 UI 提示。
- **FR-012**: 播放控制栏（OSD）MUST 提供线路选择控件，支持用户手动切换多条播放流线路。
- **FR-013**: 系统 MUST 严格遵守 `ProfilePolicy` 边界，多线路与多 EPG 的引入不得越过既有儿童白名单（`allowedChannelIds`）和内容分级管控规则。
- **FR-014**: 设置系统 MUST 严格执行 ADR-0017 角色差异化隔离，仅主管理员（`isMain === true`）可访问 EPG 优先级配置、手动绑定及线路管理。

### Key Entities *(include if feature involves data)*

- **Logical Channel (`media_item`)**: 逻辑频道实体，具有系统内唯一的 `mediaId`、规范化频道名称、台标引用、分组分类及排序序号。
- **Playback Line (`playback_source` / `source_entry`)**: 物理流线路，归属于逻辑频道，包含播放 URL、所属来源标识、清晰度标签、权重排序及启用状态。
- **EPG Source (`media_source`)**: EPG 数据源配置，包含源地址、抓取状态、优先级权重（`priority`）及同步快照代际（`epgGeneration`）。
- **EPG Programme (`epg_programme`)**: 节目排期条目，包含节目内部 ID、起始 UTC 时间（`start`）、结束 UTC 时间（`end`）、标题及描述。
- **Manual EPG Binding (`manual_epg_binding`)**: 手动 EPG 绑定记录，以 `media_id` 为主键，记录管理员手动锁定的目标 EPG 来源及目标频道，受版本防并发保护。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在包含多个主流 M3U 与 EPG 源的标准测试数据集中，自动化 EPG 级联匹配成功率达到 95% 以上。
- **SC-002**: 直播首页与分类网格首屏加载时，当前正在播出节目与进度条渲染延迟不超过 500ms（与频道列表并行/同响应返回）。
- **SC-003**: 当前节目播放完毕时，前端界面在 2 秒内无感切换至下一档节目，不产生页面抖动与白屏刷新。
- **SC-004**: 当主播放线路模拟注入 500/断流故障时，播放器在 3 秒内自动切换至健康备用线路恢复播放。
- **SC-005**: 经历 5 次连续全量 EPG 重新拉取后，系统中所有标记为 `manual` 的手动绑定频道保持 100% 映射一致性，无覆盖与丢失。
- **SC-006**: 在儿童档案模式下，100% 拦截未授权频道的播放请求，无论其拥有多少条备用线路。

## Assumptions

- **A1（自动清洗聚合为主，后台手动调整为辅）**：系统在导入 M3U 时，默认以清洗后的标准化名称（剔除 `4K`、`1080P`、`HEVC`、`IPv6`、`[备份]` 等常见后缀）作为逻辑频道聚合依据，并在后台提供线路开关与微调能力。
- **A2（全局权重级联模式）**：多 EPG 源优先采用全局优先级权重级联（源 1 缺失自动由源 2 补充），单频道的特殊诉求通过 ADR-0008 手动绑定精确指定，不引入复杂的逐频道多源加权计算。
- **A3（统一 UTC 时间基准）**：前后端所有节目排期数据均以 ISO-8601 UTC 标准时间戳传输与存储，避免客户端跨时区或夏令时计算错位。
- **A4（公共浏览与鉴权分离）**：当前节目与进度条信息属于公共元数据，游客均可浏览；点击播放时遵循统一鉴权与 Profile 策略拦截（遵循 ADR-0010 与 015 规范）。
