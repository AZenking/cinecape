## Clarifications

### Session 2026-11-01

- Q: 本期设置「个人偏好」分组实际交付哪些偏好项，存在哪里？ → A: 分组先行——仅沿用已存在的偏好项（010 服务端 Profile 级连播/换源偏好等），不新增设备本地偏好项；默认清晰度/音轨/字幕语言等新增偏好不在本期范围，无支持项的子分类不显示（文档 §11 决策 6 据此定案）。
- Q: 游客播放意图在页面刷新后是否保留？ → A: 应用会话内（内存）保留——登录/选档在应用内浮层完成，刷新丢失后重新点击播放即可；意图不写入浏览器存储，身份失效即清除。
- Q: FR-005「所有播放入口」是否覆盖点播入口，验收责任如何划分？ → A: 统一链路为全局机制；点播入口沿用 010 已实现的等价行为，本规格验收仅以直播三类入口为准，点播回归责任按 010，不因本规格触发 010 全量回归。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 游客可浏览，播放一次打通登录、选档与授权 (Priority: P1)

游客可以自由浏览公共首页、直播、EPG 节目单和节目详情，不被登录页阻断。只有点击播放时才进入登录 → 选择 Profile →（必要时 PIN）→ 服务端播放授权的统一链路；授权通过前不发起任何媒体流请求。播放意图被保存：完成登录与选档后自动回到原目标继续授权；授权被拒绝时说明原因并保留节目详情。登录期间错过的直播节目不补播——直播始终播放该频道此刻的内容。

**Why this priority**: 设计文档指出的最需要补齐项（游客播放意图保存、原目标恢复）；它是所有播放入口的公共底座，也是游客转化的核心链路。

**Independent Test**: 以游客身份分别从直播首页、EPG 节目单、首页推荐点击播放，完成登录与选档后核对回到原目标并直接进入授权播放；中途取消核对无媒体流请求、无个人数据读取、无状态残留。仅本故事即可交付「游客能看、一点就通」的完整价值。

**Acceptance Scenarios**:

1. **Given** 游客未登录，**When** 打开首页、直播、EPG 与节目详情，**Then** 全部可浏览且不出现阻断式登录页。
2. **Given** 游客点击「播放当前频道」，**When** 进入登录 → 选档 →（必要时 PIN），**Then** 播放意图被保存，完成后回到原节目详情并继续服务端授权；全程授权通过前无媒体流请求。
3. **Given** 登录或选档耗时较长，期间原节目已结束，**When** 授权发起，**Then** 播放目标被重新解析为该频道此刻的内容，不尝试补播已结束节目。
4. **Given** 服务端授权拒绝（如策略限制），**When** 返回界面，**Then** 显示具体原因并保留节目详情，可返回或再次尝试；不暴露内部细节。
5. **Given** 游客触发私有操作（播放、收藏、查看历史），**When** 界面响应，**Then** 给出登录引导且不产生部分写入；播放走意图保存路径，收藏与历史仅提示不执行。

### User Story 2 - 直播首页「正在直播」优先与统一节目详情面板 (Priority: P2)

直播首页第一视觉是「正在直播」：Hero 表达正在播放的频道、当前节目、直播状态、进度与起止时间，主按钮为「播放当前频道」。页面顺序为节目单入口 → 正在直播 → 接下来 → 按类型浏览。卡片主体可聚焦、只有一个主动作；收藏只收藏频道不触发播放；未来节目不可播放。正在直播、即将开始与从 EPG 进入的节目都打开同一类节目详情面板（保持底层页面可见），节目状态定期安静刷新、不打断用户。

**Why this priority**: 直播首页是直播第一入口，「现在优先」与详情面板统一是本次设计的核心信息架构变更。

**Independent Test**: 键盘走查 /live 首页：核对内容顺序、Now Hero 语义、三类入口的详情面板一致性、卡片行为（收藏/未来节目/无节目单）与 30 秒级刷新不打断；不依赖 Story 1 的授权改造也可验收布局与行为。

**Acceptance Scenarios**:

1. **Given** 打开直播首页，**When** 浏览，**Then** 第一视觉为「正在直播」（频道标识、当前节目、直播状态、进度、起止时间、「播放当前频道」），页面顺序为节目单入口 → 正在直播 → 接下来 → 按类型，无运营横幅式点播 Hero。
2. **Given** 点击直播卡片的收藏按钮，**When** 操作完成，**Then** 仅收藏该频道，不触发播放；未登录时给出登录引导。
3. **Given** 一个即将播放的节目卡片，**When** 查看，**Then** 显示开播时间，主操作为查看详情或节目单；不存在「播放」入口或任何可直接播放未来内容的暗示。
4. **Given** 一个无节目单数据的频道，**When** 查看，**Then** 保留频道身份并显示「暂无节目单」；该频道可用时仍可播放当前内容。
5. **Given** 分别从正在直播、接下来、EPG 进入节目详情，**When** 面板打开，**Then** 三者打开同一类详情面板（抽屉/浮层，底层页面保持可见），内容包含频道名称与标识、节目标题与简介、起止时间与时长、当前状态（正在直播/即将开始/已结束/暂无数据）、主操作与次操作（收藏频道、查看节目单）；来源只影响返回时恢复的页面状态。
6. **Given** 节目状态自动刷新发生，**When** 用户正停留在首页或详情面板，**Then** 焦点不丢失、详情面板不关闭、分页不重置。

### User Story 3 - EPG 节目单：直播的第二入口 (Priority: P3)

节目单页提供日期切换、「回到现在」、时区说明、频道/分类筛选、节目墙或按频道列表。首次进入定位到当前时间附近；用户手动浏览过去或未来时不被自动拉回；「回到现在」只恢复今天与当前时间、不清除筛选。点击节目块打开详情面板而非直接播放；日期、时间窗口、频道分页、视图模式与滚动位置都进入可恢复状态，刷新不丢失。

**Why this priority**: EPG 是独立页面、可独立交付验收的第二入口；其状态保留与定位规则是高频使用体验。

**Independent Test**: 键盘浏览过去/未来日期、切换频道筛选与视图模式、刷新页面、点击「回到现在」，逐项核对定位、保留与不清除行为；可独立于授权改造验收。

**Acceptance Scenarios**:

1. **Given** 首次进入节目单，**When** 页面加载，**Then** 定位到当前时间附近，同时显示当前节目与后续排期，并显示时区说明（家庭时区）。
2. **Given** 用户已手动浏览到过去或未来时段，**When** 数据刷新，**Then** 页面不被自动拉回现在，浏览位置保持。
3. **Given** 用户点击「回到现在」，**When** 恢复完成，**Then** 回到今天与当前时间，频道/分类筛选保持不变。
4. **Given** 点击任意节目块，**When** 响应，**Then** 打开与直播首页同一类详情面板，不默认直接播放；从频道观看按钮进入则播放该频道当前直播而非未来节目。
5. **Given** 用户设置了日期、时间窗口、频道分页、视图模式与滚动位置，**When** 刷新或通过 URL 重新打开，**Then** 全部状态恢复。
6. **Given** 节目单时间显示，**When** 呈现，**Then** 按家庭时区转换并标注，不因浏览器时区变化被自动覆盖。

### User Story 4 - 播放器连续性：退出恢复、切换失效、失败可重试 (Priority: P4)

全屏播放器至少提供当前频道与节目名称、直播状态与进度、切换频道、字幕/音轨/清晰度等当前播放控制、退出播放、播放失败的重试与原因说明。退出播放后恢复来源页面的地址、筛选、滚动、详情状态和焦点；Escape、返回按钮与关闭遮罩都回到触发入口而不是首页。切换 Profile 时先结束旧播放授权再按新 Profile 重新授权。播放器内可打开播放设置浮层，关闭后继续播放。

**Why this priority**: 「连续返回」是设计原则的终点体验；依赖 Story 1 的链路与 Story 2 的详情面板，故排在其后。

**Independent Test**: 从不同入口进入直播播放后分别执行退出、切换 Profile、模拟播放失败，核对恢复完整性、旧授权失效与重试路径；可与 Story 2/3 并行验收。

**Acceptance Scenarios**:

1. **Given** 正在全屏播放直播，**When** 退出播放，**Then** 回到触发入口的页面状态（地址、筛选、滚动、详情面板状态、焦点全部恢复），不回到首页。
2. **Given** 播放中切换 Profile，**When** 新授权完成，**Then** 旧 Profile 的播放授权已结束、旧播放票据不可用；新播放按新 Profile 授权后才继续。
3. **Given** 播放失败（网络或授权后故障），**When** 查看播放器，**Then** 显示原因与重试入口，重试不重复扣减或产生并行会话。
4. **Given** 播放中打开播放设置浮层（字幕/音轨/清晰度等），**When** 关闭浮层，**Then** 播放不中断；浮层不提供跳转到完整设置页的入口。
5. **Given** 用户按 Escape、点击返回按钮或关闭遮罩，**When** 任一操作发生，**Then** 回到触发入口并恢复焦点，不把用户送回首页。

### User Story 5 - 设置布局分组与交互规则（访问验证以届时已接受规则为准） (Priority: P5)

设置从身份/Profile 菜单进入，不放在直播内容的一级浏览区。设置布局为左侧分类 + 右侧详情，按「个人偏好 / 家庭管理 / 系统」分组；个人偏好与家庭管理分别标明作用范围。开关与单选项即时生效；复杂表单局部保存；退出登录、删除 Profile、撤销会话、重置设置必须二次确认；地址保留当前分类；模块加载失败只影响当前模块。播放器内的当前播放控制不重复搬进设置页——设置保存默认值，播放器处理当前值。

**Why this priority**: 布局与交互规则独立于验证模型、可先行交付；但设置价值依赖全局导航框架，且与 011 存在接缝（访问验证归属），故列最后。

**Independent Test**: 打开设置外壳核对分组与作用范围标注、URL 分类保留、即时生效与局部保存、四类危险操作确认、模块级失败与重试；窄屏与键盘走查。验证流程按届时已接受规则另行测试，不计入本故事。

**Acceptance Scenarios**:

1. **Given** 已登录用户打开身份/Profile 菜单，**When** 点击设置，**Then** 进入设置外壳；直播内容一级浏览区不存在设置入口。
2. **Given** 设置外壳，**When** 查看左侧分类，**Then** 分为个人偏好 / 家庭管理 / 系统三组；家庭管理区域标注需要管理授权，个人偏好区域标注仅作用于当前设备/本人；个人偏好只显示确有支持的项，无支持项不显示空模块。
3. **Given** 一个开关或单选偏好（如默认字幕），**When** 修改，**Then** 即时生效，无全页保存按钮；复杂表单的保存按钮只出现在当前编辑区域。
4. **Given** 退出登录、删除 Profile、撤销设备会话、重置设置任一危险操作，**When** 提交，**Then** 先经二次确认并说明后果。
5. **Given** 设置页地址含分类参数，**When** 刷新或直接打开，**Then** 打开原分类模块；某模块加载失败时仅该模块显示错误与重试，左侧导航保持可用。
6. **Given** 用户从播放器打开播放设置浮层或从设置返回 Profile，**When** 关闭/返回，**Then** 焦点恢复到触发位置；播放器内不出现跳转完整设置页的入口。

### Edge Cases

- **游客直达播放深链接**：进入登录流程，完成后按保存的意图回到原目标；不提前读取任何个人数据。
- **刷新导致意图丢失**：播放意图仅限当前应用会话，刷新后不恢复原目标——用户重新点击播放即可，无残留状态、无部分写入。
- **登录等待期间节目结束**：直播重解析为该频道此刻内容；不补播、不报错为失败。
- **自动播放被浏览器阻止**：显示「点击播放」等明确引导；直播为实时流，不涉及续播语义，也不写入虚假观看状态。
- **授权拒绝的具体原因**（内容策略、等级限制、未评级）：向当前用户解释可理解的原因并保留详情；不暴露内部策略细节或他人数据。
- **即将开始与已结束节目**：不可播放、无播放入口；已结束节目可查看详情与节目单。
- **EPG 数据缺失或部分源失败**：保留频道身份与已获取排期，失败区域可重试；不以全空白冒充无数据。
- **刷新与轮询竞态**：任何自动刷新不得关闭详情面板、重置分页/筛选、移动焦点或拉回时间位置。
- **Profile 切换瞬间的在途请求**：旧 Profile 的收藏、历史、授权与在途请求全部失效；不能出现旧身份数据闪现。
- **未选档状态**：可浏览公共内容与进入选档；不能以未确定 Profile 发起播放或读取个人数据。
- **设置模块失败**：仅当前模块报错并可重试；不阻塞其他分类。
- **减少动态偏好开启**：动效仅保留表达焦点与状态变化所需的最小反馈或全部停用。
- **窄屏/低高度窗口**：侧栏与设置菜单折叠为列表后，全部功能仍可经键盘与触摸到达。

## Requirements *(mandatory)*

### Functional Requirements

**全局导航与状态边界**

- **FR-001**: 顶部导航 MUST 提供 首页 / 点播 / 直播 三个内容入口与右侧 登录/当前账号/当前 Profile 区域；设置 MUST 从 Profile 菜单进入，MUST NOT 出现在直播内容的一级浏览区。
- **FR-002**: 四种业务状态（游客浏览 / 已登录未选 Profile / 已登录已选 Profile / 设置已解锁）的能力边界 MUST 按下方状态矩阵执行；未确定 Profile 时 MUST NOT 发起播放或读取个人数据。
- **FR-003**: Profile 切换时，旧 Profile 的收藏、观看历史、播放授权与在途请求 MUST 全部失效；界面 MUST NOT 仅替换头像而保留旧身份状态（播放授权与旧票据的失效细节另见 FR-022）。

**统一播放链路（Story 1）**

- **FR-004**: 游客 MUST 能浏览公共首页、直播、EPG 节目单与节目详情，不被登录页阻断。
- **FR-005**: 所有播放入口 MUST 使用同一条 登录 → 选择 Profile →（必要时 PIN）→ 服务端播放授权 链路；授权通过前 MUST NOT 请求任何媒体流。该链路为全局机制：点播入口沿用 010 已实现的等价行为（本规格不改造、不纳入验收）；本规格的链路验收以直播播放入口为准。
- **FR-006**: 游客或未选档用户点击播放时 MUST 保存播放意图（入口与目标），登录与选档完成后 MUST 回到原目标并继续授权流程；意图仅保存在当前应用会话内（内存），页面刷新后不承诺恢复（重新点击即可），MUST NOT 写入浏览器长期存储。
- **FR-007**: 服务端授权拒绝时 MUST 说明用户可理解的原因并保留节目详情；MUST NOT 暴露内部细节或以首页替代返回位置。
- **FR-008**: 登录或选档完成后 MUST 重新解析播放目标；直播 MUST 播放该频道此刻的内容，MUST NOT 补播用户等待期间已结束的节目。
- **FR-009**: 游客触发私有操作（播放、收藏、查看历史）时 MUST 给出登录引导且不产生部分写入；播放按 FR-006 保存意图，其余操作仅提示不执行。

**直播首页与节目详情（Story 2）**

- **FR-010**: 直播首页内容顺序 MUST 为 节目单入口 → 正在直播 → 接下来 → 按类型浏览；首屏 Hero MUST 表达「正在播放」（频道标识、当前节目、直播状态、进度、起止时间、「播放当前频道」），MUST NOT 使用点播式宣传横幅。
- **FR-011**: 卡片行为 MUST 满足：点击卡片主体打开节目详情；主按钮进入统一播放链路；收藏仅收藏频道、不触发播放；即将播放节目显示开播时间且主操作为查看详情或节目单；未来节目 MUST NOT 显示播放入口或暗示可直接播放。
- **FR-012**: 无节目单数据的频道 MUST 保留频道身份并显示「暂无节目单」；频道可用时 MUST 仍可播放当前内容。
- **FR-013**: 正在直播、即将开始与从 EPG 进入的节目 MUST 打开同一类节目详情面板（抽屉/浮层，底层页面保持可见），内容含频道名称与标识、节目标题与简介、起止时间与时长、当前状态（正在直播/即将开始/已结束/暂无节目数据）、主操作（播放当前频道）与次操作（收藏频道、查看节目单）；来源只影响返回恢复的页面状态。
- **FR-014**: 节目状态 MUST 定期安静刷新（约 30 秒，可随规划调整）；刷新 MUST NOT 关闭详情面板、重置分页或打断焦点。

**EPG 节目单（Story 3）**

- **FR-015**: 节目单页 MUST 提供 日期切换、回到现在、时区说明、频道/分类筛选、节目墙或按频道列表、节目详情面板。
- **FR-016**: 首次进入 MUST 定位到当前时间附近并同时显示当前与后续排期；用户手动浏览过去/未来时 MUST NOT 自动拉回；「回到现在」只恢复今天与当前时间、MUST NOT 清除筛选。
- **FR-017**: 点击节目块 MUST 打开详情面板而非直接播放；频道观看按钮 MUST 播放该频道当前直播而非未来节目。
- **FR-018**: 日期、时间窗口、频道分页、视图模式与滚动位置 MUST 进入地址或可恢复状态；刷新后 MUST 完整恢复。
- **FR-019**: 节目单时间 MUST 按家庭时区显示并标注时区说明；MUST NOT 因浏览器时区变化被自动覆盖（与 011 FR-027 一致）。

**播放器与连续性（Story 4）**

- **FR-020**: 直播播放器 MUST 至少提供：当前频道与节目名称、直播状态与进度、切换频道、字幕/音轨/清晰度等当前播放控制、退出播放、失败重试与原因说明。
- **FR-021**: 退出播放 MUST 恢复来源页面的地址、筛选、滚动、详情状态与焦点；Escape、返回按钮与关闭遮罩 MUST 回到触发入口，MUST NOT 把用户送回首页。
- **FR-022**: 切换 Profile MUST 先结束旧播放授权再按新 Profile 重新授权；旧播放票据 MUST 不可用。
- **FR-023**: 播放器内播放设置 MUST 为浮层，关闭后继续播放；MUST NOT 直接跳转完整设置页；当前播放控制 MUST NOT 被重复搬入设置页（设置保存默认值，播放器处理当前值）。

**设置布局与交互（Story 5）**

- **FR-024**: 设置 MUST 采用左侧分类 + 右侧详情布局，按「个人偏好 / 家庭管理 / 系统」分组；家庭管理区域（左侧菜单呈现为「家庭管理组」）MUST 标明需要管理授权（访问验证按届时已接受的规则执行，本规格不另定义）；个人偏好与家庭配置 MUST 分别标明作用范围；个人偏好 MUST 仅显示确有支持的项，无支持项不显示空模块。本期个人偏好「分组先行」：仅沿用已存在的偏好项（010 服务端 Profile 级连播/换源偏好等），MUST NOT 新增设备本地偏好项或为填充分组引入新的偏好存储。
- **FR-025**: 设置内容边界 MUST 按下方分类边界表执行；MUST NOT 把当前播放器控制重复搬入设置页。边界表定义**能力域归属与交互方式**，不等于本期一次性交付承诺：本期呈现范围以 FR-024 与澄清 Q1 为准（确有支持的项才显示，无支持项的分类/子组不落位）；其中「关于与帮助」分类现行系统无对应模块，本期**显式不落位**（延后至后续规格明确），其余既有模块的表内归属照常执行。
- **FR-026**: 开关与单选项 MUST 即时生效且不使用覆盖全页的保存按钮；复杂表单 MAY 局部保存，保存按钮 MUST 只出现在当前编辑区域。
- **FR-027**: 退出登录、删除 Profile、撤销设备会话、重置设置 MUST 二次确认并说明后果。
- **FR-028**: 设置地址 MUST 保留当前分类（如 section 参数），刷新后仍打开原模块；模块加载失败 MUST 只影响当前模块，左侧导航与重试入口保持可用。
- **FR-029**: 从 Profile 菜单进入完整设置、返回后 MUST 恢复原焦点；播放器内播放设置浮层关闭后 MUST 回到播放器。

**焦点、键盘与响应式（全局）**

- **FR-030**: 全部交互元素 MUST 有明显可见的焦点状态；MUST NOT 仅用颜色表达选中、直播中、错误与禁用。
- **FR-031**: 卡片与列表项 MUST 支持键盘方向移动与 Enter/Space 操作；详情面板 MUST 支持 Escape 关闭并恢复触发焦点。
- **FR-032**: 窄屏 MUST 将侧栏与设置菜单折叠为列表，大屏保留左菜单右详情；动效 MUST 仅用于表达焦点、开关与状态变化，并遵守减少动态偏好。
- **FR-033**: 当前交付平台为 PC 浏览器，交互模型 MUST 按远距离观看设计（可预测返回、清晰焦点、渐进展示）。

### 状态矩阵（FR-002 判定依据）

| 状态 | 可以做什么 | 不能做什么 |
| --- | --- | --- |
| 游客浏览 | 查看公共内容、直播、节目单、详情 | 播放、查看 Profile 私有数据 |
| 已登录未选 Profile | 浏览公共内容、进入 Profile 选择 | 以未确定的 Profile 发起播放或读取个人数据 |
| 已登录已选 Profile | 播放、收藏、查看观看历史 | 访问未授权内容 |
| 设置已解锁 | 管理设置和家庭管理模块 | 绕过服务端权限或敏感操作校验 |

### 设置内容边界表（FR-025 判定依据）

| 分类 | 内容 | 交互方式 |
| --- | --- | --- |
| 账户与 Profile | 当前 Profile、切换、Profile 管理、PIN、退出登录 | 选择器、表单、确认对话框 |
| 播放 | 默认清晰度、默认音轨、自动播放、重试策略 | 开关或单选，修改后即时生效 |
| 直播与节目单 | 默认入口、默认视图、时区显示、频道排序 | 单选或设置面板 |
| 字幕与语言 | 默认字幕、默认音频语言、强制字幕、音频描述 | 单选或选择器 |
| 辅助功能 | 字体、对比度、减少动态、字幕样式、焦点提示 | 即时预览或即时生效 |
| Profile 与权限 | Profile 分级、内容名单、频道权限 | 需要管理授权（按届时已接受规则） |
| 内容来源 | 来源配置、导入状态、同步状态 | 独立管理页面 |
| 节目单与频道匹配 | EPG 来源、同步状态、频道绑定 | 独立管理页面 |
| 播放策略 | 家庭播放规则和权限策略 | 需要管理授权（按届时已接受规则） |

| 关于与帮助 | 版本、条款、隐私、反馈、播放帮助 | 普通链接和信息页 |

### Key Entities *(include if feature involves data)*

- **播放意图**：游客/未选档用户点击播放时保存的临时意图（入口页面、播放目标、触发时间）；登录与选档完成后用于恢复原目标；不含任何凭据，身份失效即清除。
- **节目详情面板上下文**：面板的来源（正在直播 / 接下来 / EPG）、频道与节目标识、返回恢复所需的页面状态；同一面板服务三类入口。
- **直播页面可恢复状态**：直播首页与节目单的日期、时间窗口、筛选、分页、视图模式、滚动位置与焦点；进入地址或等效可恢复形式。
- **频道收藏**：Profile 级收藏条目（频道类型），归属当前 Profile，切换 Profile 后失效；本期沿用既有能力，仅约束交互行为。
- **设置位置与分类状态**：当前分类（地址参数）与模块级加载状态；与 011 的「设置位置记忆」衔接，深链接优先。
- **沿用既有实体**：账号、档案、频道、节目排期、EPG 来源、设备会话、播放会话/票据——本规格不引入新身份模型，不改写 005/010 的播放授权语义。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 游客转化链路——从直播首页、EPG 两类直接播放入口,以及首页直播入口(游客经首页导航卡片进入 /live 后播放;登录态为个人区「观看直播」按钮——现 IA 下游客首页无直接播放钮,经澄清裁决)以游客身份发起播放,完成登录与选档后回到原目标并直接进入授权播放的成功率 100%(每类入口抽样流程全部通过,以应用会话内不刷新的连续流程为准;刷新场景按 FR-006 重新点击验证);授权通过前的媒体流请求次数为 0。
- **SC-002**: 详情与链路一致性——正在直播、即将开始、EPG 三类入口打开同一类详情面板并进入同一播放链路的一致率 100%；未来/已结束节目出现播放入口的用例为 0。
- **SC-003**: 安静刷新——连续观察 ≥10 分钟内，自动刷新导致的焦点丢失、详情面板关闭、分页/筛选重置次数均为 0。
- **SC-004**: EPG 状态保留——日期、筛选、视图、滚动经刷新与「回到现在」后按 FR-016/FR-018 保留（筛选保留率 100%）；首次进入定位当前时间的偏差在相邻节目粒度内。
- **SC-005**: 播放连续性——退出播放后地址/筛选/滚动/详情/焦点恢复成功率 100%；Profile 切换后旧授权与旧票据可用性为 0（负向用例通过）。
- **SC-006**: 状态边界负向——未登录/未选档状态读取私有数据成功 0 次；授权前媒体流请求 0 次；游客私有操作产生部分写入 0 处。
- **SC-007**: 设置布局——三组分类与作用范围标注覆盖 11 类内容边界表 100%；无支持项的空个人偏好模块出现 0 个；四类危险操作确认覆盖率 100%。
- **SC-008**: 可访问性——键盘完成浏览 → 详情 → 播放/取消 → 返回全流程可达率 100%；焦点状态覆盖全部交互元素；Escape 关闭后焦点恢复成功率 100%；仅用颜色表达状态的元素 0 处；减少动态偏好生效。
- **SC-009**: 响应式——窄屏折叠布局下直播浏览、EPG、设置导航全功能可达率 100%；刷新后地址分类与页面状态恢复率 100%。

## Assumptions

- **范围边界（点播，经澄清 Q3 定案）**：设计文档 §3.5 点播整节明确以 [010 规格](../010-online-vod/spec.md) 为准，本规格不重复定义点播需求；仅主导航（FR-001）、四状态边界（FR-002）与「共同边界」中未由 010 覆盖的全局一致性纳入本文。统一播放链路（FR-005）为全局机制，点播入口沿用 010 已实现的等价登录守卫与身份隔离行为——不改造、不纳入本规格验收，也不因本规格触发 010 全量回归（点播回归责任按 010）。
- **范围边界（设置访问验证）**：设计文档 §7.1 的「登录 → 主 Profile 检查 → 设置 PIN」流程及 §10 对应验收项属旧模型；设置区域访问验证规则归属 ADR-0011 与 011（Proposed）的替代关系，本文不定义验证方式，相关验收按届时已接受的规则执行。文档 §11 决策 1（主 Profile 定义与入口可见性）、2（PIN 建立/有效期/锁定）、3（PIN 与密码叠加）据此由 ADR-0011 与 011 框架吸收，不在本文决策。
- **会话恢复（文档 §11 决策 4）**：已有有效会话重新打开应用时的 Profile 恢复沿用现行登录会话行为，本期不改变会话持久化语义。
- **时区（文档 §11 决策 5）**：以家庭时区为权威（与 011 FR-027/FR-035 一致），节目单与设备时间按其显示并标注；不采用浏览器本地自动覆盖，用户级时区覆盖不在本期范围。
- **偏好项范围与存储（文档 §11 决策 6，经澄清 Q1 定案）**：本期个人偏好「分组先行」——仅沿用已存在的偏好项（010 服务端 Profile 级连播/换源偏好等，机制不变），不新增设备本地偏好项；默认清晰度、音轨、字幕语言等新增偏好不在本期范围，避免出现「服务端 Profile 级 + 设备本地」两套并行存储规则；未来新增偏好项的存储位置另走规格变更。
- **「关于与帮助」分类延后（经一致性分析 U1 定案）**：现行系统无该模块；本期不落位、不新增占位页，FR-025 边界表该行仅保留能力域归属记录。后续若需交付（版本/条款/隐私/反馈/帮助），另走规格变更与最小静态页任务。
- **收藏与数据模型（文档 §11 决策 7）**：频道收藏能力已存在（005 契约 `/me/favorites/channels`），本期仅约束交互行为（收藏不触发播放、Profile 归属与失效），不改数据模型；其余新实体（播放意图等）的字段与接口在规划阶段按 005 契约兼容性确定。
- **参数**：节目状态刷新周期约 30 秒为设计建议值，可在规划阶段随性能预算调整；调整不改变验收方式（SC-003 按连续观察法验证）。
- **现状承载**：文档 §9 的组件映射（LivePage/NowHero/NowSection/NextSection/GroupSections/ProgrammeSlotDialog/GuidePage/usePlayAction/ActionCoordinator 等）为现状位置参考；本规格约束目标行为而非实现结构，规划阶段可自行决定复用或重组。
- **与 009 的关系**：全屏播放器与浮层沿用 009 修正案 A 的全局非阻塞框架；本规格的播放器需求为能力清单，不与 009 的模态/浮层治理冲突。
- **证据要求**：验收包含真实浏览器流程与键盘走查；静态梳理与既有测试通过不能替代运行时证据（宪章原则一）。
