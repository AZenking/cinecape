**Feature Branch**: 本次未创建或切换分支；功能标识为 `010-online-vod`

**Created**: 2026-10-29

**Status**: Implementing（2026-10-31 起按 constitution 流转自 Accepted；**实现完成、验证中**——US1–US5 服务端与 web 面已交付且自动化测试全绿（server unit 1484 / contract 730 / web vitest 265，见 [evidence/release-checks.md](evidence/release-checks.md)），FR001–040/SC001–008 逐项证据见 [evidence.md](evidence.md)；真实环境采样（T050 续播 20 次±3s、T066 真实连播、T076 两真实来源 carry、T088 目标 Linux 容器）**Not-run**，不满足 Verified 条件，不虚标 Verified。）

**Governance**: 遵循 `.specify/memory/constitution.md`；按 Proposed → Accepted → Implementing → Verified 流转。本文不授权实施，不代表运行验收完成。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 配置来源并公开浏览 (Priority: P1)

管理员登记在线点播源；游客可搜索电影和剧集、阅读详情并选择线路和分集。只有尝试播放时要求登录及选择当前观看档案。

**Why this priority**: 提供在线内容入口，同时保持现有公共浏览与播放权限的分离。

**Independent Test**: 使用一个可用源和一个超时源，完成游客检索、详情查看；验证游客无法取得媒体流，管理员受保护设置不向游客开放。

**Acceptance Scenarios**:

1. **Given** 管理员已完成现有设置验证，**When** 添加、测试、改名或启停来源，**Then** 显示结果或版本冲突；非管理员、过期设置授权及缺少当次敏感操作验证均不能更改来源。
2. **Given** 多个启用来源且其中一个超时，**When** 游客搜索，**Then** 显示成功来源结果及部分失败状态；全部失败与没有匹配影片使用不同提示。
3. **Given** 搜索结果存在，**When** 游客阅读详情或加载下一页，**Then** 不创建永久媒体或观看历史，不泄露来源地址、凭据及任何人的进度；已生成页面可重复查看。
4. **Given** 用户已登录并选档且允许观看，**When** 首次请求播放某分集，**Then** 成功登记完整影片后即可在公共媒体库看到可用父影片；登记失败无半成品，播放失败不撤销已经完成的登记，也不产生已观看记录。
5. **Given** 一次登记已成功但结果丢失，**When** 在24小时内以相同操作重试且授权仍有效，**Then** 返回原目标，不重复建档；即使原预览过期也可恢复结果。

### User Story 2 - 按观看档案播放和续播 (Priority: P1)

观看者播放影片并保存进度，退出或换设备后继续同一分集；不同档案的历史始终分开。

**Why this priority**: 续播是日常追剧的基础价值，不能以普通采集源缺少不可变内容指纹为由整体取消。

**Independent Test**: 两个观看档案、两台设备，播放同一分集到不同位置；重新打开、切档和重启后核对位置，并验证内容变化的回退。

**Acceptance Scenarios**:

1. **Given** 档案A实际观看并成功保存同源同线路进度，**When** A在另一设备或部署重启后点击继续观看，**Then** 在本次媒体检查通过后恢复服务端确认的位置；档案B看不到A的历史或位置。
2. **Given** 普通采集源的稳定影片和分集身份、连续性信息未变化，**When** 新的播放检查表明时长兼容，**Then** 允许续播并提供从头播放；签名地址变化不单独重置进度。
3. **Given** 内容明确替换、集数身份歧义、时长异常或位置无效，**When** 请求续播，**Then** 从头播放或要求重选并解释原因；准备失败不覆盖旧历史。
4. **Given** 内容已可播放但尚未实际播放或首次进度未被接受，**When** 用户取消，**Then** 不建立观看历史；历史写入被较新的观看覆盖时，旧播放不得覆盖新历史。
5. **Given** 播放期间更换档案、撤销会话或目标策略改为拒绝，**When** 旧播放或延迟操作继续请求资源、保存进度或续播，**Then** 拒绝，切回原档案也不能恢复旧权限。

### User Story 3 - 自然结束后自动下一集 (Priority: P1)

观看者可以开启或关闭自动连播；一集正常结束后有可取消倒计时，下一集重新检查权限后播放。

**Why this priority**: 减少逐集手动操作，是本轮明确纳入的交付目标。

**Independent Test**: 在有序三集样本中结束第一集；分别验证正常连播、取消、关闭开关、第二集受限、缺集及浏览器阻止自动播放。

**Acceptance Scenarios**:

1. **Given** 当前档案开启连播且当前集正常结束、最终样本有效，**When** 结束处理成功，**Then** 出现5秒倒计时，可取消或立即下一集；自然结束判断使用本次最终样本，不要求上一次周期样本已经进入最后5秒。
2. **Given** 下一集受当前档案策略拒绝、缺失、重复编号、季边界或无法确定，**When** 倒计时结束，**Then** 停止自动前进并提示手动选择，不跳过限制也不自动跨来源。
3. **Given** 下一集已有未完成记录，**When** 即将连播，**Then** 先让观看者选择继续目标记录或从头，不静默覆盖位置。
4. **Given** 倒计时期间关闭自动连播或切档，**When** 延迟操作到达，**Then** 不启动下一集；重复结束通知只产生一次有效播放过渡。
5. **Given** 下一集已准备好但浏览器拒绝自动播放，**When** 自动启动失败，**Then** 显示“点击播放”，不写首次观看、不继续跳集；点击后沿用该有效播放，超时失效时重新检查权限。

### User Story 4 - 在播放器内便捷换源 (Priority: P1)

观看者无需退出播放面即可查看其他线路或来源、比较可达性，并选择保留当前位置、使用目标记录或从头播放。

**Why this priority**: 来源不稳定时能快速恢复观看，且不混淆不同版本及个人记录。

**Independent Test**: 使用两个来源的同集样本、一个版本不明样本、一个明确冲突样本；对照目标权限、定位结果、失败恢复和操作去重。

**Acceptance Scenarios**:

1. **Given** 当前播放已接受首次进度，**When** 打开换源，**Then** 看见匹配集名、来源及可达性结果，不暴露地址；最多同时检测3个候选，不产生观看历史或播放权限。
2. **Given** 目标匹配充分且当前会话有已接受位置，**When** 选择保留位置，**Then** 只使用来源会话自己的已确认位置，经目标本次时长检查后定位；同档案另一设备的新历史不得替换该位置。
3. **Given** 版本信息不足，**When** 请求携带位置，**Then** 必须明确选择目标集并确认版本可能不同；明确冲突不能携带位置，不能按列表下标盲目对应。
4. **Given** 进度请求仅被投递、未实际接受，**When** 用户换源，**Then** 不把它显示成已保存；可用本会话更早的有效样本并提示回退，或选择从头，不能借用另一会话位置。
5. **Given** 换源在停止旧播放前失败，**When** 用户返回，**Then** 可恢复仍有效的原播放；旧播放已终结后失败只能重试或重新播放原源，不复活旧播放。
6. **Given** 连点不同目标、多个标签页或取消与启动竞争，**When** 操作并发到达，**Then** 一个来源播放阶段最多成功提交一次后继过渡；失效响应不能让后台新播放无人管理。

### User Story 5 - 稳定退出和全局播放体验 (Priority: P2)

播放、保存、换集与换源由一个一致的控制面负责；浏览其他页面不会中断播放，退出或切档不被网络失败阻塞。

**Why this priority**: 防止增加新体验后破坏现有全局播放和身份切换行为。

**Independent Test**: 播放期间导航、暂停后换源、断网退出及A→B→A切档，验证没有重复保存、无主播放或旧身份回写。

**Acceptance Scenarios**:

1. **Given** 正在播放或下一集倒计时，**When** 仅切换内容页面，**Then** 保留全局播放；只有明确退出、身份变化或失败流程终止播放。
2. **Given** 用户明确换源，**When** 保存/关闭流程进行中，**Then** 能看到进行状态并等待明确结果；普通退出仍在最多1秒保存尝试后继续退出，失败显示未同步。
3. **Given** 请求结果丢失或组件清理重复执行，**When** 重试停止或播放过渡，**Then** 不产生不同载荷的重复最终保存，不重复创建后继播放，不复活终态。

### Edge Cases

- 搜索全部失败、部分成功、缓存失效、上游分页变化：展示区别，已生成页可重放；不承诺未读取上游结果是完整快照。
- 来源禁用后再启用、A→B→A切档：以前的播放权限与过渡均不能复活。
- 同名不同年/季/版本、空或重复集名、编号不连续：不自动合并身份；有歧义时停止自动匹配。
- 时长未知、短视频、最后数秒、倍速、seek到尾：续播与完成资格分别判断；无法确认自然结束时提供手动下一集，不直接自动跳转。
- 当前播放被较新设备抢占历史写入权：可合法继续播放；会话自身的接受位置与个人历史写入结果分别表示。
- 暂停保存未接受、最终保存过期或代次冲突：显示具体保存结果；停止成功不等于保存成功或自然完成。
- 倒计时后新集准备失败、自动播放被拒绝、目标原有历史：不自动递归下一集、不创建虚假观看。
- 操作取消已输给启动：须找回并停止不再需要的新播放，不能只忽略响应。
- 登记成功后预览过期、配额已满、并发首次登记、清理与重放竞争：不重复资源、不返回已删除目标，不留下半登记。

## Requirements *(mandatory)*

### Functional Requirements

#### 浏览、来源与登记

- **FR-001**: 管理员必须能在现有设置授权和敏感操作验证下配置、测试、改名及启停Apple CMS在线来源；普通观看档案不得获得管理权限。
- **FR-002**: 游客必须能搜索和浏览家庭可用在线元数据，不要求登录、选档或内容策略放行；媒体流、凭据、个人数据不可公开。
- **FR-003**: 系统必须区分没有匹配内容、部分来源失败和全部失败，并支持有界分页、过期后重搜及取消。
- **FR-004**: 浏览预览不得永久扩充媒体库；有认证播放意图且当前观看者允许观看时才登记家庭媒体。成功登记立即纳入可用公共目录，不等待个人首次观看。
- **FR-005**: 完整影片登记及其成功重试结果必须一起成功或一起失败；同操作同选择重试复用身份，不同选择不能复用同操作的结果。无变化复用不得制造新的目录变更。
- **FR-006**: 成功登记结果至少可重放24小时，重放不依赖旧预览有效，但重验当前身份、资源和权限；期间保护目标免被回收。资源明确变化时要求重选，不承诺旧播放资格。
- **FR-007**: 每家庭初始支持最多10个启用在线源、5000个父影片及100000个分集；超额明确拒绝而非静默遗漏。未观看且无任何持久/活动引用的登记至少保留24小时后才可回收，不损害历史或策略引用。

#### 身份、策略与资源一致性

- **FR-008**: 历史、续播、连播偏好和播放过渡必须按家庭及当前验证Profile隔离；不能由客户端指定另一Profile或恢复旧上下文权限。
- **FR-009**: 每次独立播放目标、续播、下一集、换源和后续资源访问都必须由服务端验证当前身份、目标策略、家庭资源及最新有效状态；已有播放或测速成功不授予下一目标权限。
- **FR-010**: 父或子显式禁止优先；父子有效等级取较严格者，只有一方有等级时继承它。已评级允许名单可覆盖等级上限，未命中仍可因等级满足而放行；未评级只按未评级策略。不得将允许名单改成必要白名单，其他媒体规则不变。
- **FR-011**: 分集身份必须与临时地址分离，不因签名更新产生新集；同名跨来源/线路不自动合并身份、历史或名单。改名/歧义不凭顺序迁移个人位置。
- **FR-012**: 定位、检查和交付必须属于同一有效播放输入；内容或连续性在准备中变化时结束本次准备并重新授权，不能悄悄重绑版本。固定定位不等于保证外部字节不变。
- **FR-013**: 同一播放阶段的陈旧输出、旧票据、旧过渡和延迟响应不能在新阶段/身份生效。失败不回退或复活已经终结的阶段；取消、任务退出及资源回收均须可恢复且有界。

#### 进度和续播

- **FR-014**: 仅实际播放并接受首次有效样本后建立观看历史；仅浏览、登记、准备或测速不建立历史。进度顺序号在同一会话跨播放阶段仍单调递增，重试保持同号同载荷。
- **FR-015**: 必须分别表示样本投递确认、会话样本接受及个人历史是否更新。会话合法但已失去历史写入权时，允许保存其自身合格位置供主动换源，不改较新历史；拒绝/过期样本不得成为新位置依据。
- **FR-016**: 普通采集源必须支持基于稳定定位、分集结构和已知版本冲突检查的实际续播，称为连续性匹配，不宣称不可变内容证明；本次可信时长检查后才能确认起点。
- **FR-017**: 历史和详情须显示“可尝试继续观看”与确认失败原因，最终资格由本次媒体检查决定。位置不合法、内容/连续性变化、时长不兼容或缺少本次可信时长时从头或要求重选，不静默声称已续播。
- **FR-018**: 续播只能从该Profile的同目标历史读取；必须支持停止、部署重启及其他设备重新认证后的续播。新的实际播放才更新历史，准备失败保持旧记录。
- **FR-019**: 自然完成、接近结尾和未完成必须可区分。初始自然结束容差为min(5秒,总时长的5%)；接近结尾窗口为min(30秒,总时长的10%)，只提示，不自动算完成。未完成且位置仍在时长范围内允许尝试续播，不能仅因位于最后30秒强制从头。
- **FR-020**: 初始时长差异容差为max(30秒,原可信时长的2%)；超过容差不自动继承位置，禁止按百分比强行映射。没有可信时长不能以旧历史冒充本次事实；静态媒体原续播行为保持不变。
- **FR-021**: 起点必须恰有一个服务端依据：从头、目标历史、或主动过渡携带位置；检查完成后一次冻结，另一设备后来更新不能改已冻结起点，不能再被第二次历史读取覆盖。

#### 自然结束与自动下一集

- **FR-022**: 必须保存会话级结束结果，独立表示最终样本是否接受、个人历史是否更新和自动下一集资格；普通停止成功或终态本身不能推导自然完成。
- **FR-023**: 自然结束提示只能在已实际播放、存在本次可信时长及合格最终位置时参与完成判断；先处理最终样本再判定，不能要求前一次周期样本已在尾部。不能仅凭客户端结束标记判完成。
- **FR-024**: 对跳到尾部、倍速、临近尾部续播、短片、断网补报必须执行一致的末段连续播放检查；证据不足时停止自动连播但仍提供手动下一集，不把观看完成当作媒体授权证明。允许的正常倍速不得仅因墙钟时长不足被拒绝。
- **FR-025**: 初始自动连播默认开启，开关按Profile持久保存；仅对同源同线路明确连续的下一常规集生效。编号缺失/重复、季边界、花絮或影片末尾停止，不能自动跨来源或跨电影。
- **FR-026**: 自动下一集必须显示5秒可取消倒计时；倒计时期间仅准备展示信息，不产生下一集观看记录。关闭连播或切档后，延迟操作不能启动下一集。
- **FR-027**: 下一集必须独立授权；已有未完成历史时让观看者选继续或从头，禁止自动覆盖。手动下一集不要求自动开关开启或自然完成，但仍按可靠顺序选择并鉴权。
- **FR-028**: 自动播放被浏览器阻止时显示可操作的“点击播放”，不写虚假首次观看或继续跳集；等待最多60秒后释放该未起播播放，后续点击重新准备并鉴权。

#### 换源及播放过渡

- **FR-029**: 播放面必须提供当前线路和跨来源候选、匹配集名及有界可达性比较，用户无需退出重搜；测速最多3候选且不产生票据、媒体授权或历史，未授权目标不得探测。
- **FR-030**: 匹配充分至少要求规范标题、电影年份或剧集年份/季/集一致且语言/版本无冲突；缺关键字段归歧义，明确不同版本归冲突。歧义需确认具体目标才能携带位置，冲突不允许携带，标题相同或列表下标不构成充分匹配。
- **FR-031**: 用户可选择携带当前位置、使用目标自己的历史或从头。携带位置只能取当前设备来源会话及阶段中已接受的样本和可信时长，不得取其他会话最新历史或客户端提交的任意起点。
- **FR-032**: 保存未接受时须提供本会话更早合格位置并提示回退，或让用户选从头；不能将仅投递成功显示为已保存。目标检查不通过则从头并说明原因。
- **FR-033**: 过渡必须具备可等待的暂停保存、目标准备、旧播放关闭和新播放启动结果，统一协调周期/最终保存与卸载兜底；不因重复清理发送同序号不同载荷。
- **FR-034**: 旧播放尚未终结时过渡失败可恢复仍有效的旧播放；旧播放终结后不复活。普通退出/切档最多尝试1秒最终保存后继续退出，失败提示未同步，不阻止身份撤销。
- **FR-035**: 过渡意图绑定设备、Profile、身份上下文、来源会话阶段、目标修订及用途，初始有效期60秒。创建与消费均重验，自动下一集在消费时再检查偏好；停止旧播放不单独使已合法创建的意图失效，撤销/切档/版本冲突则使其失效。
- **FR-036**: 消费过渡并建立后继播放必须整体成功或失败；同一来源阶段最多一个成功后继过渡，包含不同操作标识、多标签页和重复结束事件。尚未消费时可显式替换目标并使旧意图失效；成功消费后新的选择须针对新播放发起。
- **FR-037**: 成功过渡重试返回原后继播放当前结果，不重复创建；取消先成功则不得启动，消费先成功则必须找回其结果。用户已改变目标时对不再需要的已建播放显式停止，不只丢弃响应；终态重放不复活。
- **FR-038**: 携带位置不得永久合并不同源的历史或身份；目标实际播放才写目标记录。不得自动无限轮换来源，策略拒绝不通过尝试其他来源绕过。
- **FR-039**: 所有个人、控制和设置响应不得进入公共缓存；错误、地址及测速不得泄露私有来源或其他Profile信息。过期及失效操作必须明确可恢复行为，未初始化或存储故障不可伪装成无内容。
- **FR-040**: 本功能必须保持全局非阻塞播放、内容页面导航不断播及既有静态媒体/直播行为；身份变化终止旧播放与倒计时，普通路由变化不视为退出。

### Key Entities *(include if feature involves data)*

- **家庭在线来源**：家庭所有的提供方配置、展示名称、启用状态及定位有效版本，只有管理员能管理。
- **影片、线路与分集**：影片是浏览父项，线路内分集是独立播放目标；稳定身份与临时播放位置分离，保存明确序列与歧义信息。
- **媒体登记及重试结果**：一次认证播放意图的家庭资源登记、选择和可恢复结果；不是观看历史。
- **内容连续性描述**：稳定定位、已知年份/季度/版本及分集映射；可表达操作上连续，不声称等价于不可变媒体证明。
- **播放会话及阶段**：绑定当前设备与观看身份的受控播放，包含固定定位输入、内容修订、服务端起点及状态；旧阶段不可复活。
- **会话接受位置与结束结果**：该会话自己的有效样本、最终保存和自然结束资格，独立于是否拥有个人历史写入权。
- **Profile观看历史与偏好**：分集位置、时长、完成状态及连播开关；跨设备同档案共享、跨档案隔离。
- **播放过渡**：当前来源阶段到目标播放的一次短期、可取消、可重试意图，携带服务端确定的定位依据，不是播放权限。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在3个可用来源和1个超时来源、正常测试网络下，每源最多100条样本、20次搜索中至少19次在8秒内展示结果及正确部分失败提示；所有来源不可用时100%区别于无匹配。
- **SC-002**: 对同源同线路、连续性未变化且时长兼容的样本，20次停止/重新打开中至少19次恢复到最后已确认位置±3秒；覆盖部署重启和两设备同Profile，未确认位置不计入恢复承诺。
- **SC-003**: 在可自动播放环境的10次正常多集结束测试中，10次倒计时后只启动正确下一集一次；取消、缺集、受限、关闭开关及浏览器阻止的各组负向场景均不误启动或写入历史。
- **SC-004**: 两来源同集匹配样本的10次主动携带位置切换，全部在目标实际播放时恢复到服务端冻结位置±3秒；冲突/时长异常的所有样本均要求重选或明确从头。
- **SC-005**: 跨家庭、跨Profile、切档再切回、会话撤销及旧响应竞争的全部验收样本均拒绝旧权限/写入；公共浏览中个人位置和私有来源泄漏为0。
- **SC-006**: 成功登记丢响应、并发重复登记、重复结束、连点换源和取消竞争各执行20次；无半登记、重复有效后继或无人管理的播放，终态复活为0。
- **SC-007**: 普通导航20次保持播放及进度连续；断网退出/切档在1秒保存尝试后不再被保存流程阻塞；所有失败均显示未同步状态而不是保存成功。
- **SC-008**: 上线验收必须包含真实浏览器及目标Linux容器的停止后续播、有序多集连播和两来源换源证据；模拟数据验证不能替代实际播放证据。既有NAS续播与直播回归场景全部通过。

## Assumptions

- 本期面向PC，自托管、单部署单家庭；复用现有认证、选档、设置验证及播放控制，旧业务数据必须保留。无清库豁免。
- 兼容范围为Apple CMS JSON来源和标准VOD HLS；依赖用户配置的外部源、可探测媒体和设备能力。未支持的DRM、脚本、网页解析及专用凭据来源须明确显示不兼容。
- 本期不包含榜单、全站扫描、广告移除、源订阅导入、自动跨源故障轮换或跨源永久历史合并。海报经服务端同源代理提供（`GET /api/public/vod/posters/:posterRef`：不透明 ref + SafeUpstream 有界读取，不向前端暴露上游图床地址），上游未给海报或代理失败时使用占位。用户要求的续播、自动下一集及便捷换源均属于本期交付，不以后续指纹适配为前置。
- 普通源无提示替换媒体仍可能产生位置误差；基于稳定身份/结构/时长校验的续播是明确的体验取舍，不改变任何身份和内容访问权限。
- 初值：连播默认开、倒计时5秒、过渡60秒、成功登记重放24小时、无引用登记保留至少24小时；均是本规格的可验收默认值，调整需同步规格，不是已上线设置。
- 自然结束是产品播放结果而非“证明用户完整观看”的安全凭证；末段连续播放须支持0.5–2倍速，初始合格末段为最后一次seek/起播后至少min(2秒,总时长的5%)的媒体时间连续推进，结束位置落入FR-019容差且期间没有已知错误/暂停/跳跃；倍速按媒体时间判断。上报须符合当前会话顺序和已交付事实，但不将这些观测描述为不可伪造的观看证明。只靠最终位置无法确认时，自动连播保守停止，手动下一集仍可独立授权使用。
- SC-001在受控正常网络/样本规模下测量，不能保证外部来源服务水平；其余体验验收选择明确支持的可播样本，并单列外部故障证据。
- 后续规划必须将播放完成资格与样本顺序、会话阶段和在途保存的可等待行为写入明确设计，并同步讨论方案与005受影响契约；不得直接照搬讨论稿中“2xx即已保存”或“stop成功即完成”的旧推断。
- 本规格只定义用户需求及可验收结果；领域模型、接口、事务协调、并发数据约束及具体测试实现留给后续规划与ADR。本次不创建实施计划、任务或业务代码。

## 审查修订补充验收（2026-10-30，关联I1–I5、U1–U2）
