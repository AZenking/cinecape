# Feature Specification: 直播全流程重构——即开即看、智能分流与同类切台 (Live TV Experience Redesign)

**Feature Branch**: `015-live-flow-redesign`

**Created**: 2026-11-08

**Status**: Proposed

**Governance**: 遵循 `.specify/memory/constitution.md` 核心原则一（规格驱动与多层证据验收）、核心原则二（身份与数据边界隔离）、核心原则三（公开浏览与默认安全的服务端播放鉴权）。按 Proposed → Accepted → Implementing → Verified 流转。

- [ADR-0009: 播放交付与转换决策](../../adr/0009-playback-delivery-conversion.md)

- 参考相邻规格：[规格 005（PC 浏览与播放授权链）](../005-pc-browsing-flow/spec.md)、[规格 012（直播与设置体验）](../012-live-settings-experience/spec.md)、[规格 014（频道 Logo 链路）](../014-channel-logos/spec.md)

**Input**: 用户手绘线框草图（`media_1794127889674_ebb61729.jpg`）、批注修正图（`media_1794134731713_7d429d8b.png`）及会话方案共识：
1. 解决直播核心矛盾——彻底消除“看直播必须前进二级详情页再点击播放”的高摩擦路径，实现卡片 Hover/点击直接起播与就地播放；
2. 明确两大精准分流路径：Live 行直达 EPG 节目单时间墙（Screen 3）；各个分类行展示系统全部分类，点击对应分类的查看全部直达分类平铺网格（Screen 2）且自动高亮选中目标分类 Tab；
3. 直播首页顶部 Hero 区域为【直接播放】核心大屏，支持直接收看直播；下方自上而下【展示各个分类】的频道泳道；
4. 独立一体化播放与详情页（Screen 4）进入即自动起播，右侧伴随展示当前节目进度与下一档预告，下方提供同类型直播横条（`sam type live`）实现无缝平滑切台换流。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 首页大屏直接播放与各个分类全景展示 (Priority: P1)

作为一名家庭观众或访客，打开直播综合首页，顶部大屏即具备实时播放能力，我能开门见山直接收看推荐的直播电视，而无需跳转其他页面；页面下方逐行清晰展示系统里的各个频道分类（如电影、音乐、体育、央视、卫视等），我可以快速横向浏览各分类的热门直播，也可以悬停卡片直接点击播放按钮立即换台。

**Why this priority**: 直播首页是用户进入直播功能的第一视觉。顶部“直接播放”与下方“按分类展示”奠定了开门见山、低摩擦找台与看台的核心基调。

**Independent Test**: 打开直播首页，验证顶部大屏直接呈现正在播放的直播流并支持全屏/展开；验证下方完整排布各个分类行；验证鼠标悬停任意频道卡片浮现快捷播放按钮，点击后立即以全屏或一体化播放页起播该频道。

**Acceptance Scenarios**:

1. **Given** 用户（含游客）进入直播首页，**When** 页面加载完成，**Then** 顶部大屏区域作为直接播放核心，加载并呈现热播精选频道直播流，提供音量与全屏控制，无需跳转即可直接收看。
2. **Given** 用户浏览直播首页下方区域，**When** 纵向滚动页面，**Then** 界面依次呈现：正在直播行、即将播放行、以及按系统各个频道分组（电影、音乐、体育等）逐行平铺展示的分类频道泳道。
3. **Given** 正在直播或分类频道卡片，**When** 用户悬停在卡片上，**Then** 卡片正中浮现明确的播放按钮；点击播放按钮直接发起该频道当前直播播放，不进入静态二级图文页。
4. **Given** 用户点击卡片上的标题或信息区域，**When** 触发交互，**Then** 导航至播放与详情一体化页，展示该频道完整节目元数据并自动加载起播。
5. **Given** 即将播放（Next）分类行中的卡片，**When** 用户点击，**Then** 导航至一体化详情页展示未来节目预告排期，卡片本身不显示“立即播放”按钮，避免暗示可提前收看未开播流。

### User Story 2 - Live 行一键直达 EPG 节目单时间墙与相交节目即时起播 (Priority: P1)

作为一名关注电视排期的观众，我想纵览“全网各个台现在播到哪、接下去播什么”，点击正在直播行的“查看全部”后，我能直接进入横向时间轴排布的 EPG 节目单墙，红色的当前时刻线（NOW）清晰标出此时此刻的播放进度；点击与红线相交的正在播出节目块，我能立刻收看该频道直播。

**Why this priority**: 满足“时间与排期维度”的检索诉求。将 Live 查看全部直接导向 EPG 墙，避免了死板的无时间轴卡片列表，符合看电视排期的第一直觉。

**Independent Test**: 从直播首页正在直播行的行尾点击“全部正在直播”，核对直接导航至 EPG 节目单时间墙；验证页面以当前时刻为锚点居中呈现，垂直时间红线对齐当前时刻；点击与红线相交的正在播出节目块，直接触发播放。

**Acceptance Scenarios**:

1. **Given** 用户在直播首页正在直播（Live）泳道，**When** 点击行尾的“全部正在直播”入口，**Then** 页面直接导航至 EPG 节目单时间墙，横向聚焦在家庭时区的今天与当前时刻范围。
2. **Given** 用户在 EPG 节目单时间墙中浏览，**When** 界面呈现排期，**Then** 纵贯所有频道的当前时刻垂直红线（NOW）准确标记当前时间位置，并标出绿色的当前直播标签。
3. **Given** 用户在 EPG 墙中看到一条正在播出的节目（与 NOW 垂直红线相交），**When** 用户点击该节目块，**Then** 系统直接起播该频道当前直播流，无需二次点击。
4. **Given** 用户在 EPG 墙中看到一条未来时段的节目块（位于 NOW 红线右侧），**When** 用户点击该节目块，**Then** 弹出轻量节目详情抽屉或浮层，展示节目标题、起止时间、简介及距开播倒计时，并提供“收看该频道当前直播”的备用入口。
5. **Given** 用户在时间轴上横向滚动查看较远排期，**When** 点击顶部的“回到现在”按钮，**Then** 视图平滑滚动重置回当前时刻红线居中位置。

### User Story 3 - 各分类查看全部进入分类网格与 Tab 联动检索 (Priority: P2)

作为一名想按兴趣找台的观众（例如“我想看电影频道”），点击电影分类行的“查看全部”后，能进入多列平铺的分类网格大厅，顶部的“电影”标签自动处于激活状态；我可以进一步切换到体育、新闻等其他分类，也可以使用搜索框快速过滤频道。

**Why this priority**: 满足“内容分类维度”的深入检索与收藏诉求，形成“首页发现热门 → 分类大厅拉清单搜台”的顺畅体验。

**Independent Test**: 从直播首页的“电影”分类行点击查看全部，验证进入分类网格页面且顶部分类 Tabs 中“电影”自动高亮选中；验证切换 Tabs 仅展示对应分类下的全部频道；验证搜索输入即时过滤频道名称。

**Acceptance Scenarios**:

1. **Given** 用户在直播首页某个具体分类行（如“电影”），**When** 点击行尾的“查看全部”，**Then** 导航至分类平铺网格页，URL 携带该分类标识，顶部分类 Tabs 自动高亮选中“电影”，主体呈现该分类下频道的响应式多列网格。
2. **Given** 用户在分类平铺网格页中，**When** 点击顶部分类 Tabs 中的其他类别（如“体育”或“全部”），**Then** 网格内容平滑更新为对应分类的频道，URL 参数同步更新，无需刷新整页。
3. **Given** 用户在分类平铺网格页中，**When** 在搜索框中输入关键字，**Then** 频道网格实时按频道名称模糊匹配过滤，并提供一键清空搜索能力。
4. **Given** 分类网格中的任一频道卡片，**When** 用户悬停在卡片上，**Then** 展现直接播放按钮与快捷收藏按钮，点击播放按钮直接起播。

### User Story 4 - 播放与详情一体化页与同类型直播无缝切台 (Priority: P1)

作为一名正在收看直播的观众，进入独立播放页面后，播放器自动起播，右侧伴随显示当前节目的播出进度、简介以及下一档预告；在播放器下方列出“同类型正在直播”的其他频道横条，当我点击另一个频道卡片时，播放器就地切换直播流，右侧信息即时更新，无需重载整个页面。

**Why this priority**: 这是消费阶段的核心闭环。将播放器、节目伴随信息与同类型快捷切台融合在一个页面，重现传统电视或现代流媒体沉浸式“一边看台、一边切台”的自然体验。

**Independent Test**: 点击任意频道的播放或详情入口，验证进入一体化播放页并自动缓冲起播；验证右侧展示当前节目进度、简介与下一档预告；验证底部呈现同类型直播频道横条；点击横条中的另一频道，验证播放器无刷新平滑换流，右侧信息与浏览器地址栏同步更新。

**Acceptance Scenarios**:

1. **Given** 用户从任何入口选择收看某频道，**When** 进入播放与详情一体化页，**Then** 左侧/上部实时播放器自动发起播放解析并加载直播流，右侧/侧边展示频道标识、当前节目名、时段进度百分比、节目简介及收藏切换状态。
2. **Given** 当前频道存在下一档排期，**When** 用户查看右侧面板，**Then** 明确展示“即将播放（Next）”节目名称与开播时间，让观众提前获知后续排期。
3. **Given** 当前频道归属于某一分类（如“电影”），**When** 页面加载完成，**Then** 播放器下方横向呈现“同类型正在直播”频道列表，聚合当前同样在播电影的其他频道，卡片显示频道名与当前节目标题。
4. **Given** 用户正在收看频道 A，**When** 点击底部同类型直播列表中的频道 B，**Then** 页面不触发全局刷新重载，播放器就地切换至频道 B 的直播流，右侧面板即时更新为频道 B 的节目详情，浏览器地址栏同步平滑更新为频道 B 的地址。
5. **Given** 用户点击频道收藏按钮，**When** 操作成功，**Then** 收藏图标即时切换为已收藏状态；已选 Profile 的收藏状态跨设备与刷新持久保留。

### User Story 5 - 游客免登录浏览与播放意图全链路恢复 (Priority: P2)

作为一名未登录的访客，我可以自由浏览直播首页、EPG 节目单、分类网格以及频道详情元数据；当我点击任意播放入口或换台时，系统弹出轻量登录/选档弹层；完成验证后，系统自动继续我最初选择的频道起播，无需我重新寻找内容。

**Why this priority**: 坚守 [ADR-0010](../../adr/0010-public-browsing-playback-separation.md) 与宪章核心原则三，让游客零门槛了解家庭媒体库资产，同时确保播放鉴权无缝衔接，不产生断崖式体验。

**Independent Test**: 在无会话状态下访问直播首页，浏览分类与 EPG 墙；点击任意频道的直接播放按钮，验证弹出登录选档弹层；完成登录与 Profile 选择后，验证自动继续发起原频道的播放流程；若在弹层中点击取消，验证回到原浏览位置且不触发后台播放。

**Acceptance Scenarios**:

1. **Given** 游客访问直播首页、分类网格或 EPG 节目单，**When** 滚动与查看各类元数据，**Then** 页面正常呈现全部内容，不弹出强制登录阻断，不要求预先选档。
2. **Given** 游客点击任意频道的直接播放按钮或相交于 NOW 线的节目块，**When** 触发播放操作，**Then** 系统暂存当前播放意图（目标频道标识），并弹出统一登录与档案选择弹层，在授权前绝不向服务器请求媒体流数据。
3. **Given** 游客在弹层中完成账号登录并选择有效 Profile，**When** 认证与选档成功，**Then** 弹层关闭，系统自动恢复原暂存的播放意图，并向服务端发起播放授权，授权通过后顺利起播。
4. **Given** 游客在登录或选档过程中点击取消或遮罩关闭，**When** 弹层退出，**Then** 用户平滑停留在原浏览界面，暂存意图被丢弃，不发起任何后台播放，不产生残留报错。
5. **Given** 游客尝试点击收藏按钮，**When** 触发操作，**Then** 弹出轻量引导提示用户登录选档，不产生脏数据写入。

## Edge Cases

- **频道无 EPG 排期数据**：当某频道来源没有可用 EPG 节目单时，直播首页、分类网格及播放页依然必须允许发现和正常播放该频道；节目标题位置统一显示“暂无节目单”，播放控制正常可用。
- **当前节目刚巧在跨日/换档临界点**：节目在整点切换时，正在直播与即将播放卡片在 30 秒内自动更新为新节目标题；若用户在临界点发起播放，播放始终指向该频道此分此秒的实时直播流，绝不尝试回放已结束的时段。
- **同类型直播为空**：若当前频道所属分组下只有该频道自身一个可用频道，则同类型直播区域自动隐藏或显示该分类下的唯一频道标注，不产生空白死角或破坏布局。
- **频道流加载失败或源失效**：若某个频道由于上游流故障无法播放，一体化播放页内明确展示“当前直播信号暂时不可用，请尝试其他频道”，并保留右侧节目简介与底部同类直播横条，用户可一键切换其他同类频道。
- **窄屏或窗口缩放（768px~1024px）**：在 PC 较窄窗口或 200% 缩放比例下，播放页右侧伴随面板自适应下沉到播放器下方，同类型直播横条紧随其后水平滚动，保证播放器主体与文字内容无重叠溢出。
- **键盘导航与焦点管理**：在 EPG 节目单墙和卡片列表中支持 Tab 键与方向键导航，所有可交互卡片与节目砖块具备高可见度的焦点环（Focus Ring），回车键即时起播。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 直播首页（`/live`）MUST 采用“顶部直接播放大屏 + 正在直播泳道 + 即将播放预告 + 全部分类横滑泳道”的自上而下布局结构。
- **FR-002**: 直播首页顶部 Hero 区域 MUST 具备就地直接播放能力，展示当前热播或首选频道的直播画面，并提供进入全屏或一体化播放页的快捷入口。
- **FR-003**: 首页正在直播（Live）泳道末尾 MUST 提供“全部正在直播”入口，点击直接导航至 EPG 节目单时间墙（`/live/guide`），禁止导向无排期的静态列表。
- **FR-004**: 首页各频道分类泳道（电影、音乐、体育、央视等）末尾 MUST 提供“查看全部”入口，点击导航至分类平铺网格（`/live/channels`），且 MUST 通过 URL 参数自动激活目标分类 Tab。
- **FR-005**: 正在直播与分类列表中的所有频道卡片在悬停或聚焦时 MUST 呈现显式的播放操作按钮，点击后直接发起起播流程，取消强制进入静态二级详情的步骤。
- **FR-006**: 即将播放（Next）卡片 MUST 仅展示排期预告与倒计时，MUST NOT 提供提前播放未来内容的入口。
- **FR-007**: 分类平铺网格页（`/live/channels`）MUST 提供包含系统全部分类的导航标签栏（Tabs）、实时频道名称搜索框以及响应式多列频道卡片网格。
- **FR-008**: EPG 节目单时间墙（`/live/guide`）MUST 纵贯展示代表当前系统时刻的垂直指示线（NOW），与 NOW 指示线相交的正在播出节目块点击 MUST 直接发起该频道的实时播放。
- **FR-009**: EPG 节目单时间墙中位于 NOW 指示线右侧的未来节目块，点击 MUST 弹出轻量抽屉或浮层展示节目简介，并保留收看该频道当前直播的辅助入口。
- **FR-010**: 系统 MUST 提供独立的播放与详情一体化页（`/live/watch/:channelId`），该页面进入后 MUST 自动发起播放解析并呈现视频流播放器。
- **FR-011**: 播放与详情一体化页在播放器伴随区域 MUST 展示该频道的当前节目标题、播出进度百分比条、节目详细介绍、收藏切换按钮以及紧接着的下一档节目预告（Next）。
- **FR-012**: 播放与详情一体化页下方 MUST 展示同类型正在直播频道横向列表（`sam type live`），其内容基于当前频道的分类（`group_title`）动态筛选。
- **FR-013**: 在一体化播放页点击下方同类型直播卡片时，页面 MUST 在原地平滑切换播放器流地址并即时更新伴随信息，禁止整页刷新重载，且 MUST 保持浏览器 URL 路径与当前播放频道同步。
- **FR-014**: 系统所有直播页面与元数据 MUST 允许游客在无认证状态下自由查阅；点击播放或换台时 MUST 暂存播放目标，经登录与 Profile 选择后自动无缝恢复起播，授权通过前 MUST NOT 请求任何媒体流数据。
- **FR-015**: 播放授权、Profile 内容分级策略（ProfilePolicy）以及家庭资源归属校验 MUST 在每次换台与起播时由服务端强鉴权保证，浏览可见不豁免播放授权。

### Key Entities *(include if feature involves data)*

- **Channel**: 直播频道基础实体，包含稳定标识（`mediaId`）、频道显示名、频道 Logo 引用、主分组类型（`group_title`）以及可用性状态。
- **ProgrammeSlot**: 节目时段实体，包含所属频道、节目标题、简介、时区感知的开播时间（`startsAt`）与结束时间（`endsAt`）。
- **LiveCategoryGroup**: 频道分类实体，来源于媒体来源配置的真实分组（如电影、新闻、音乐、体育），映射为分类导航 Tabs 与首页分类泳道。
- **PlaybackIntent**: 播放意图会话实体，暂存用户选中的起播目标频道与启动模式，在游客认证全流程中保持连续性，登录完成后自动消费并销毁。
- **RelatedLiveChannels**: 关联同类直播聚合模型，按当前频道的 `group_title` 抓取并排除当前频道的其他正在播出频道清单。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在直播首页悬停正在直播或分类卡片，点击播放按钮后到播放器首帧开始缓冲的交互路径缩短为 1 次点击（消除原本必须进入详情页再点击播放的中间步骤）。
- **SC-002**: 从直播首页 Live 行尾点击“全部正在直播”，100% 直达 EPG 节目单时间墙并准确定位至当前时刻红线位置，无中间阻断或错误重定向。
- **SC-003**: 从直播首页任意分类行（如“电影”）点击查看全部，100% 导航至分类网格并自动高亮激活该分类 Tab，正确呈现该分类下的全部频道。
- **SC-004**: 在独立播放与详情一体化页面点击下方同类型直播卡片换台，页面重载刷新次数为 0，播放器切流响应时间与网络加载平滑衔接，URL 自动与当前播放频道保持一致。
- **SC-005**: 游客在未登录状态下点击任意频道的直接播放，经登录与选档完成后自动进入起播状态的成功率为 100%，全程在通过服务端授权前媒体流数据请求次数为 0。
- **SC-006**: 在包含 200 个频道、多分类的大型测试数据源下，直播首页多分类泳道加载与 EPG 节目单时间轴首次渲染在主流设备上保持流畅稳定，无操作卡顿与水平布局外溢。

## Assumptions

- **A-001 数据模型复用**：频道的分类直接沿用现有数据源的 `group_title`，无分组频道归入默认“其他”分类，不引入臆造的模糊分类算法。
- **A-002 播放能力对齐**：播放内核与流媒体协议沿用现有统一受控播放解析器（`Playback Resolver`）及 HLS/Direct 交付机制，不新增非标准私有流协议。
- **A-003 PC 宽屏为基准**：本功能重构优先覆盖 PC 浏览器视口（1024px、1280px、1440px、1920px 及以上），兼顾 768px~1024px 响应式折叠，不扩展手机专用 Native 客户端或 TV 遥控器焦点协议。
- **A-004 时区一致性**：所有节目排期与时间指示线计算严格遵循家庭设置的时区基准，跨日判断与 DST 转换与服务端时钟保持一致。
- **A-005 游客与数据安全**：公开元数据接口绝不返回媒体流真实物理路径、上游凭据或个人数据，严格遵循 ADR-0010 既定安全基线。
