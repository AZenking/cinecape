## User Scenarios & Testing *(mandatory)*

### User Story 1 - 观看者在直播大厅中消费统一逻辑频道并获取级联 EPG 节目单 (Priority: P1)

用户进入直播大厅（Live TV）和节目单指南（EPG Guide）时，看到的每一个电视频道都是一个完整的、独立的“逻辑频道”（例如“CCTV-1 综合”）。用户无需关心也不可见底层存在多少个 IPTV 订阅源；系统自动聚合多个 EPG 源的数据，实时计算出当前频道的当前节目、下一节目以及播放进度。即使用户导入了 3 个不同的直播源，页面上也不会出现 3 个重复的 CCTV-1，而是呈现一个标准的 CCTV-1 频道，并显示高质量的节目单。

**Why this priority**: 这是整个平台直播与节目单体验的基石。解决用户对“页面直接使用物理源还是逻辑频道”的核心困惑，确保浏览体验整洁、专业，消除重复频道与割裂的 EPG 碎片。

**Independent Test**:
- 导入多个包含同名频道的直播源与多个 EPG 源；
- 访问直播大厅，验证同名频道自动归集为一个逻辑频道展示；
- 验证该频道展示的当前播放节目与时间进度条来自最优的 EPG 源；
- 验证即使某个低优先级的 EPG 源缺少节目单，只要有其他源具备数据，频道仍完整展示节目信息。

**Acceptance Scenarios**:
1. **Given** 平台存在两个直播源（源 A、源 B）且均包含“CCTV-1 综合”，**When** 观看者打开直播频道列表，**Then** 列表中仅显示一个“CCTV-1 综合”逻辑频道。
2. **Given** 逻辑频道“湖南卫视”关联了两个 EPG 源，主 EPG 源中该频道节目单为空，次级备用 EPG 源中包含完整节目排期，**When** 观看者查看该频道的节目指南，**Then** 界面无缝呈现次级 EPG 源的节目单，并在时钟进度条上显示当前正在播放的节目。
3. **Given** 某个逻辑频道在所有关联 EPG 源中均无节目数据，**When** 观看者查看该频道卡片，**Then** 界面优雅降级展示“暂无节目单”，不发生页面崩溃或布局错乱。

### User Story 2 - 观看者在播放器中自由切换多线路与无感故障容灾 (Priority: P2)

当用户点击某个逻辑频道进行播放时，播放器加载该频道聚合的默认最优线路进行播放。播放器控制栏清晰提供“线路选择（例如：线路 1·高清、线路 2·备用、线路 3·标清）”菜单，用户可根据当前网络质量自主切换线路。当正在播放的线路发生网络中断、流地址失效或持续卡顿时，播放器自动尝试切换至下一条备用线路继续播放，保障观看连续性。

**Why this priority**: 将多直播源从“冗余混淆的频道列表”降维转化为“单频道下的高可用冗余线路”，在保证界面清爽的同时极大增强流媒体播放的稳定性与抗故障能力。

**Independent Test**:
- 打开具有多条流线路的逻辑频道播放界面；
- 验证播放器线路菜单正确列出所有聚合线路并允许手动切换；
- 模拟首选线路流断开，验证播放器在 5 秒内自动切换至第二线路并成功恢复播放。

**Acceptance Scenarios**:
1. **Given** 逻辑频道“浙江卫视”聚合了 3 条不同直播源的播放流，**When** 用户在播放器控制栏点击“线路切换”，**Then** 界面展开线路菜单，清晰列出线路 1、线路 2、线路 3，且当前活动线路高亮显示。
2. **Given** 用户正在播放线路 1，**When** 线路 1 出现网络流中断或加载超时，**Then** 播放器自动静默尝试连接线路 2，并在画面右上角提示“已为您自动切换至备用线路”，无需用户手动干预。
3. **Given** 逻辑频道的所有线路均发生故障，**When** 自动容灾遍历所有线路皆失败，**Then** 播放器停止重试，展示清晰友好的“当前频道所有线路暂时无法连接，请稍后重试”错误提示及手动重试按钮。

### User Story 3 - 管理员在频道资产工作台管理线路聚合与灵活 EPG 跨源匹配 (Priority: P3)

管理员进入后台“直播与频道设置”时，面对的是以“逻辑频道资产”为核心的工作台（Channel Workbench）。管理员可以清晰查看系统中每个逻辑频道的名称、台标、所属分类、已汇聚的物理线路数量（如“3 条线路”），以及当前绑定的 EPG 源与节目单状态。管理员可以直接对单个频道点击“管理线路”（调整线路优先级、测试流连通性）或“匹配 EPG”，在弹出的配置面板中自由选择系统内已登记的任意 EPG 源及其候选频道进行精确绑定锁定，彻底废除旧有的“源与源 1:1 对齐”怪异模式。

**Why this priority**: 赋予管理员完全的控制力与直观的工作流。将底层复杂的物理源同步转化为直观的频道资产治理，让多源管理变得井然有序。

**Independent Test**:
- 登录主管理员账户，进入频道管理工作台；
- 查看频道列表，验证各频道准确展示“聚合线路数”与“当前 EPG 绑定源”；
- 打开 EPG 绑定弹窗，验证可在所有可用 EPG 源之间自由切换并即时检索目标频道，保存后立即生效。

**Acceptance Scenarios**:
1. **Given** 管理员进入直播与频道设置页面，**Then** 主视图呈现统一的频道资产表格，包含频道名称、Logo、分类、线路数（Badge）及 EPG 匹配状态，而非源与源关联配置。
2. **Given** 管理员点击某个频道的“绑定 EPG”，**When** 在弹窗中切换不同的 EPG 源并搜索候选节目单频道，点击确认绑定，**Then** 该频道立即被锁定至选定的 EPG 目标，并在频道列表中显示“手动锁定”标签与来源名称。
3. **Given** 管理员解除某个频道的手动 EPG 锁定，**When** 保存操作，**Then** 系统自动重新执行多 EPG 源级联智能匹配逻辑，恢复最优自动绑定。

### Edge Cases

- **同名频道不同画质或地域版本辨识**：当两个物理流同名为“CCTV-5”但一个标有“4K”，另一个标有“HD”时，系统提取清洗后的核心标识聚合为同一个逻辑频道，并将“4K”、“HD”保留为对应播放线路的元数据标签（Line Label）。
- **EPG 源整体故障或不可达**：当某个权重最高的外部 EPG 源下载超时或内容损坏时，系统自动跳过该源，无损降级至下一权重 EPG 源，不阻塞频道元数据服务与页面渲染。
- **孤立无流频道或失效线路清理**：当某个逻辑频道下的所有物理流源被管理员全部删除后，系统自动将该频道标记为“无可用线路”或移入待归档池，避免在前端直播大厅中展示不可播放的幽灵频道。
- **跨时区与夏令时节目时间对齐**：当不同的 EPG 源使用不同的时区标记（如 UTC 与 UTC+8）时，系统在入库与计算当前节目时统一标准化为 ISO-8601 UTC 时间，根据用户家庭设置的时区呈现。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统**必须**将「逻辑频道」（Logical Channel）作为面向终端观看者的唯一直播资产实体，严禁向前端页面直接暴露物理 IPTV 源。
- **FR-002**: 系统**必须**支持将多个不同直播源中属于同一电视频道的物理流，自动或受控汇聚为该逻辑频道下的播放线路（Playback Lines）。
- **FR-003**: 播放解析器在响应频道播放请求时，**必须**返回该频道所有可用的播放线路列表，并指明当前默认推荐线路。
- **FR-004**: 前端播放器**必须**提供多线路手动切换面板，并在播放失败或断流时提供按线路优先级自动重试与故障转移机制。
- **FR-005**: 系统**必须**维护全局 EPG 节目单资源池，并支持为多个 EPG 源配置全局级联优先级权重。
- **FR-006**: 系统在解析逻辑频道的节目排期时，**必须**严格遵循以下确定性级联匹配阶梯：
  1. 单频道管理员手动绑定（最高优先级，锁定不被自动覆盖）；
  2. 精确 `tvg-id` 匹配（在按权重排序的有效 EPG 源中顺序检索）；
  3. 频道标准名称与别名归一化匹配（在按权重排序的有效 EPG 源中顺序检索）；
  4. 降级兜底状态（无匹配时输出“暂无节目单”，不破坏界面完整性）。
- **FR-007**: 频道列表与电子节目指南**必须**实时计算并展示逻辑频道的当前节目标题、开始时间、结束时间及播放进度百分比。
- **FR-008**: 系统管理后台**必须**提供以逻辑频道为视角的“频道资产工作台”，支持查看频道线路数量、状态、EPG 匹配情况并进行手动干预。
- **FR-009**: 管理员在 EPG 绑定弹窗中**必须**能够自由跨越所有已启用的 EPG 源进行检索与绑定，彻底废除“直播源 1:1 绑定 EPG 源”的旧式关联设计。
- **FR-010**: 所有对逻辑频道及其线路的公开浏览与播放请求，**必须**继续严格执行家庭隔离与 `ProfilePolicy` 权限校验，未授权的受控频道不得被普通或受限档案访问播放。

### Key Entities

- **Logical Channel (逻辑频道)**:
  - 平台顶层业务资产实体。包含唯一标识、家庭归属、标准频道名称、频道号、台标、所属分类、频道分级标识及多条播放线路引用。
- **Playback Line (播放线路)**:
  - 物理流传输抽象。归属于单个逻辑频道。包含线路标识、所属物理来源、清晰度标签（如 4K、1080P、原画、备用）、流媒体格式、物理流地址（受保护不直接外露给公开浏览）、权重优先级及连通性状态。
- **EPG Schedule Pool (EPG 节目单池)**:
  - 汇聚多个外部 EPG 订阅源解析出的节目单时序数据集合。包含源标识、源全局权重、节目条目（标题、描述、开始时间、结束时间）。
- **Channel EPG Binding (频道 EPG 绑定记录)**:
  - 逻辑频道与特定 EPG 源频道的映射关系。包含绑定模式（`auto` 自动级联 / `manual` 管理员锁定）、目标 EPG 源标识、目标 EPG 频道 `tvg-id` 及最后验证时间。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 无论后台导入多少个直播订阅源，前端直播大厅中展示的逻辑频道去重率达到 100%，不再出现名称与内容相同的重复频道干扰用户。
- **SC-002**: 用户在直播大厅浏览频道列表时，具备 EPG 数据的频道在 200 毫秒内计算并渲染出精准的当前节目与进度条。
- **SC-003**: 当播放中的线路发生流中断时，播放器在 5 秒内自动切换至健康备用线路恢复播放，无需用户手动刷新或退出重进。
- **SC-004**: 管理员在频道工作台中完成单个频道的跨源 EPG 手动搜索、重绑及保存的全流程操作耗时小于 15 秒。
- **SC-005**: 废弃旧有 1:1 直播源匹配模式后，管理员对频道 EPG 匹配操作的认知混乱度与配置错误率显著降低，匹配成功率提升至 95% 以上。

## Assumptions

- **A-001**: 用户导入的 M3U 直播源通常包含标准化或半标准化的频道名称（如 "CCTV-1", "CCTV-1 综合", "CCTV-1 [1080P]"），系统可通过通用清洗算法提取核心标识进行自动汇聚。
- **A-002**: 大多数家庭网络环境具备基本的公网连通性，可以定时下载与更新主流 XMLTV 格式的 EPG 文件。
- **A-003**: 播放器组件运行于现代主流浏览器环境，具备标准 HLS/DASH 解码与流状态监听能力。
- **A-004**: 本规格专注于 PC 端与核心服务端领域模型的频道中心制演进，移动端或其他客户端将在后续阶段直接复用相同逻辑频道抽象契约。
