## Clarifications

### Session 2026-10-24

- Q: 是否将 EPG 手动匹配加入阶段 3？ → A: 维护者明确要求参考 magi，先更新规格、方案和任务清单，不写业务代码；新增逐频道候选搜索、保存锁定、解除恢复自动与失效保留，不扩展完整匹配工作台。此增补替代 2026-10-23 对逐频道绑定/人工锁定的排除，旧记录仅追溯原范围。

### Session 2026-10-23

- Q: NAS 同路径文件被替换后是否保留原白名单与人工分级？ → A: 采用 A；大小或修改时间变化时保留媒体身份，恢复未评级、移除全部档案对该媒体的允许项、保留禁止项，等待家长重新配置；大小和修改时间均未变化的替换本期无法可靠识别。
- Q: 如何精简并入 magi 的 EPG 能力？ → A: 采用来源设置、手动同步与状态、来源级精确关联及当前/下一节目展示；原范围不含请求头编辑、匹配工作台、模糊匹配、人工锁定、批量审批、定时调度和 EPG 导出（逐频道手动绑定/锁定已由 2026-10-24 增补纳入；其他排除继续有效）。
- Q: 刷新结果为空或大量频道消失时是否需要确认？ → A: 采用 A；已有非空目录时，空结果或缺失比例达到 25% 需家长确认，确认前保留旧目录，首次导入不触发。
- Q: IPTV 与独立 XMLTV 节目指南如何指定关联关系？ → A: 采用 A；每个 IPTV 来源可关联一份可选 EPG 来源，按 tvg-id 与指南频道标识精确匹配，无匹配显示“暂无节目”；参照 LibreTV 的来源级 EPG 配置方式，保留独立 EPG 来源管理。
- Q: NAS 文件改名或移动后是否自动保留原内容身份？ → A: 采用 A；按来源与相对路径识别，改名或移动视为新内容，旧内容标记不可用并保留引用，新内容不继承原权限配置。
- Q: 当前项目是否采用同来源优先按 tvg-id、缺失时按完整播放地址识别频道？ → A: 采用 A；缺少播放地址的条目非法，不使用名称兜底；频道标识冲突时拒绝刷新。

## User Scenarios & Testing

### User Story 1 - 接入并维护家庭媒体来源 (Priority: P1)

主账号添加 IPTV 播放列表、节目指南和 NAS 媒体目录，手动刷新后获得可查询目录，并能禁用来源。

**Why this priority**: 家庭需要将自己的媒体引入平台。
**Independent Test**: 使用受控播放列表、节目指南和临时媒体目录分别完成导入、重复刷新、失败刷新与禁用。

**Acceptance Scenarios**:

1. **Given** 主账号通过家长验证，**When** 添加合法来源并刷新，**Then** 显示刷新结果与新增/更新/不可用数量。
2. **Given** 同一来源与输入，**When** 重复刷新，**Then** 不产生重复媒体或播放资源，既有媒体标识不变。
3. **Given** 来源超时、无法读取或整体格式非法，**When** 刷新，**Then** 显示可重试错误，保留上次成功目录，不将失败当作空目录删除。
4. **Given** 来源被禁用，**When** 浏览目录，**Then** 仅依赖该来源的内容不可见；有其他启用来源的内容保留。

### User Story 2 - 按当前观看者浏览媒体 (Priority: P1)

观看者浏览、搜索和查看家庭允许的频道、电影及本地视频；只有当前档案允许的内容可见。

**Why this priority**: 把已建立的策略连接到真实资源。
**Independent Test**: 导入真实受控来源，用成人和儿童档案分别查看列表、搜索、详情，比较允许与禁止结果。

**Acceptance Scenarios**:

1. **Given** 有效会话与当前档案，**When** 查询列表、分类或详情，**Then** 仅返回当前家庭且策略允许的可用内容。
2. **Given** 内容被禁止，**When** 搜索、直接访问已知标识或翻页，**Then** 不能通过详情、计数、节目指南或关联项泄漏该内容。
3. **Given** 缺失/停用当前档案、无效会话或损坏策略，**When** 查询目录，**Then** 拒绝访问，不回落成人权限。
4. **Given** 首次空目录或查询无结果，**When** 页面加载，**Then** 区分无来源、无可见内容和请求失败；键盘可操作搜索与翻页。

### User Story 3 - 配置真实媒体黑白名单 (Priority: P2)

主账号通过独立的家长管理入口选择同家庭媒体，编辑媒体允许/禁止名单与儿童频道允许名单。

**Why this priority**: 完成阶段 2 延后的资源选择与归属校验。
**Independent Test**: 将超限媒体加入允许名单、再加入禁止名单，验证儿童下一次目录查询分别允许和拒绝。

**Acceptance Scenarios**:

1. **Given** 主账号通过家长验证，**When** 搜索管理候选媒体，**Then** 可选择同家庭中被当前观看策略隐藏的内容，但不能获得播放地址或文件路径。
2. **Given** 合法候选标识，**When** 保存名单，**Then** 校验全部资源归属、频道类型和版本，整体成功或整体失败。
3. **Given** 媒体在允许与禁止名单，**When** 浏览，**Then** 禁止优先；允许名单不覆盖未评级开关或儿童频道门槛。
4. **Given** 跨家庭/不存在标识或旧版本，**When** 保存，**Then** 拒绝且原策略不变；其他设备下一次访问使用最新策略。

### User Story 4 - 迁移 magi 的 EPG 设置能力 (Priority: P1)

家长在来源管理页配置独立 EPG/XMLTV 来源的名称、地址与启用状态，手动刷新节目指南，查看执行状态、最近成功时间、频道/节目数量及脱敏错误；在 IPTV 来源编辑页选择一份可选 EPG 来源，频道详情展示当前和下一节目。本期不提供单独的连通性检查操作；同步结果不等于频道流可播放。

**Why this priority**: 复用 magi 已有的来源管理体验，提供可维护的节目指南设置。
**Independent Test**: 使用受控 XMLTV 来源完成创建、编辑、家长验证、手动刷新、停用、重新启用和 IPTV 关联，核对当前/下一节目；刷新及重启后设置保留。

**Acceptance Scenarios**:

1. **Given** owner 通过家长验证，**When** 保存名称、地址和启用状态，**Then** 设置持久化；非法地址、越权或并发旧版本不得覆盖现值。
2. **Given** 已启用 EPG 来源，**When** 手动刷新，**Then** 页面显示执行中及最终成功/失败状态，成功后显示频道/节目数量和最近成功时间；同来源重复刷新提示正在执行，不启动第二次任务。
3. **Given** 来源已禁用、未成功同步或同步失败，**When** 查看设置，**Then** 显示原因与可执行修复操作；失败不能清空上次成功数据。
4. **Given** 来源地址含凭据，**When** 查看列表、错误与日志，**Then** 敏感值脱敏；编辑时未改动的地址保留，掩码不能作为新地址保存。
5. **Given** 刷新尚未完成，**When** 服务重启，**Then** 该次刷新标记为中断，保留上次成功数据，家长可以重新触发刷新。
6. **Given** IPTV 已关联 EPG，**When** 当前档案访问允许的频道详情，**Then** 按 tvg-id 精确展示当前/下一节目及起止时间；无匹配、未关联或 EPG 禁用时显示“暂无节目”。

### Edge Cases

- 成功空刷新与网络/解析失败区分；部分条目非法不清空上次成功快照，失败条目原因可查看。
- 文件重名、频道同名不代表同一内容；不同来源不按标题自动合并。
- 同来源 tvg-id 不变而播放地址变化时保留频道身份、名单和人工分级；无 tvg-id 时完整地址变化视为新频道，旧频道标记不可用且保留引用，新频道不继承旧频道的名单或人工分级。
- 来源中的条目消失时标记该来源资源不可用，不删除媒体身份或名单引用；重现后复用标识。
- 同来源同时刷新只允许一个执行，其余明确提示正在刷新；刷新期间查询继续读取上次成功快照。
- NAS 挂载断开、无权限、路径越界和指向挂载外的符号链接必须拒绝；不能删除或修改原始媒体文件。
- 频道无节目匹配、节目跨日、时区缺失或未知分级不能被解释为安全内容；节目展示带明确时区。
- 导入条目中的名称、描述、海报和地址均不可信；展示不能执行其附带内容，也不能泄漏地址内凭据。

### User Story 5 - 手动匹配频道节目指南 (Priority: P1)

家长对尚未自动匹配或匹配错误的频道，搜索本家庭 EPG 候选，选择节目指南频道并保存；手动结果优先且不被刷新覆盖，可以解除以恢复自动规则。

**Why this priority**: 来源频道 ID 不一致时仍能修正节目单，不改变观看权限。
**Independent Test**: 两个不相同频道 ID 建立手动关联，查询节目、刷新和重启后仍有效；解除后回落来源级精确匹配。

**Acceptance Scenarios**:

1. **Given** owner 通过家长验证，**When** 选择频道并按 EPG 来源、频道 ID 或名称搜索候选，**Then** 只返回本家庭已启用且成功导入的指南频道，可预览当前/下一节目，不返回流地址、路径或源凭据。
2. **Given** 手动选择合法目标，**When** 保存，**Then** 手动匹配优先并锁定；无需 IPTV 的 tvg-id 相等，也可选择不同于来源默认的同家庭 EPG。普通刷新、重启或来源默认关联改变不得覆盖它。
3. **Given** 目标消失、冲突、来源禁用或无当前节目，**When** 查看节目，**Then** 区分绑定失效和暂无节目；绑定配置保留，失效时不自动换回其他频道。原目标恢复后同 ID 自动恢复，不新建媒体身份。
4. **Given** 已有手动绑定，**When** 家长解除，**Then** 恢复 FR-007 来源级自动匹配；若仍无精确匹配则显示暂无节目。
5. **Given** 非 owner、缺失/错误密码、跨家庭目标、非频道媒体、过期编辑版本或候选所属指南刷新后已变化，**When** 查询或保存/解除，**Then** 拒绝且不部分写入、不改变内容策略。

## Requirements

### Functional Requirements

- **FR-001**: 区分 MediaItem（内容身份）、MediaSource（来源）和 PlaybackSource（可播放资源）；全部属于同一 Household，跨家庭关联拒绝。
- **FR-002**: 首批包含 IPTV 的 M3U/M3U8 播放列表、XMLTV 节目指南及 NAS 已挂载目录；支持手动新增与刷新、启用/禁用、查看刷新结果。本期不含定时刷新、云端刮削、自动跨来源内容合并及源文件删除。
- **FR-003**: 新增/修改/禁用来源、编辑内容分级与名单均只允许 owner 且重新验证主账号密码，沿用已接受的家长验证与锁定规则。未通过不得修改数据。
- **FR-004**: 同来源采用稳定条目身份，重复刷新不新增重复项；普通刷新不能重置媒体标识、名单和人工修正分级；NAS 同路径文件变化按 FR-022 处理。IPTV 频道在同来源内优先使用 tvg-id，缺失时使用完整播放地址；不使用名称兜底。缺少播放地址的条目非法；重复频道标识视为冲突并拒绝本次刷新，不覆盖已发布目录。NAS 条目按来源与相对路径识别；改名或移动视为新内容，旧条目标记不可用并保留引用，新条目不继承旧条目的名单和人工分级；本期不计算内容指纹或提供人工身份合并。
- **FR-005**: 每次刷新提供状态、完成时间和新增/更新/不可用/失败数量；新快照整体发布，失败保留上次成功数据；部分非法条目使该次刷新失败，列出错误条目以供修正后重试。对已有非空目录的 IPTV/NAS 来源，合法新快照为空或相对最近成功快照中当前可用条目的缺失比例达到 25% 时，进入待家长确认状态；未确认不发布。首次导入不触发此规则。确认须 owner 重新验证主账号密码，且只能发布所确认的快照；来源配置或已发布基线变化后须重新刷新，不能应用过期确认。EPG 刷新不以频道消失比例改变媒体可用性。
- **FR-006**: 媒体基本信息包含标题、类型、可选描述/海报、分级与可用性；缺失海报用占位。首期本地文件以文件名提供标题，支持 mp4、mkv、avi、mov、webm、m4v、ts；不据容器格式承诺可播放。
- **FR-007**: 频道可关联节目指南，展示当前/下一节目及起止时间；无匹配显示“暂无节目”，不猜测关联。每个 IPTV 来源可选择当前家庭的一份可选 EPG 来源，同一 EPG 可被多个 IPTV 来源复用；仅在所选 EPG 中按 tvg-id 与 XMLTV 频道标识精确匹配，缺失或冲突留为未匹配。自动模式不搜索其他 EPG、不按名称猜测；逐频道手动模式按 FR-023～026 优先于本条默认规则。未配置或 EPG 禁用时显示“暂无节目”，不影响频道自身可用性。
- **FR-008**: 目录提供标题搜索、类型筛选和分页，每页默认 20、最多 100 项，排序为标题及稳定标识；计数和分页均在权限过滤后产生。
- **FR-009**: 列表、详情、搜索、节目指南和关联内容均从服务端有效会话取得当前档案，并使用最新 ProfilePolicy 与真实资源事实；客户端身份、等级或可用状态不能扩大权限。跨家庭或不可见详情与不存在同形拒绝。
- **FR-010**: 浏览响应不包含播放地址、物理文件路径、来源凭据；本阶段不开放播放、原始文件下载、代理媒体流或绕过授权的静态文件入口。PlaybackSource 只供服务端后续播放解析使用。
- **FR-011**: 家长候选资源查询与观看目录分离；候选查询须 owner 加家长验证，可以查同家庭策略隐藏媒体，不受当前档案内容过滤，但同样不返回播放地址、文件路径和凭据。
- **FR-012**: 名单保存校验每一媒体归属；频道名单仅允许频道，标识去重且每名单最多 1000 项。继承阶段 2 保存版本冲突、禁止优先与未评级规则；媒体失去来源不静默删除名单引用。
- **FR-013**: 等级使用已接受的 0～18 内部年龄阈值；本期不自动映射外部评级，统一按未评级导入，owner 可验证后逐内容人工修正。EPG 节目等级不自动改变频道等级，频道白名单不承诺节目级安全。
- **FR-014**: NAS 仅扫描明确配置并可读取的挂载根目录，递归但拒绝越界路径/符号链接；仅索引，不修改原文件；媒体目录不会成为公开文件服务。
- **FR-015**: 远程来源仅允许显式配置的 HTTP/HTTPS 地址；拒绝本机服务、云元数据地址与未授权内网目标；允许家长明确批准的家庭局域网来源。解析后的目标、重定向和后续刷新均须遵守同一边界。日志、错误与界面不暴露 URL 凭据。
- **FR-016**: 禁用或刷新移除资源后，下一次目录访问使用新可用状态；存在其他启用来源时保留内容。来源暂不提供永久删除操作，避免破坏后续个人数据引用。
- **FR-017**: 内容状态、来源、节目关联和名单重启后保留；升级与回滚须在临时数据中演练，保留既有身份、策略及 PIN，明确新增目录数据的恢复方式。

- **FR-018**: 精简适配 magi 的 EPG/XMLTV 来源管理：名称、地址、启用状态、手动刷新、执行状态、最近成功时间、频道/节目数量与脱敏错误；首次刷新即完成初次导入，不设重复的“导入”和“刷新”入口，也不提供单独的连通性检查。配置变更采用版本校验，变更和刷新均受 owner 与主账号密码再次验证保护；同来源禁止并发刷新，失败/中断保留上次成功数据，重启后可查看中断状态并手动重试。
- **FR-019**: EPG 设置属于 Household，不绑定某个观看 Profile。管理操作与普通观看入口分离；普通观看者不能读取来源凭据或管理结果中的资源位置。沿用本项目局域网目标授权及远程地址校验边界，不能因参考实现而放宽。
- **FR-020**: 本期仅纳入 EPG 来源设置、手动同步与状态、来源级精确关联及节目展示。沿用 FR-007：每个 IPTV 来源选择一份可选 EPG，仅按 tvg-id 精确匹配，不按名称或模糊结果自动绑定。新增逐频道手动绑定与保存即锁定（FR-023～026）；仍不纳入请求头编辑、优先级、备选策略、完整匹配工作台、模糊自动匹配、批量审批、定时调度和 EPG 导出。设置入口并入来源管理页；IPTV 来源编辑页提供可选 EPG 选择；节目展示并入频道详情，不另建匹配工作台。
- **FR-021**: 迁移不得删除重建已建立的媒体身份，不得改变已确认的频道标识规则、名单与人工分级；参考项目的数据存储、任务执行和界面组件不自动成为本项目技术要求。

- **FR-022**: NAS 同来源、同相对路径文件的大小或修改时间变化时，保留媒体身份，但恢复未评级，移除当前 Household 全部 Profile 对该媒体的媒体允许项，保留媒体禁止项；清理允许项的策略须递增版本，避免旧表单覆盖。文件事实更新、分级重置及名单清理须同时生效，未经家长再次配置不能沿用旧允许项。此规则也适用于旧路径消失后重新出现且大小或修改时间变化的文件。本期不计算内容指纹，大小和修改时间均未变化的替换无法可靠识别；未变化文件继续保留原配置。

- **FR-023**: 频道管理提供手动节目指南匹配。候选查询、读取绑定配置、保存与解除均要求 owner 和当次主账号密码；可管理同家庭被观看策略隐藏或暂不可用的频道，但普通节目查询仍须当前 ProfilePolicy 放行。候选可跨本家庭的 EPG 来源选择，不可跨 Household。
- **FR-024**: 每频道最多一个手动绑定，目标为 EPG 来源和其 XMLTV 频道 ID；保存即锁定且优先于来源级自动精确匹配。候选只选已启用、已成功导入且非冲突的频道；无当前/下一节目并不等于目标无效。保持现有频道身份、名单和分级，手动绑定不授予观看权限。
- **FR-025**: 手动配置在 IPTV/EPG 刷新、重启、频道暂时消失及 IPTV 来源默认 EPG 改变后保留。目标消失/冲突/来源禁用时保留配置并明确 invalid 原因，禁止静默回退到自动或其他 EPG；目标同 ID 恢复则绑定重新有效。家长解除后恢复自动匹配；无手动配置时沿用 FR-007。非频道媒体不能创建绑定。
- **FR-026**: 保存/解除具有版本冲突保护，保存时重验候选最新归属、可用性与所查询的指南版本；首次配置和解除后再次配置都不能绕过并发校验。绑定修改与目录修订递增须原子完成；错误不改变配置。每频道独立保存，不引入批量审批或额外的“解锁后让刷新覆盖”状态。

### Key Entities

- **MediaItem**：家庭内稳定内容身份，类型 channel/movie/series/episode/video、标题、基础元数据与内部等级；内容是否可用取决于启用来源资源。
- **MediaSource**：家庭配置的 IPTV、EPG 或 NAS 来源及启用状态，不属于某个观看者。
- **PlaybackSource**：连接内容与来源的服务端资源位置和协议；不是可直接展示的播放许可。
- **节目条目**：来源频道标识、标题和带时区起止时间；关联频道但不自动授予内容权限。
- **刷新记录**：来源、状态、最近成功时间、数量与脱敏错误。
- **ProfilePolicy 名单**：引用稳定媒体身份；独立于来源刷新生命周期。

- **频道手动 EPG 绑定**：家庭内媒体频道、目标 EPG 来源、XMLTV 频道 ID、绑定版本；有效性由最新指南派生，配置不随暂时失效删除。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 三类受控来源各完成一次真实导入，重复刷新后媒体与资源数量不变、既有标识全部保持。
- **SC-002**: 失败/中断刷新不破坏已发布目录；来源禁用、消失与恢复用例全部符合规定且不改变源文件。
- **SC-003**: 成人/儿童、黑白名单交集、未评级、跨家庭、身份篡改和过期/撤销会话的列表/详情/节目访问矩阵全部符合预期，无被禁止内容或敏感资源位置泄漏。
- **SC-004**: 家长通过真实资源选择完成三类名单编辑；不存在/跨家庭/非频道/版本冲突保存全部拒绝且原值不变。
- **SC-005**: 在记录硬件条件的家庭部署验收环境中，含 10000 条内容的目录连续 20 次搜索/翻页，95% 在 2 秒内展示完成；刷新期间仍可浏览上次成功目录。
- **SC-006**: 重启持久化、由阶段 2 升级、回滚和备份恢复均通过；原有身份、PIN 和策略值全部保留。
- **SC-007**: 真实浏览器与真实服务完成来源导入、目录搜索/详情、档案切换及名单编辑；网络与后端证据证明权限过滤，静态检查或模拟数据界面不替代上述验收。

- **SC-009**: 同路径文件大小或修改时间变化及消失后变化重现的用例，均保留媒体身份、恢复未评级、清除全部档案的媒体允许项并保留禁止项；受影响策略版本递增，旧版本保存拒绝；未变化文件的原配置保留。

- **SC-008**: 真实服务和浏览器完成 EPG 设置保存、手动刷新成功/失败、并发刷新拒绝、禁用/重新启用、重启中断与重试，以及 IPTV 关联后的当前/下一节目展示；失败/中断均保留上次成功数据。非 owner、错误密码、跨家庭、过期版本及敏感值泄漏负向用例全部拒绝或不泄漏。

- **SC-010**: 手动搜索/预览、保存优先、刷新与重启保留、失效不回退、同 ID 恢复、解除自动匹配、并发冲突及越权负向矩阵全部通过；真实 HTTP 和浏览器分别留证，升级/回滚/恢复不破坏原目录与策略。旧 402 用例等历史证据不作为本增补通过证明。

## Assumptions

- 遵循路线图，IPTV/EPG 与 NAS 均纳入阶段 3；先统一目录，播放解析与设备协议选择留到阶段 4，观看进度等留到阶段 5。
- 首期 IPTV/EPG 通过家长指定网络地址获取；NAS 通过部署挂载读取。本地播放列表上传、目录拖拽、自动发现与外部登录认证供应商不在本期。
- 本地文件默认 video；movie/series/episode 类型可表示但不承诺本期自动识别季集关系或外部元数据。允许 owner 修正标题和类型，但已有引用的内容身份不改变，频道不能改为非频道来绕过名单类型约束。
- 对远程来源的局域网授权是特定目标授权，不是允许访问全部内网；具体配置形式在计划与 ADR 中落实。
- 本规格在完成澄清后随维护者再次调用 speckit-plan 接受；技术设计由本目录 plan/research/data-model/contracts 记录，新增架构决策在实施前完成接受。

- “迁移”暂按功能与交互迁移理解，不自动读取 magi 的运行数据库、真实源地址或凭据；实际数据搬迁需另行明确输入、映射与覆盖规则。
- 参考源码：magi 的 `apps/web/src/routes/dashboard/sources/xmltv.tsx`、`apps/web/src/features/dashboard/epg/source-form-dialog.tsx` 与 `apps/web/src/routes/dashboard/epg-matching.tsx`。本次迁移复用来源设置与同步的用户能力，不搬运其完整匹配工作台或部署架构；2026-10-24 新增单频道手动匹配，借鉴其来源+频道 ID 配对、版本与人工锁定语义。沿用 redRoad 的现有单服务与本地存储约束，不因本需求引入独立数据库服务、消息队列或工作进程；具体实现归技术计划。
- NAS 文件变化以大小或修改时间判断，不代表完整内容校验；恢复未评级后的访问继续遵循各 Profile 的 allowUnrated，因此不承诺所有档案一律不可访问。
