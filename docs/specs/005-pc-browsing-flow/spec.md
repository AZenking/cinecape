# Feature Specification: PC 公开浏览与观看操作流程全面调整

**Feature Branch**: `master`（当前分支；未配置分支创建 hook，本次不创建或切换分支）

**Created**: 2026-10-26

**Status**: Accepted（2026-10-26 维护者显式接受：指示执行 speckit-implement 进入实施，本规格与 [ADR-0010](../../adr/0010-public-browsing-playback-separation.md)、[ADR-0011](../../adr/0011-main-profile-settings-access.md)、[ADR-0012](../../adr/0012-profile-resume-fresh-storage.md) 同批由 Proposed→Accepted；实现进度与验收记录见 [tasks.md](tasks.md) 与后续 evidence.md）

**Governance**: 遵循[宪章 1.2.0](../../../.specify/memory/constitution.md)；按 Proposed → Accepted → Implementing → Verified 流转。本规格为新的目标行为，不代表既有代码或浏览器验收已完成。

**Related ADRs**: 已接受的 [ADR-0002](../../adr/0002-one-deployment-one-household.md)、[ADR-0003](../../adr/0003-constitution-alignment.md)、[ADR-0004](../../adr/0004-technology-stack.md)、[ADR-0006](../../adr/0006-profile-policy-authorization.md)、[ADR-0007](../../adr/0007-media-catalog-import.md)、[ADR-0008](../../adr/0008-manual-epg-binding.md)、[ADR-0009](../../adr/0009-playback-delivery-conversion.md)构成可复用基线。ADR-0006 的逐次主账号密码验证继续有效，设置 PIN 不替代它。[ADR-0010](../../adr/0010-public-browsing-playback-separation.md)、[ADR-0011](../../adr/0011-main-profile-settings-access.md)、[ADR-0012](../../adr/0012-profile-resume-fresh-storage.md)已于 2026-10-26 与本规格同批接受并生效，按其替代矩阵部分替代 001/003/004 相应条款（见 contracts/api.md §8 与各旧规格替代标注）。

## Clarifications

### Session 2026-10-26

- Q: 输入 PIN 解锁设置后，修改来源、Profile 或内容权限时，是否还需要再次输入账号密码？ → A: A；进入设置验证 PIN，原有敏感修改仍逐次验证账号密码，设置解锁期间也不豁免。
- Q: 首次登录且还没有任何 Profile 时，主 Profile 应怎样建立？ → A: A；首次登录后填写档案名称并设置 6 位数字 PIN，创建主 Profile，再进入档案选择；不自动创建默认档案。
- Q: 点击首页的点播观看历史时，应如何开始观看？ → A: B；进入内容详情，提供“继续观看”和“从头播放”；进度按 Profile 保存，同一 Profile 换设备也能续播。
- Q: EPG 墙应允许查看哪段日期的节目排期？ → A: A；按家庭时区展示今天及未来 6 天，共 7 天；只展示已有排期，缺失时显示“暂无节目”。
- Q: 输入 PIN 进入设置后，这次解锁应保持多久？ → A: A；固定 15 分钟，期间返回或刷新无需再输 PIN，操作不延长有效期；退出登录、切换 Profile、会话撤销或 PIN 变更时立即失效。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 游客直接浏览家庭内容 (Priority: P1)

家庭成员无需登录即可打开首页、基础点播目录、内容详情、直播及节目单，了解有哪些内容可看；只有个人数据、播放和设置要求进一步验证。

**Why this priority**: 这是此次调整区别于现有登录优先流程的基础。

**Independent Test**: 在已初始化且有已导入内容的独立测试部署中，用没有会话的浏览器逐一打开公共页面，比较完整可用内容清单，并检查直接访问与刷新。

**Acceptance Scenarios**:

1. **Given** 已初始化且存在可用内容，**When** 游客从首页导航或直接打开公共页面，**Then** 页面可浏览，不跳转登录，不要求选档，不按儿童或成人策略隐藏元数据。
2. **Given** 已登录的儿童 Profile 不可播放某影片，**When** 查看公开目录和影片详情，**Then** 元数据仍可见；点击播放另行校验，不把可浏览误判为可播放。
3. **Given** 游客尝试指定其他家庭、Profile 或猜测不可用媒体，**When** 访问公开内容，**Then** 只能读取本部署家庭的可用元数据，不得到个人数据、来源凭据、源位置或媒体流访问凭据。
4. **Given** 空目录、搜索无匹配或服务故障，**When** 浏览页面，**Then** 分别显示暂无内容、无匹配结果或可重试错误，不将故障显示成空目录；游客不会被引导直接管理来源。
5. **Given** 在目录中搜索、筛选并翻到后续页，**When** 打开详情再返回或取消登录，**Then** 恢复原搜索、筛选和页码；返回不重置为第一页。

### User Story 2 - 账号配置、登录与 Profile 选择顺畅衔接 (Priority: P1)

未初始化时弹窗配置家庭主账号，成功后使用账号登录并选择 Profile；已初始化时可继续游客浏览，也可主动登录。账号过程不夹带来源导入。

**Why this priority**: 账号与观看身份是播放和个人内容的前提。

**Independent Test**: 分别在全新部署和已初始化部署完成配置、手动登录、选档、刷新、退出及取消登录。

**Acceptance Scenarios**:

1. **Given** 未初始化，**When** 打开应用并提交合法账号配置，**Then** 仅建立家庭和账号基础，成功后显示登录，不自动登录、不要求添加来源；并发重复配置只成功一次。
2. **Given** 首次登录且尚无 Profile，**When** 用户填写档案名称并设置 6 位数字 PIN，**Then** 经当前账号密码验证后创建成人主 Profile，再进入档案选择；不自动创建默认档案，不混入账号初始化，也不开放一般设置数据。
3. **Given** 已有 Profile，**When** 新登录成功并选择或解锁 Profile，**Then** 自动回到原业务目标或首页，不停留在仅有成功通知的选档界面。
4. **Given** 有效会话且当前 Profile 仍可用，**When** 刷新页面，**Then** 恢复该身份；若 Profile 失效，清除个人区域并在需要个人身份或播放时引导重新选档，公共浏览不中断。
5. **Given** 游客打开登录或选档流程，**When** 取消，**Then** 回到原浏览页面，不自动播放、不重复弹窗；错误凭据得到统一失败提示。

### User Story 3 - 从任何页面发起同一套受控播放 (Priority: P1)

用户在首页收藏、历史、直播节目或详情中点击播放时，系统按登录、Profile、播放权限的顺序处理，并保留用户选择的内容目标。

**Why this priority**: 防止各页面形成不同的权限和登录路径。

**Independent Test**: 对可用频道和受支持的点播媒体分别验证游客点击、登录选档、拒绝、切换档案及退出，播放器能力沿用既有受控播放范围。

**Acceptance Scenarios**:

1. **Given** 游客点击一个正在播出的频道，**When** 登录和选档完成，**Then** 继续该频道的播放流程；登录前不请求或交付媒体流。
2. **Given** 已登录且选档，**When** 播放策略禁止的内容或资源已失效，**Then** 服务端拒绝，页面显示不可播放或不可用提示，不泄露策略细节或资源位置。
3. **Given** 播放准备中连续点击其他内容或重复提交，**When** 新目标生效，**Then** 仅当前意图可开始播放，旧登录回调与旧准备结果不能启动其他内容。
4. **Given** 正在播放，**When** 退出、切换 Profile 或会话被撤销，**Then** 旧播放停止或在下一次交付被拒绝，旧凭据不能转用于新身份，个人数据不串档。
5. **Given** 登录期间原目标被禁用或失去可用来源，**When** 完成选档，**Then** 重新判断目标，不尝试使用登录前取得的过期事实继续播放。

### User Story 4 - 首页展示当前 Profile 的收藏与点播历史 (Priority: P2)

游客看到公共内容入口；登录选档后，首页额外展示该 Profile 收藏的频道和点播观看历史，供用户快速返回熟悉的内容。

**Why this priority**: 为首页提供实际个人价值，并落实观看身份隔离。

**Independent Test**: 用两个 Profile 分别收藏不同频道、播放不同点播媒体，在两个设备上刷新并切换 Profile，比较首页。

**Acceptance Scenarios**:

1. **Given** 游客或已登录但未选档，**When** 打开首页，**Then** 可见公共直播摘要、所有节目单与基础点播入口，不显示任何 Profile 的收藏或历史；未选档者可主动选档。
2. **Given** 已选 Profile，**When** 在频道详情或直播卡片收藏、取消收藏并刷新，**Then** 首页显示对应结果；重复收藏或重复取消不产生重复记录或报错状态。
3. **Given** 点播真正开始播放，**When** 返回首页，**Then** 出现一条该媒体的最近观看记录；重复观看更新同一条并排到最前，单纯查看详情、解析失败或直播观看不进入点播历史。
4. **Given** Profile A 的数据请求尚未完成，**When** 切到 B 或退出，**Then** A 的内容立即从个人区清除，迟到结果不能覆盖 B 或游客页面。
5. **Given** 收藏频道或历史媒体被移除或不可用，**When** 查看个人区，**Then** 显示不可用状态且不提供有效播放；可取消失效收藏，不把无效记录当成正在直播节目。
6. **Given** 当前 Profile 在设备 A 观看点播并正常停止，**When** 在设备 B 从首页历史进入同一内容详情，**Then** 提供“继续观看”和“从头播放”；前者从最近有效保存位置播放，后者从零开始，两者都重新经过播放授权。
7. **Given** 保存位置缺失、无效或已到媒体结尾，**When** 查看详情，**Then** 仅提供从头播放，不产生越界定位；另一 Profile 不显示或使用该进度。
8. **Given** 进度保存请求乱序、重复、伪造其他档案或播放会话已失效，**When** 请求保存位置，**Then** 重复不新增历史、较旧活动不覆盖新活动，越权或失效写入被拒绝；断网退出后仍可恢复此前成功保存的位置。

### User Story 5 - 按节目浏览直播首页 (Priority: P1)

游客和已登录用户都可在直播页查看正在播出与即将开始的节目，并按频道类型发现可观看内容。

**Why this priority**: 直播是本轮明确要求的核心公共页面。

**Independent Test**: 准备多种分类频道、跨日节目、无 EPG 频道及固定时间场景，验证页面顺序和节目时间边界。

**Acceptance Scenarios**:

1. **Given** 存在节目数据，**When** 打开直播，**Then** 从上到下显示所有节目单入口、正在直播、即将播放、各类型正在直播的节目。
2. **Given** 当前时间刚好等于节目开始或结束，**When** 页面更新，**Then** 开始时节目进入正在直播，结束时退出；同一频道不同时出现两个当前节目。
3. **Given** 频道没有可用节目单或类型，**When** 查看直播，**Then** 明确显示暂无节目或其他分类，该可用频道仍能被找到和发起受控播放。
4. **Given** 点击即将播放节目，**When** 查看详情，**Then** 显示节目时间及频道，并明确播放入口播放的是该频道当前直播，不宣称可预约、回看或立即播放未来节目。

### User Story 6 - 在 EPG 墙查看全部频道排期 (Priority: P2)

用户从所有节目单进入按频道和时间组织的节目墙，切换日期、定位当前时间，并从节目了解对应频道。

**Why this priority**: 提供完整排期入口，避免逐频道查询节目。

**Independent Test**: 用 200 个频道、每频道每天 48 个节目、7 天排期的测试数据，完成日期切换、滚动、当前时间定位和节目选择。

**Acceptance Scenarios**:

1. **Given** 有节目单，**When** 进入 EPG 墙，**Then** 纵向为频道，横向为时间，节目展示名称与起止时间，有当前时间标识及明确的家庭时区。
2. **Given** 今天及未来 6 天的排期，**When** 切换日期或横向查看时间，**Then** 仅可选择该 7 天内的日期，展示窗口内已有节目；跨日节目按交叠范围展示，缺失位置显示“暂无节目”，不补造排期。家庭时区跨日后日期范围滚动，若原选日期已超出范围，则回到新的今天并提示日期已更新。
3. **Given** 浏览未来时间，**When** 选择正在直播的节目、未来节目或点击回到现在，**Then** 分别提供当前频道播放、未来节目信息和当前时间定位；未来节目不直接播放其未来内容。
4. **Given** 缩小浏览器窗口或用键盘浏览，**When** 操作频道、时间与节目块，**Then** 频道和时间上下文可辨识，焦点可见，滚动局限于节目墙，不导致整页溢出。
5. **Given** 已选日期并滚动到某频道与时间，**When** 查看节目详情后返回或取消播放登录，**Then** 保留原日期、频道与时间位置。

### User Story 7 - 主 Profile 验证后进入统一设置 (Priority: P1)

管理员从主 Profile 菜单进入设置，输入对应 PIN 后使用左侧子菜单、右侧主体管理平台。选档解锁和设置解锁彼此独立。

**Why this priority**: 公共浏览开放后，管理读取与写入仍必须保持完整权限边界。

**Independent Test**: 准备主 Profile、普通成人和儿童档案，分别尝试直接进入设置、PIN 验证、过期后访问及敏感管理操作。

**Acceptance Scenarios**:

1. **Given** 已登录并选主 Profile 且账号具有管理权限，**When** 点击设置并提交正确 PIN，**Then** 进入设置；读取任何管理模块前均已通过服务端验证。
2. **Given** 游客、未选档、普通 Profile、伪造解锁状态或仅完成选档 PIN 验证，**When** 直接请求设置内容或管理操作，**Then** 拒绝且不返回来源、设备或其他管理数据。
3. **Given** 有效设置解锁，**When** 15 分钟有效期结束，或退出、换档、会话撤销、PIN 变更、主档案变更或停用，**Then** 授权立即失效；未保存编辑不自动提交，重新验证后重新读取现值。有效期内离开后返回或刷新可在服务端核验有效后继续访问，无需再输 PIN，且不会重置到期时间。
4. **Given** 连续 5 次错误 PIN，**When** 立即重试、刷新或重启服务，**Then** 5 分钟内拒绝，即使输入正确 PIN；锁定结束后可重试。
5. **Given** 已解锁设置，**When** 修改策略、来源、档案或其他原本要求账号密码的操作，**Then** 仍要求当次账号密码；PIN 解锁不成为管理员权限或逐次密码验证的替代。
6. **Given** 忘记主 Profile PIN，**When** 已登录管理员验证当前账号密码并重设 PIN，**Then** 仅允许恢复 PIN，旧解锁立即失效；没有密码的请求不得读取设置或变更 PIN。

### User Story 8 - 在 PC 设置中完成配置闭环 (Priority: P2)

管理员在统一设置中维护账号、档案、策略、来源、节目单、设备和通用配置，操作结果能持久保存，并能返回公共观看页面。

**Why this priority**: 全面调整须整合已有业务能力，不能只替换导航或创建空白设置页。

**Independent Test**: 在已解锁设置中逐项完成代表性读写，刷新并重启服务核对；同时在不同 PC 窗口宽度下完成键盘操作。

**Acceptance Scenarios**:

1. **Given** 已解锁设置，**When** 选择七个子菜单，**Then** 右侧展示对应模块，地址与选中项一致，返回观看页面不会要求重新登录。
2. **Given** 添加媒体来源并通过所需密码验证，**When** 保存配置，**Then** 明确给出导入下一步；刷新成功或确认发布后有查看内容入口，失败保留上次成功目录并可重试。
3. **Given** 编辑数据尚未保存、保存遇到版本冲突或授权过期，**When** 离开或提交，**Then** 明确提示未保存、重新读取或重新验证，不以旧版本静默覆盖现值。
4. **Given** 1024、1280、1440、1920 和 2560 像素宽的 PC 窗口，**When** 完成导航、弹窗、节目浏览和设置编辑，**Then** 无操作遮挡、文本重叠或整页横向溢出；弹窗内容可在其内部滚动。
5. **Given** 主账号更改密码，**When** 更改成功，**Then** 旧会话与设置解锁失效，用户以新密码重新登录，个人收藏与历史仍保留。

### Edge Cases

- 初始化状态检查失败时显示重试，不误判为未初始化；重复提交与并发配置不建立多个家庭或账号，失败不留下半配置状态。
- 新登录无档案与有效会话当前档案失效须区分；不能为了播放而静默选成人档案或给予管理权限。
- 主 Profile 必须唯一且可用；停用或替换之前须指定另一个受 PIN 保护的成人主档案，最后一个可用 Profile 不可停用。
- 登录、选档、PIN 与播放准备中取消或换目标后，旧成功回调不能在后台起播或重新打开已取消的设置。
- 无有效会话、无 Profile 或策略损坏不影响公共浏览；播放与个人数据请求仍拒绝或提示修复，不回落宽松播放权限。
- 跨家庭标识、伪造 Profile、过期解锁、来源凭据出现在输入中时，不能扩大公开查询、设置访问或个人数据范围。
- EPG 时区不同、跨午夜、节目间空档、重叠节目、刷新中换日、频道超过一屏、节目名称过长时仍保持频道和时间语境；重叠节目只选一个当前节目并保持稳定结果。
- EPG 同步失败与成功但无节目须区分；频道可用性不由 EPG 是否存在决定。
- 节目标题、简介和来源导入文本按不可信内容展示，不能执行脚本或将内含源地址作为可点击的播放入口。
- 多设备同时播放同一媒体，历史按最后有效观看活动排序，重试不重复新增；迟到旧活动不得覆盖较新的记录。
- 个人区加载失败不阻塞公共首页；退出后浏览器后退和迟到响应不能重新显示原 Profile 数据。
- 收藏后节目来源停用、历史媒体失效、PIN 在另一设备变更、设置页重载时都重新检查当前状态。
- 200% 浏览器缩放、768 像素窄窗口和 600 像素高度下采取收拢导航或局部滚动，不要求专门手机界面；节目墙的横向滚动不扩散到页面外。
- 不兼容历史数据不等于自动清库、删除源媒体文件或移除本地备份；本次规格准备不执行任何数据变更。

### Key Entities *(include if feature involves data)*

- **Household**: 本部署唯一家庭资源边界，拥有公开可浏览的可用媒体、来源、节目单与家庭时区。
- **Account / DeviceSession**: 认证与管理员权限、设备有效会话；浏览不依赖它们，播放、个人内容与设置依赖它们。
- **Profile / 主 Profile**: 当前观看者与个人数据归属；主 Profile 是唯一可用成人档案中的指定设置 PIN 目标，管理权限仍来自 Account。
- **Settings Access Grant**: 独立于选档的设置访问授予，关联会话、目标主档案、用途和到期时间，可撤销且有限期。
- **Media / Channel**: 可用内容与频道的公开展示信息，不包含源位置或播放凭据；频道可有主分组。
- **Programme / Guide Window**: 频道节目、开始与结束时间、标题、简介及可浏览时间范围，不表示具备回看或未来播放能力。
- **Channel Favorite**: 家庭与 Profile 下唯一频道收藏关系及收藏时间，支持幂等添加和移除。
- **Viewing History / Resume Progress**: 家庭与 Profile 下按点播媒体合并的最近观看记录，包含最近有效观看时间及位置，供同 Profile 跨设备选择继续观看或从头播放；与设备故障记录及临时播放会话分离，进度写入须验证播放身份并拒绝过时覆盖。
- **Playback Intent / Session**: 用户当前播放目标及授权后的受控播放生命周期；登录或选档继续目标，不继承未验证的客户端身份声明。

- **SC-006**: 在 200 频道、每频道每天 48 节目、7 天数据及固定局域网测试环境中，直播与 EPG 首个可操作视图在 3 秒内出现，日期切换或回到现在在 2 秒内反馈，独立执行 20 次至少 19 次达标；测试报告记录客户端、服务端硬件与数据规模，不能用空数据结果替代。对应 FR-025～027。
- **SC-007**: 游客、普通档案、仅选档解锁、伪造凭据、过期及撤销状态均无法读取管理内容或提交管理修改；相关负向用例通过率 100%，设置解锁不替代敏感操作当次密码验证。对应 FR-028～033、FR-040～041。
- **SC-008**: 七个设置子模块均完成至少一项代表性操作及刷新、重启核对；配置失败、版本冲突、未保存离开和来源导入下一步提示均有可复现验收结果，不存在空菜单。对应 FR-034～041。
- **SC-009**: 在指定 PC 尺寸、窄窗口、200% 缩放以及当前稳定版 Chrome、Edge、Firefox、Safari 中完成浏览、登录、选档、设置及节目单主操作；关键操作遮挡和非预期整页横向溢出为 0，键盘完成全部主流程且无焦点陷阱。对应 FR-042～045。
- **SC-010**: 新部署在无历史业务数据的独立环境中完成账号→档案→导入→公开浏览→收藏→播放→历史→设置的完整闭环；新版本恢复路径在独立环境验证成功，源媒体和备份被误删次数为 0，不要求旧版库或旧链接可用。对应 FR-047～048。

## Assumptions

- **A-001 范围**：本轮为 PC 浏览器的前后端整体调整。响应式覆盖 PC 大小窗口、缩放和窄窗口降级，不扩展手机专版、TV 遥控器、原生客户端、点播独立产品设计或新转码能力。
- **A-002 数据兼容**：用户明确不要求历史数据兼容，允许采用全新业务库及破坏旧契约的新流程，不做旧数据迁移、旧路由兼容或旧行为开关。本次没有实际清库授权动作；部署维护过程须显式选择目标并说明数据影响，新版本自身的数据一致性、备份与恢复仍需满足宪章。
- **A-003 主档案建立与恢复**：首个主 Profile 的建立方式已于 2026-10-26 澄清确认：首次登录后由用户填写名称并设置 6 位数字 PIN，建立成人主 Profile 后再进入档案选择，不自动创建默认档案。已有有效会话可恢复当前档案，新登录仍显式选档；普通 Profile 可切换到主 Profile，但不可直接访问设置。会话恢复等未单独确认的部分仍为建议默认值。
- **A-004 设置规则与剩余默认值**：设置解锁自验证成功起固定 15 分钟、期间返回或刷新可继续使用且不延长有效期，以及敏感修改逐次账号密码验证，均已于 2026-10-26 澄清确认。退出、换档、会话撤销或 PIN 变更立即失效；全部失效条件见 FR-031。首建或找回 PIN 用账号密码验证的受限流程，不先开放通用设置。错误 PIN 连续 5 次锁 5 分钟等未单独确认默认值仍随规格接受一并审阅，见 FR-032～033。
- **A-005 首页默认方案**：公共区先提供直播摘要、节目单与基础点播入口；登录后个人区顺序为收藏频道、点播观看历史。暂不增加推荐算法、运营位或自动轮播。个人区每次先显示最近 20 项，支持继续查看，顺序按 FR-017～018，记录保留至对应档案移除或显式维护重置。
- **A-006 历史与续播范围**：2026-10-26 已确认从首页历史进入详情后提供继续观看和从头播放，同 Profile 支持跨设备续播，不自动起播。本轮不要求手动删除历史、观看完成状态标记或多设备同时播放的位置合并；同一媒体采用较新播放意图实际起播后持有的写入权位置，旧意图的迟到活动不得覆盖；该并发取舍的具体代次协议见本功能data-model.md。进度缺失、越界或已到结尾仅从头播放；正常播放每 10 秒保存、异常中断最多丢失 15 秒的指标是待规格接受的建议默认值。
- **A-007 直播默认方案**：正在直播与即将播放分别按当前节目结束时间、下一节目开始时间排序，同时间按频道名称和稳定标识排序；分类按来源主分组，缺失归其他。各区先显示 20 项并可继续查看，不限于首屏少量频道。重叠节目选开始时间最近者，同起点按稳定标识确定，不增加模糊分类。
- **A-008 EPG 范围与默认视图**：2026-10-26 已确认按家庭时区浏览今天及未来 6 天、共 7 天已有排期，缺失显示“暂无节目”，日期范围随跨日滚动。默认时间窗口为现在前 30 分钟起的 6 小时，裁剪在可浏览日期范围内；按日期可浏览该日全部时段。频道按名称及稳定标识排序，无节目不隐藏频道，分批浏览必须可遍历全部频道。不做录制、预约、回看、自动补齐外部排期。时间窗口、排序等未单独确认部分仍为建议默认值。
- **A-009 依赖与治理**：依赖已导入的来源、可信家庭时区、现有账号认证、Profile 策略和受控播放能力；外部节目数据缺失不算播放故障。后续计划必须新增公共浏览与设置访问的 ADR，同步领域模型及受影响规格的显式替代关系，不把历史 Verified 记录改成新流程验收证据。
- **A-010 验收环境**：测试基于局域网、受控内容与节目夹具，使用验收时当前稳定版的四种 PC 浏览器，并记录版本、硬件和时间。当前未做性能实测或浏览器验证，以上指标是目标而非结果。
- **A-011 用户指定技术约束**：组件库与工程边界记录在同目录的 [delivery-constraints.md](delivery-constraints.md)，供计划阶段落实；不将具体组件写法作为业务成功标准。此前 16～22 人日仅为粗估，新增明确范围与任务拆分后须复核，不作为固定工期。
