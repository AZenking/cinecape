# 005 交付约束与计划输入

日期：2026-10-26

状态：Proposed，随 [spec.md](spec.md) 审阅。此文件保留用户指定的技术与交付约束，供后续计划阶段落实，不是 plan、tasks、接口契约或实现证据。

## 1. 需求来源与优先级

- 用户要求基于 [流程讨论记录](../../frontend-operation-flow-discussion.md)全面调整，修改彻底，不必兼容历史数据。
- 本轮仅做 PC 浏览器端；最新追加响应式要求，解释为大小 PC 窗口、窄窗口及缩放的可用性，不自动扩展到手机专版或 TV。
- 用户指定使用 [heroui-react 技能](/Users/charles/.agents/skills/heroui-react/SKILL.md)，即 HeroUI v3。
- 业务行为及验收以本功能规格为提案；历史讨论中的候选项已通过 spec.md Assumptions 明确为建议默认值，并非既往用户逐项确认。
- 旧规格、领域模型与 ADR 中的登录浏览、按策略隐藏元数据等行为不能直接与本规格并行作为两个默认流程。实施前应明确新行为与旧文档的替代范围。

## 2. HeroUI v3 与样式边界

- 继续 React + Vite，页面通用交互使用 HeroUI v3 与 Tailwind CSS v4，遵循已接受的 ADR-0004，不引入另一套通用组件库。
- 在编写或修改具体组件前，必须按 heroui-react 技能获取并阅读当时的官方 v3 组件文档，不能凭 v2 经验套用。当前仅准备规格，未实现组件，未完成组件文档核验。
- 使用 v3 复合组件结构及对应交互约定，通用按钮采用 `onPress`；不引入 v2 的 `HeroUIProvider`、`@heroui/theme` 或其安装模式。
- Tailwind 样式先于 HeroUI 样式导入；主题采用统一语义 token、CSS 变量与 oklch，避免每个页面自行维护颜色和焦点规则。
- 初始化、登录、选档、PIN 验证、表单、菜单、错误与加载态使用同一套基础交互；媒体卡、播放器和 EPG 墙允许组合自建，但使用同一 token 与可访问性规则。
- 默认延续当前暗色媒体界面，不在本轮增加主题编辑器；不能把管理设置页布局直接套到所有观看页。

## 3. PC 响应式与可访问性

- 主要验收宽度：1024、1280、1440、1920、2560 CSS 像素；高度覆盖 768 和 1080 CSS 像素。
- 额外降级检查：768 CSS 像素窄窗口、600 CSS 像素高度、200% 浏览器缩放，分别与组合检查关键流程。不是手机专版验收。
- 公共导航、用户/Profile 菜单、媒体卡布局与个人内容区域随宽度重排，不以写死屏宽的方式实现 PC 页。
- 设置在宽窗口采用左侧菜单与右侧主体，窄窗口可收拢子菜单，但当前模块与返回路径须保持明确。
- 弹窗限制在可视窗口内并允许内部滚动；EPG 使用局部二维滚动，频道与时间语境在滚动时仍可识别，不造成整页横向溢出。
- 覆盖鼠标与键盘：焦点顺序与可见性、弹层焦点进入和恢复、非颜色唯一提示、错误关联与加载状态。
- 浏览器矩阵采用验收时稳定版 Chrome、Edge、Firefox、Safari，并记录版本；不预先声称已兼容。播放器沿用原生 HLS / hls.js 的既有能力与限制，不借 UI 调整扩大编解码承诺。

## 4. 前后端调整边界

- 前端拆分公共观看布局、设置布局及登录、选档、播放意图协调；按业务模块收拢页面与数据访问，不只替换文字导航。
- 后端拆分公共元数据、Profile 私有数据、受控播放与设置授权。不能仅移除前端守卫或将全部旧管理接口匿名开放。
- 当前 Profile 的收藏与历史须持久化，身份由服务端验证；缓存及在途请求按家庭和 Profile 隔离，旧设备管理播放记录不是首页个人历史的替代。
- 直播与 EPG 需有批量、窗口化查询能力；节目墙不能依赖打开每个频道详情取得排期。
- 七个设置模块包括现有功能整合和规格明确的新业务，例如账号密码修改、通用配置维护；不能把缺失的服务端能力掩盖为无效按钮。
- 复用可信的认证、策略判定、媒体导入、EPG 匹配和受控播放内核；不要求为了“彻底”重写已正确实现的底层能力。
- OpenAPI、共享类型、相关规格与最终运行行为需同步，所有变更必须由负向契约、运行时与 PC 浏览器证据共同验证。

## 5. 无历史兼容的含义

- 用户明确免除旧业务数据保留与迁移要求；允许为新流程重建业务存储，不做旧字段读取兜底、旧路由别名、双版本契约或长期兼容开关。
- 不把讨论中的“逐步目录整理”理解为最终交付可以永久保留两套入口；最终只有统一的新默认流程。
- 不兼容历史数据不等于必须重写认证/播放内核，也不等于本次规格命令执行清库。当前不删除任何用户库、备份、文件或源媒体。
- 技术计划须区分旧版本不支持升级与新版本内部的数据一致性、幂等、备份和恢复要求。显式维护重置必须标识目标与影响，禁止自动静默清空；原始媒体和独立备份不能随业务库重建删除。
- 宪章1.2.0已直接限定本轮005/代际2的旧数据兼容例外，新版本自身仍要求迁移一致性及经验证的恢复/回滚路径。后续ADR仅记录交付方案，不能自行创造或扩大豁免范围，保留新版本自身的 up/down 或等效恢复演练，不声称已满足旧库无损升级。

## 6. 计划前的治理工作

1. 新增公共浏览与播放分离 ADR，明确其对规格 003 浏览授权和 004 详情可见性要求的替代范围，播放安全边界继续有效。
2. 新增主 Profile 与设置访问 ADR，明确本规格的 PIN 首建、恢复、15 分钟解锁、会话绑定及失效规则；保留 ADR-0006 的敏感管理操作逐次账号密码验证。
3. 对无历史兼容的重建交付记录决策、数据影响和恢复方案，不能静默改变原迁移承诺或删除历史 ADR。
4. 同步领域模型，区分 Account 管理角色、主 Profile 标识、个人收藏/历史与设置授予。
5. 计划中细化路由、实体、契约、响应式布局与测试数据，再生成任务；不得以本次规格质量清单通过作为实现授权或运行验收。
