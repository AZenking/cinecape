# PC 首页、直播与 EPG 页面设计方案

日期：2026-10-26  
状态：设计建议，待评审；未实施、未安装依赖、未进行运行验证。

## 1. 依据与边界

依据 [前端整体操作流程讨论记录](./frontend-operation-flow-discussion.md)。原记录的已确认项优先；本文的尺寸、排序、时间范围、点击行为均是本次建议，不自动升级为已确认需求，也不替代现有规格与 ADR。

范围为 PC 浏览器的首页、直播、EPG。保留顶部「首页／点播／直播」，点播页面不展开。游客可浏览全部内容；播放必须登录、选择 Profile 并由服务端授权。收藏与点播观看历史按 Profile 隔离。账号初始化只配置账号，不夹带来源导入。

## 2. 公共视觉与布局

### 2.1 方向：家庭节目台

让用户快速回答「现在看什么」「常看的频道在哪」「接下来播什么」。以节目时间与频道身份为重点，不放占满首屏的自动轮播广告或自动播放背景。

建议采用深蓝灰底色与低饱和青色交互色；红色仅强调正在直播和当前时间线。首页、直播卡片上的节目时间条与 EPG 使用相同表达，这是三页的共同视觉特征。

| 用途 | 建议值 |
| --- | --- |
| 页面底色 | `#101820` |
| 卡片 / 抽屉 | `#1A2632` |
| 悬停 / 选中底色 | `#263747` |
| 正文 | `#F2F5F7` |
| 次级文字 | `#B2BFCC` |
| 主操作 / 焦点 | `#63C7C0` |
| 直播 / 当前时间 | `#F17878`，同时配文字或线条形态 |

中文正文用系统无衬线字体（优先 PingFang SC / Microsoft YaHei）；标题同字族加粗。频道编号、时间用等宽数字，避免时间刷新时跳动。页面标题 28px、区块标题 20px、正文 16px、元信息 14px。颜色需在后续原型中校验实际对比度。

### 2.2 公共框架

- 顶部固定导航 64px：品牌返回首页；左侧首页／点播／直播；右侧登录与 Profile。
- 页面基准 1440×900，内容最大宽度 1440px；两侧留白 40px，1280px 以下收至 24px。
- 首页与直播使用页面滚动；EPG 使用一块有界网格，网格内横向看时间、纵向看频道，避免两套纵向滚动同时争夺鼠标。
- 1440px 首页卡片通常一行 4 张，1280px 一行 3 张；更窄 PC 窗口降为 2 张。本轮不增加手机或 TV 交互设计。
- 卡片圆角 10px、区块间距 32px、卡片间距 16px；动效仅用于悬停、抽屉与状态反馈，尊重减少动态效果偏好。

### 2.3 登录和 Profile 状态

| 状态 | 顶部右侧 | 页面内容 |
| --- | --- | --- |
| 游客 | 「登录」 | 公共内容；无个人收藏与历史 |
| 已登录，未选档 | 账号名＋「选择 Profile」 | 公共内容；不预先展示任何档案数据 |
| 已登录，已选档 | 账号名＋头像＋Profile 名 | 公共内容和当前档案的个人模块 |

点击播放建议使用登录弹窗 → 选档弹窗 → 服务端授权 → 播放。保留原页面、滚动位置与内容目标；用户取消后仍留在原页面。选档完成后重新解析内容状态：直播继续该频道当前直播，不尝试重播登录前已结束的节目。

Profile 切换时立即移除旧个人内容并加载新数据；旧请求不能回填。播放正在进行时切换 Profile 必须结束旧播放授权再按新 Profile 重新发起，不能仅替换头像。具体会话恢复规则仍沿用原文待明确项。

主 Profile 菜单可展示设置入口，PIN 验证后进入设置；主 Profile 定义、PIN 归属与有效期仍待明确。本文不补造这些权限规则。

## 3. 首页 `/`

### 3.1 页面结构

```text
┌ redRoad    首页  点播  直播                 账号 / Profile ┐
│ 首页                                         查看直播 → │
│ 收藏频道                                      查看全部  │
│ [频道 / 当前节目 / 时间进度 / 观看] × 4                  │
│ 点播观看历史                                  查看全部  │
│ [封面 / 标题 / 最近观看时间] × 4                         │
│ 此刻直播                                      所有节目单│
│ [当前节目 / 频道 / 起止时间 / 观看] × 4                   │
└────────────────────────────────────────────────────────┘
```

已选 Profile 顺序：收藏频道 → 点播观看历史 → 此刻直播。前两项来自已确认需求；「此刻直播」是建议新增的公共模块，游客直接以此作为首页主体。游客上方可放一句轻提示「登录后查看收藏频道和观看历史」及登录按钮，不用大面积空白个人区占据首屏。

本版不增加推荐算法、热门排行、最新入库或大幅海报轮播，避免在公共模块尚未确认时扩大范围。

### 3.2 收藏频道

- 卡片以频道 Logo、频道名、当前节目名为主；显示起止时间和节目进度；次行可显示下一节目。
- 频道封面缺失时使用频道标识底板，不依赖每个 EPG 节目有宣传图。
- 主按钮「观看直播」走统一播放流程；卡片标题区进入该频道在 EPG 中的位置；收藏星标独立操作，不触发播放。
- 默认按收藏建立顺序展示，第一屏最多 4 张；「查看全部」进入直播页的收藏频道筛选，避免本轮再增加独立页面。
- 无收藏：「还没有收藏频道」＋「去直播页看看」；收藏读取失败只替换本区块，保留其他内容。

### 3.3 点播观看历史

- 使用 16:9 封面、媒体标题、最近观看时间；按最近观看倒序，同一媒体合并展示，首行最多 4 张。
- 点击卡片进入已有内容详情；若提供独立播放按钮，默认「播放」，不承诺从上次位置续播。
- 本轮仅建议最近观看列表。播放位置进度、跨设备续播、完成标识、删除记录须另行确认；未确认前标题使用「点播观看历史」，不用「继续观看」。
- 「查看全部」在首页展开分批加载的历史列表，收起后保留原位置；不依赖尚未设计的点播页。
- 无记录：「观看点播内容后，会在这里留下记录」；内容已移除时显示不可用状态，不能保留失效播放入口。

### 3.4 此刻直播

展示最多 4 个当前节目，按频道的稳定顺序选取，不使用虚构热度。点击「查看直播」进入直播首页；「所有节目单」进入 EPG 当前时间。无 EPG 的频道也应有「暂无节目单」卡片，并允许按频道发起直播授权。

## 4. 直播 `/live`

### 4.1 页面结构

```text
┌ redRoad    首页  点播  直播                 账号 / Profile ┐
│ 直播                                    [所有节目单 →] │
│ [搜索频道或节目…]       [全部频道 ▼]  [全部 / 收藏频道] │
│ 正在直播                                                │
│ [节目卡片] [节目卡片] [节目卡片] [节目卡片]              │
│ 即将播放                                 未来 2 小时    │
│ [20:00 节目] [20:10 节目] [20:30 节目]                  │
│ 按类型看直播                                            │
│ 新闻      [当前节目] [当前节目] [当前节目]               │
│ 体育      [当前节目] [当前节目] [当前节目]               │
│ …                                                       │
└────────────────────────────────────────────────────────┘
```

「所有节目单」始终位于直播页最上方，正在直播 → 即将播放 → 按类型的顺序不变。

### 4.2 工具与筛选

- 搜索作用于频道名及已加载 / 服务端可查询范围内的节目名，标注范围为「当前及未来 2 小时」，不暗示搜索完整历史排期。
- 分类筛选三块内容同步生效；展示匹配数量与「清除筛选」。类别来自可用数据，缺失归「其他」，不凭节目名猜分类。
- 游客点「收藏频道」时提示登录；取消后仍保留原筛选。已选档无收藏时给出空状态。
- 分类和搜索保存在 URL；离开到 EPG 或播放器再返回时恢复筛选、加载批次与滚动位置。

### 4.3 正在直播

节目卡片为 16:9 图区＋信息区，图可降级为频道 Logo 底板。信息包括「直播中」、节目名、频道名、起止时间、进度、下一节目。首次最多 8 张，使用「加载更多」控制密度。

卡片主体打开节目详情抽屉，明确的「观看直播」按钮才播放。收藏星标提示「收藏频道」，不会被误解为收藏节目。频道不可用时保留卡片及原因，禁用观看；无 EPG 时展示频道名和「暂无节目单」，不伪造节目进度。

### 4.4 即将播放

默认未来 2 小时内、每频道最近一个尚未开始的节目，按开播时间升序，同时间按频道顺序。首次最多 8 张，可加载更多。

卡片突出开播时间和频道。点击打开详情，按钮为「查看节目单」；可另给明确的「观看该频道直播」，但不得将其表述为播放未来节目。不增加预约、推送或录制功能。

### 4.5 按类型看直播

各分类一行，首批最多 4 张；「更多」应用该分类并回到正在直播区。与上方出现同一频道是有意的不同浏览入口，不复制个人收藏状态。无节目数据但频道有分类时仍可列入对应组。

### 4.6 节目详情抽屉

建议从右侧打开、宽 400px；展示频道、标题、时间、时长、简介和状态。保留页面底下的浏览上下文；点击遮罩或 Escape 关闭，焦点返回触发卡片。

| 节目状态 | 主操作 |
| --- | --- |
| 正在播出 | 观看直播 |
| 尚未开始 | 在节目单中查看；可选独立「观看该频道直播」 |
| 已结束 | 仅展示信息；本轮不提供回看 |
| 无节目数据 | 展示频道信息；频道可用时可观看直播 |

抽屉打开期间节目跨越起止时间时刷新状态；播放前以服务端重新检查为准。

## 5. EPG `/live/guide`

### 5.1 页面结构与密度

```text
┌ redRoad    首页  点播  直播                 账号 / Profile ┐
│ ← 直播    所有节目单                                    │
│ [日期 ▼] [前一天] [后一天]   [回到现在]   时区 Asia/Shanghai│
│ [搜索频道…]     [分类 ▼] [全部 / 收藏频道]                │
├──────────────┬ 19:00 ─── 19:30 ─── 20:00 ─── 20:30 ───┤
│ 频道 Logo 名 │ [节目 A────────] [节目 B───────────────] │
│ 频道 Logo 名 │ [节目 C──] [节目 D────────] [节目 E───] │
│ 频道 Logo 名 │ [暂无节目单───────────────────────────] │
│ …            │                  │当前时间               │
└──────────────┴──────────────────────────────────────────┘
                                点击节目 → 右侧详情抽屉
```

- 左侧频道列固定 184px；时间轴固定高 48px；频道行高建议 76px。
- 初始可视时间约 3 小时，每 30 分钟一个主刻度；在窄 PC 窗口减少可视时长，避免将文字压到不可读。
- 网格占剩余视口高度，建议最小 420px；横纵滚动限定在网格。固定频道列和时间轴同步对齐。
- 当前时间线贯穿网格，顶部显示 HH:mm；与选中节目用不同样式，不能只靠颜色识别。

### 5.2 日期与定位

- 首次进入定位到「现在前 30 分钟」，让用户同时看到当前节目起点与后续排期。
- 单次按选中日期加载一个日历日，并包含与该日边界相交的节目；可视窗口只显示其中一部分，不将全量多日数据一次送入组件。
- 日期选择器只开放后端实际覆盖的日期；无未来数据时明确「该日期暂无节目单」，不承诺固定 7 天。
- 「回到现在」切回今天并定位当前时间，保留频道筛选；用户手动浏览后不被自动拉回。
- 页面展示部署家庭的 IANA 时区，时间戳在接口使用带偏移 / UTC 的绝对时刻。跨午夜节目显示完整起止日期；夏令时日不能硬编码为 24 小时。
- 从频道卡片进入时，将该频道滚入可视区并短暂突出；筛选排除目标频道时先提示并提供清除筛选。

### 5.3 节目块与交互

- 节目块宽度按真实时长；标题单行省略、次行时间。短节目不人为扩大覆盖相邻时段，可通过点击详情查看完整信息。
- 当前节目显示直播状态；过去节目降低视觉强调但保持文字可读；未来节目正常显示。
- 单击、Enter 或 Space 打开同一节目详情抽屉；不默认直接播放。频道行内独立观看按钮播放当前频道。
- 横向滚动用底部滚动条或 Shift＋滚轮；增加「前移 / 后移 1 小时」按钮，不能要求用户必须有触控板。
- 初版不增加节目拖拽、改时长、录制、预约、回看或缩放控件。
- 返回直播与重进 EPG 时保留日期、筛选、频道位置和水平位置；若原日期已不在数据覆盖范围，提示并回到今天。

### 5.4 空洞、错误和刷新

| 情况 | 展示与处理 |
| --- | --- |
| 整个频道无排期 | 保留频道行，「暂无节目单」；频道可用仍可观看 |
| 节目间隙 | 显示中性空白时段 / 暂无信息，不把相邻节目拉长填满 |
| 单日无数据 | 保留工具栏和频道上下文，提供其他可用日期入口 |
| 首次请求失败 | 错误提示与重试，避免无限骨架屏 |
| 已有数据后刷新失败 | 保留已获取数据并提示「更新失败」，标记数据更新时间 |
| 重复 / 重叠排期 | 按后端规范化结果展示；异常不得在前端静默改写节目时间 |
| 日期 / 筛选切换中 | 保持框架，网格加载；废弃旧请求，不能闪回上一日期 |

当前时间标记建议每分钟更新；节目元数据以服务端同步结果为准，可见页面每 5 分钟重取当前窗口作为初始建议。浏览过去日期不持续轮询；页面重新可见时校正时间并刷新今天数据。刷新不重置用户位置或关闭详情。

### 5.5 键盘和无障碍

工具栏、频道观看按钮、收藏按钮和节目块均须可键盘操作。节目块可读名称包括频道、标题、起止时间和状态。虚拟化网格不能把上千节目全部放进 Tab 顺序；建议网格单入口，方向键在可见 / 相邻节目间移动并滚入视图，Escape 退出抽屉并恢复焦点。该能力是验收要求，不能因引入 Planby 就假定已满足；若组件实现成本过高，需提供同数据的频道节目列表视图作为替代入口。

## 6. Planby 适配评估

### 6.1 结论

**适合作为 EPG 网格的优先候选，暂不作为已确定依赖。** 它的频道与节目时间区间模型贴合本方案；首页、直播卡片、详情抽屉、登录和播放授权仍由项目实现。

官网展示虚拟视图及样式定制能力，公开 API 采用 `useEpg`、`Epg`、`Layout` 等入口。[官网](https://planby.app/) / [公开仓库](https://github.com/karolkozer/planby)。这些是组件能力说明，不是本项目性能测试结果。

### 6.2 技术与功能匹配

2026-10-26 直接读取 [npm latest 元数据](https://registry.npmjs.org/planby/latest)：`planby` 为 2.1.0，peer dependency 为 `react >=19`。本项目 `apps/web/package.json` 为 React 19、Vite 7、TypeScript 5.8、HeroUI 与 Tailwind 4，声明层面匹配；未验证构建、StrictMode、运行及样式隔离。

| 需要的能力 | 评估 | 后续验证 / 项目责任 |
| --- | --- | --- |
| 频道行、时间轴、节目块 | 核心模型直接匹配 | 确认固定列 / 轴及实际尺寸行为 |
| 大量排期渲染 | 有虚拟视图，值得采用 | 用真实规模测量，不采信官网帧率承诺作为验收 |
| 主题与节目样式 | 有定制入口 | 校验选定版本基础 / PRO 边界 |
| 日期切换、回到现在 | 可围绕时间视图设计 | 核实所需 API 是否属于可用版本 |
| 跨日、时区、夏令时 | 不能只凭营销说明确认 | 必须使用边界数据验证；部分高级能力可能需 PRO |
| 频道搜索、分类、收藏 | 项目负责 | 过滤输入数据并保持定位状态 |
| 无节目时段、异常排期 | 项目负责数据规范化 | 验证组件对空洞、重叠、极短节目的显示 |
| 登录、Profile、播放权限 | 不属于 Planby | 走项目统一入口与服务端授权 |
| 键盘、读屏和虚拟焦点 | 尚未确认达标 | 专项验证，必要时提供列表替代 |

包还会带入 Emotion、date-fns 和 use-debounce；可与 Tailwind / HeroUI 并存，但要核对打包体积、日期依赖重复、主题覆盖及 CSP 行为，不能把它视为零成本纯样式组件。

### 6.4 推荐接入边界（仅设计）

```text
公共节目单接口 → 项目节目单数据模型 → Planby 适配层 → EPG 网格
                                           ↓ 选择节目
                                  项目节目详情抽屉
                                           ↓ 观看直播
                                  统一登录 / 选档 / 播放入口
```

内部模型保留稳定 `channelId`、`programId`、`startAt`、`endAt`、标题、简介、频道标识和展示时区；适配到 Planby 所需的频道标识及 `since` / `till` 等字段。跨日节目不按日期生成新身份。接口不能返回源地址、文件路径或播放票据；Planby 只消费展示元数据。

后端返回日期覆盖范围、频道顺序和窗口内排期；按日 / 频道批次请求。视图虚拟化减少 DOM 数量，不会自动解决接口与内存全量加载。对外组件接口保持项目模型，后续更换网格实现时不影响页面权限和播放逻辑。

### 6.5 正式选型前的最小验证清单

后续另行进入实施时执行，本轮未执行：

1. 锁定包名、版本和完整许可；确定基础版能否覆盖只读 EPG，是否需要 PRO。
2. 在隔离验证环境测试 React 19 + Vite + HeroUI / Tailwind，包括 StrictMode、卸载和 resize。
3. 用 100 / 300 频道、单日约 5,000 / 15,000 节目两档数据，测加载、横纵滚动、筛选和抽屉交互；记录测试机器与浏览器。将交互响应目标暂设为 200ms 内，内存无持续增长，最终阈值需基于目标 PC 确认。
4. 验证跨午夜、夏令时、无排期、重叠、超短节目、超长标题、频道 Logo 失败。
5. 验证日期切换竞态、回到现在、频道定位、返回位置恢复及键盘 / 读屏操作。
6. 若许可或关键交互不满足，保留本设计，比较其他网格实现；不为依赖附带的编辑功能扩大业务范围。

## 7. 数据与验收要点

本方案不定义最终 API 路径，但后续契约至少需要：公共频道与节目聚合、按时间窗的批量排期和覆盖日期、Profile 收藏频道列表与变更、Profile 最近点播历史。无 EPG 不等于无频道；没有观看权限不等于游客不能浏览元数据。

验收重点：

- 游客三页均能浏览；播放触发登录与选档，取消保留上下文。
- 收藏、历史切档立即隔离，失败和迟到请求不串档。
- 直播三层顺序固定；未来节目和已结束节目不会被误当成回看或预约。
- EPG 跨日和无数据状态准确，刷新与返回不丢位置。
- Play 操作始终经过服务端授权；前端显示状态不能绕过权限。
- 1280×720、1440×900、1920×1080 建议作为首轮 PC 验证尺寸；浏览器矩阵仍待确定。

## 8. 建议评审决策

优先评审以下默认方案：

1. 首页采用「收藏频道 → 点播观看历史 → 此刻直播」；游客只显示公共区与轻量登录提示。
2. 直播未来节目窗口先设 2 小时；节目点击打开详情，明确按钮再播放。
3. EPG 采用单日数据、约 3 小时可视窗口、固定频道列及右侧详情抽屉。
4. 历史先做最近观看列表，暂不承诺续播；EPG 暂不增加预约、录制和回看。
5. Planby 作为优先候选，许可核实和小范围运行验证通过后再确定依赖。

主 Profile、PIN 与已有会话恢复等原文未决项继续保留，不因本页面方案被默认解决。
