# Apple 风格点播、直播与设置体验收敛方案

日期：2026-10-30  
状态：设计收敛版，供产品、设计和实现评审；不代表已实施、已联调或已验收。

本文把当前讨论中的点播、直播、EPG、播放授权、Profile 和设置体验收敛为一套端到端方案。它以 Apple TV 的内容优先、焦点导航、渐进式信息展示和连续返回为参考，但不复制 Apple 的具体页面或品牌视觉。

## 1. 结论先行

直播体验收敛为三个连续模式：

```text
Browse 浏览内容
    ↓
Detail 确认节目与播放意图
    ↓
Player 全屏播放并恢复上下文
```

完整主流程：

```text
进入直播
  ↓
直播首页：Now 优先
  ├── 正在直播
  ├── 接下来 / 分类
  └── 节目单
        ↓
节目详情面板
  ├── 收藏 / 查看节目单
  └── 播放当前频道
        ↓
登录 / Profile / PIN（必要时）
        ↓
服务端播放授权
  ├── 拒绝 → 解释原因 → 返回详情
  └── 通过 → 全屏播放器
                    ↓
             切换频道 / 退出播放
                    ↓
       恢复原页面、焦点与滚动位置
```

核心边界：

- 游客可以浏览公共首页、直播、EPG 和详情。
- 播放必须登录、选择 Profile，并由服务端按当前 Profile 授权。
- Profile 决定收藏、观看历史和播放权限的归属。
- 设置是受保护的系统层，不与直播内容混在一起。
- 所有播放入口使用同一条登录、Profile、授权和播放链路。
- 不在本范围内增加未来节目播放、预约、录制或回看能力。

## 2. Apple 原则在 redRoad 中的落地

参考 Apple 的 [tvOS 设计原则](https://developer.apple.com/design/human-interface-guidelines/designing-for-tvos/)、[焦点与选择](https://developer.apple.com/design/human-interface-guidelines/focus-and-selection/)、[布局](https://developer.apple.com/design/human-interface-guidelines/layout/) 和 [遥控器交互](https://developer.apple.com/design/human-interface-guidelines/remotes/)。本项目采用以下产品规则：

| 原则 | redRoad 的落地规则 |
| --- | --- |
| 现在优先 | 直播首页第一视觉是「正在直播」，不是全量频道网格或运营广告。 |
| 内容优先 | 卡片先表达频道、节目、时间和状态，操作按钮只保留一个主动作。 |
| 焦点明确 | 卡片主体可聚焦；选中后提升层级和信息密度，不自动跳焦点。 |
| 渐进展示 | 首页展示摘要，节目详情面板展示完整信息，播放器负责沉浸观看。 |
| 连续性 | 登录、Profile、播放和设置返回后恢复原页面、URL 状态、滚动和焦点。 |
| 可预测返回 | Escape、返回按钮和关闭遮罩都回到触发入口，不把用户送回首页。 |
| 权限透明 | 先允许浏览，点击播放时再说明登录、Profile 和授权要求。 |
| 安静刷新 | 30 秒刷新节目状态，但不关闭抽屉、不重置分页、不打断焦点。 |
| 少量高价值设置 | 设置只保存长期偏好；当前播放控制放在播放器内。 |

视觉实现继续遵循项目的 HeroUI 语义 Token、单一强调色、清晰焦点和少量表面层，不额外建立一套 Apple 颜色或组件系统，详见 [DESIGN.md](../DESIGN.md)。

## 3. 全局入口和状态边界

### 3.1 主导航

```text
顶部导航
├── 首页
├── 点播
├── 直播
└── 右侧：登录 / 当前账号 / 当前 Profile
              └── 设置
```

「设置」从主 Profile 菜单进入，不放在直播内容的一级浏览区。播放器内可以提供播放相关的快捷设置，但不直接跳转到完整设置页。

### 3.2 四种业务状态

| 状态 | 可以做什么 | 不能做什么 |
| --- | --- | --- |
| 游客浏览 | 查看公共内容、直播、节目单、详情 | 播放、查看 Profile 私有数据 |
| 已登录未选 Profile | 浏览公共内容、进入 Profile 选择 | 以未确定的 Profile 发起播放或读取个人数据 |
| 已登录已选 Profile | 播放、收藏、查看观看历史 | 访问未授权内容 |
| 设置已解锁 | 管理设置和家庭管理模块 | 绕过服务端权限或主账号敏感操作校验 |

Profile 切换时，旧 Profile 的收藏、历史、播放授权和在途请求都必须失效，不能只替换头像。

## 3.5 点播 `/vod`

点播沿用同一套「浏览 → 详情 → 播放 → 返回恢复」模型，但内容主线从「频道与时间」改为「影片、剧集、季和分集」。Apple TV+ 的详情页可以作为信息层级参考：首屏突出作品身份和主操作，下方再展开季、分集、预告、相关内容和信息，而不是让用户一开始面对复杂的线路和权限选项。

### 3.5.1 点播整体流程

```text
进入点播
  ↓
点播首页 / 搜索
  ├── 媒体库
  ├── 在线搜索
  └── 搜索结果
        ↓
作品详情
  ├── 电影：播放 / 继续观看
  └── 剧集：选季 → 选分集 → 选择线路（必要时）
        ↓
是否已登录且已选 Profile？
  ├── 否 → 登录 → 选择 Profile → PIN（必要时）
  └── 是
        ↓
检查内容、来源、策略和当前 Profile 权限
        ↓
在线候选是否需要登记为稳定媒体？
  ├── 是 → 完整登记成功 → 稳定详情 / 播放
  └── 否 → 直接准备播放
        ↓
本次媒体检查
  ├── 有效历史 → 继续观看 / 从头播放
  └── 无有效历史 → 从头播放
        ↓
全局播放器
  ├── 自动下一集
  ├── 播放器内换源
  └── 退出并恢复原详情、分集和焦点
```

### 3.5.2 页面分层

```text
/vod
├── 媒体库 / 在线搜索切换
├── 搜索与分页
├── 电影、剧集和分类结果
└── 游客可浏览，不读取个人历史

/vod/titles/:titleRef
├── 在线搜索得到的临时作品详情
├── 线路、季和分集选择
├── 作品简介和可用性状态
└── 播放时才进入登录、Profile 和授权流程

/media/:id
├── 已登记的稳定作品详情
├── Hero：海报、标题、类型、年份、简介
├── 主按钮：继续观看 / 播放 / 从头播放
├── 季选择与分集列表
├── 预告、相关内容和演职员（有数据才展示）
└── 当前 Profile 的历史、续播和下一集状态
```

临时在线详情和稳定媒体详情必须区分：游客查看搜索结果不创建永久媒体、不写观看历史、不泄露来源地址；只有带有有效播放意图且通过权限检查时，才登记完整作品。

### 3.5.3 Apple 风格的详情页结构

详情页只保留一个主播放动作，其他信息按优先级向下展开：

```text
Hero
├── 海报 / 背景图
├── 标题、类型、年份、年龄分级、时长
├── 简介
└── 主操作：继续观看 / 播放 / 从头播放

内容区
├── 季选择
├── 分集列表
├── 预告与花絮
├── 相关内容
├── 演职员
└── 信息、语言、辅助功能
```

行为规则：

- 电影显示「播放」或「继续观看」，始终提供「从头播放」。
- 剧集先选季，再选择分集；分集卡片显示标题、简介、时长和 Profile 续播状态。
- 有有效历史时显示「继续观看」，但必须在本次媒体检查后才能确定真正起点。
- 续播不满足条件时从头播放或提示重新选择，并解释原因，不静默伪造续播。
- 已完成和接近结尾要区分；接近结尾不自动标记为已完成。
- 已下架作品可查看自己的历史摘要，但不能显示可用播放按钮。
- 不在详情页展示来源 URL、凭据、内部候选引用或其他 Profile 的历史。

### 3.5.4 剧集与自动下一集

剧集播放完成后，播放器显示 5 秒可取消的下一集倒计时。下一集仍需重新检查当前 Profile、作品策略、来源和分集状态：

- 关闭自动连播后不启动下一集。
- 下一集存在未完成历史时，先让用户选择「继续」或「从头」。
- 季边界、缺集、重复集号、权限变化和目标版本变化时停止自动前进。
- 浏览器阻止自动播放时显示「点击播放」，不写入虚假的观看历史。
- 自动连播失败不能递归跳到更后一集，也不能跨来源绕过权限。

### 3.5.5 播放器内换源

换源是播放器内的辅助操作，不把用户踢回搜索页。候选面板最多同时检测 3 条线路，并显示来源名称、匹配集和可达性状态，不显示源地址。

用户必须明确选择以下一种定位方式：

1. 使用当前播放位置。
2. 使用目标线路自己的历史位置。
3. 从头播放。

不同来源、不同版本或身份不明确时，不能按列表下标静默携带进度，也不能自动合并不同来源的历史。旧播放在新线路准备失败前仍可恢复；旧播放已终止后只能重试或重新播放，不能复活旧票据。

### 3.5.6 点播与直播的共同边界

| 维度 | 直播 | 点播 |
| --- | --- | --- |
| 首屏重点 | 正在直播、接下来、节目单 | 作品、分类、搜索和继续观看 |
| 详情主操作 | 播放当前频道 | 继续观看 / 播放 / 从头播放 |
| 时间语义 | 当前时间和节目排期 | 影片时长、分集进度和完成状态 |
| 游客能力 | 浏览频道、节目单和详情 | 搜索、浏览详情和分集 |
| 播放权限 | 登录 + Profile + 服务端授权 | 登录 + Profile + 服务端授权 |
| 返回行为 | 恢复频道、日期、筛选和焦点 | 恢复作品、季、分集、搜索和焦点 |
| 播放后续 | 切换频道 | 自动下一集、续播、播放器内换源 |

点播的正式需求、接口、播放状态和验收以 [010 在线点播规格](./specs/010-online-vod/spec.md) 及其 contracts 为准；本节负责把它接入整体产品体验，不替代该规格。

## 4. 直播首页 `/live`

### 4.1 内容顺序

```text
直播
├── 节目单入口
├── 正在直播
├── 接下来
└── 按类型浏览
```

直播首页的 Hero 应表达「正在播放」：频道 Logo、当前节目、直播状态、进度、起止时间和「播放当前频道」。它不是点播详情页式的宣传横幅。

### 4.2 卡片行为

- 点击卡片主体：打开节目详情面板。
- 点击主按钮：进入统一播放链路。
- 点击收藏：只收藏频道，不触发播放。
- 即将播放的节目：展示开播时间，主操作为查看详情或节目单。
- 未来节目不能显示「播放」或暗示可以直接播放未来内容。
- 无节目数据时保留频道身份，显示「暂无节目单」；频道可用时仍可播放当前频道。

### 4.3 节目详情面板

详情面板使用右侧抽屉或 Sheet，保持底层直播页面可见。内容包括：

- 频道名称和 Logo
- 节目标题、简介、开始时间、结束时间和时长
- 当前状态：正在直播、即将开始、已结束或暂无节目数据
- 主操作：当前直播使用「播放当前频道」
- 次操作：收藏频道、查看节目单

当前节目、即将开始节目和从 EPG 进入的节目，都打开同一类详情面板。来源只影响返回时恢复的页面状态。

## 5. EPG 节目单 `/live/guide`

EPG 是直播的第二入口，不取代直播首页。

### 5.1 页面结构

```text
节目单
├── 日期切换
├── 回到现在
├── 时区说明
├── 频道 / 分类筛选
├── 节目墙或按频道列表
└── 节目详情面板
```

### 5.2 交互规则

- 首次进入定位到当前时间附近，同时显示当前节目和后续排期。
- 用户手动浏览过去或未来时，不自动拉回现在。
- 「回到现在」只恢复今天和当前时间，不清除频道筛选。
- 点击节目块打开详情面板，不默认直接播放。
- 从频道观看按钮播放该频道当前直播，而不是播放未来节目。
- 日期、时间窗口、频道分页、视图模式和滚动位置进入 URL 或可恢复状态。
- 数据刷新不能重置用户的日期、筛选、滚动和焦点。

## 6. 统一播放流程

```text
选择频道或节目
  ↓
打开节目详情
  ↓
点击「播放当前频道」
  ↓
是否已登录且已选 Profile？
  ├── 否 → 登录 → 选择 Profile → PIN（必要时）
  └── 是
        ↓
服务端播放授权
  ├── 通过 → 建立播放会话 → 全屏播放器
  └── 拒绝 → 说明原因 → 保留节目详情
```

授权前不请求媒体流。登录或选档完成后重新解析播放目标：直播始终播放该频道此刻的内容，不尝试重播用户等待登录期间已经结束的节目。

播放器至少提供：

- 当前频道和节目名称
- 直播状态和进度
- 切换频道
- 字幕、音轨和清晰度等当前播放控制
- 退出播放
- 播放失败时的重试和原因说明

退出后恢复来源页面的 URL、筛选、滚动、详情状态和焦点。切换 Profile 时必须结束旧播放授权，再按新 Profile 重新授权。

## 7. 设置页面

### 7.1 设置入口流程

```text
主 Profile 菜单
  ↓
设置
  ↓
登录状态检查
  ↓
主 Profile 检查
  ↓
设置 PIN 验证
  ↓
设置布局：左侧分类 + 右侧详情
```

设置解锁建议绑定当前会话和主 Profile，在退出登录、切换 Profile 或解锁过期时失效。PIN 只负责进入设置，不能替代服务端播放授权或其他敏感管理操作的密码校验。

### 7.2 设置布局

```text
设置
├── 个人偏好
│   ├── 账户与 Profile
│   ├── 播放
│   ├── 直播与节目单
│   ├── 字幕与语言
│   └── 辅助功能
├── 家庭管理
│   ├── Profile 与权限
│   ├── 内容来源
│   ├── 节目单与频道匹配
│   ├── 播放策略
│   └── 设备与会话
└── 系统
    └── 关于与帮助
```

个人偏好和家庭管理需要分组显示。这样既保留 Apple TV 式的低复杂度，又能容纳 redRoad 当前已有的来源、EPG、策略、Profile 和设备管理能力。

### 7.3 设置内容边界

| 分类 | 内容 | 交互方式 |
| --- | --- | --- |
| 账户与 Profile | 当前 Profile、切换、Profile 管理、PIN、退出登录 | 选择器、表单、确认对话框 |
| 播放 | 默认清晰度、默认音轨、自动播放、重试策略 | 开关或单选，修改后即时生效 |
| 直播与节目单 | 默认入口、默认视图、时区显示、频道排序 | 单选或设置面板 |
| 字幕与语言 | 默认字幕、默认音频语言、强制字幕、音频描述 | 单选或选择器 |
| 辅助功能 | 字体、对比度、减少动态、字幕样式、焦点提示 | 即时预览或即时生效 |
| Profile 与权限 | Profile 分级、内容名单、频道权限 | 需要额外管理权限 |
| 内容来源 | 来源配置、导入状态、同步状态 | 独立管理页面 |
| 节目单与频道匹配 | EPG 来源、同步状态、频道绑定 | 独立管理页面 |
| 播放策略 | 家庭播放规则和权限策略 | 需要服务端授权 |
| 设备与会话 | 已登录设备、播放会话、会话撤销 | 危险操作需要确认 |
| 关于与帮助 | 版本、条款、隐私、反馈、播放帮助 | 普通链接和信息页 |

### 7.4 设置交互规则

- 开关和单选项即时生效，不使用一个覆盖全页的「保存」按钮。
- 复杂表单可以局部保存，但保存按钮只出现在当前编辑区域。
- 退出登录、删除 Profile、撤销会话、重置设置必须二次确认。
- 从播放器打开播放设置时使用浮层；关闭后继续播放。
- 从 Profile 菜单进入完整设置时使用设置布局；返回 Profile 后恢复原焦点。
- URL 建议保留当前分类，例如 `/settings?section=playback`，刷新后仍打开原模块。
- 设置加载失败只影响当前模块；页面保留左侧导航和重试入口。
- 不把当前播放器控制重复搬到设置页；设置页保存默认值，播放器处理当前值。

## 8. 焦点、键盘和响应式要求

### 8.1 焦点顺序

```text
直播入口
  → Now Hero
  → 正在直播
  → 接下来
  → 分类频道
  → 节目单
  → 节目详情
  → 播放当前频道
  → 全屏播放器
  → 返回原焦点
```

设置页使用同样的原则：左侧分类是一级焦点，右侧选项是二级焦点；进入详情后，返回恢复到触发的分类或设置项。

### 8.2 PC 与电视端

当前实现优先覆盖 PC 浏览器，但交互模型按电视端远距离观看设计：

- 交互元素必须有明显的 `focus-visible` 状态。
- 不能只用颜色表达选中、直播中、错误和禁用。
- 卡片和列表项需要支持键盘方向移动与 Enter / Space 操作。
- 详情面板使用 Escape 关闭并恢复触发焦点。
- 窄屏端把左侧设置菜单折叠成列表；大屏保留左侧菜单和右侧详情。
- 动效只用于表达焦点、打开、关闭和状态变化，并遵守减少动态偏好。

## 9. 对当前 redRoad 的映射

| 设计层 | 当前承载位置 | 调整方向 |
| --- | --- | --- |
| 直播首页 | `LivePage`、`NowHero`、`NowSection`、`NextSection`、`GroupSections` | 保持 Now / Next / Groups 结构，强化「正在直播」语义 |
| 节目详情 | `ProgrammeSlotDialog`、`ProgrammeDetailPanel` | 统一为同一种节目详情面板，保留来源状态 |
| EPG | `GuidePage` | 保留日期、时间范围、频道分页、视图和返回位置 |
| 播放授权 | `usePlayAction`、`ActionCoordinator` | 作为所有入口的唯一播放边界 |
| 设置布局 | `apps/web/src/features/settings` | 将现有管理模块纳入左侧分类，并补充个人偏好分组 |
| 路由状态 | 当前页面查询参数 | 继续保存 section、筛选、分页、日期和播放来源 |

目前最需要补齐的是：游客点击播放后的意图保存、登录 / Profile 完成后的原目标恢复，以及设置 PIN 解锁状态与现有管理权限的明确边界。

## 10. 验收标准

### 直播和播放

- 游客可以打开首页、直播、EPG 和详情，不被登录页阻断。
- 游客点击播放后才进入登录和 Profile 流程。
- 授权前不发起媒体流请求。
- 正在直播、即将播放和 EPG 入口都进入统一的节目详情与播放链路。
- 播放失败有原因、重试和返回详情路径。
- 退出播放后恢复原页面、焦点、滚动和筛选。
- 自动刷新不造成跳焦点、跳日期或关闭详情。

### 设置

- 设置入口需要登录、主 Profile 和设置 PIN。
- 设置访问状态在退出登录、切换 Profile 或过期后失效。
- 个人偏好和家庭管理分组明确。
- 普通偏好修改后即时生效；危险操作有确认。
- 从播放器进入播放设置后可以无损返回播放器。
- 设置页面支持键盘焦点、Escape 返回和可读的错误状态。

## 11. 尚待确认的决策

以下内容仍是产品决策，不在本文中擅自定案：

1. 主 Profile 的定义，以及普通 Profile 是否可以查看设置入口。
2. 设置 PIN 的首次建立、有效期、错误次数和锁定规则。
3. 设置 PIN 与主账号密码校验是否叠加，以及不同管理操作的授权等级。
4. 已有有效会话重新打开应用时是否恢复当前 Profile。
5. 时区由部署家庭固定、浏览器本地决定，还是允许用户选择。
6. 播放质量、自动播放和音轨等偏好由服务端还是浏览器本地保存。
7. 收藏频道、观看历史、设备会话和设置偏好的接口与数据模型。

在这些决策确认前，本文作为交互和边界基线，不直接替代 API、数据模型、权限 ADR 或验收规格。
